지금부터 Lee Trader 프로젝트의 9차 개선 과제인

"섹터 집중 hard cap 명시화"를 진행합니다.



이 과제는 1차 Ranking Trust Gate와 독립적으로 진행 가능한

포트폴리오 리스크 관리 및 운영 관측성 개선 과제입니다.



핵심 목표:

한국 시장 특성상 반도체·이차전지·AI 등 특정 테마로 포트폴리오 쏠림이 빠르게 발생할 수 있다.

현재 Rule 자동매매에는 RULE\_MAX\_SECTOR\_WEIGHT 환경변수가 있고,

AI 자동매매에는 --sector-cap 인수 또는 production\_config YAML 기반 sector cap이 존재한다.



하지만 다음 문제가 있다.



1\. Rule/AI 섹터 상한 설정 경로가 서로 달라 운영 불일치 가능성이 있다.

2\. 매일 실제 섹터별 노출 현황을 기록하는 파일이 없다.

3\. 섹터 비중이 상한에 근접했을 때 경고 알림이 없다.

4\. 운영자가 "현재 어느 섹터가 몇 %인지" 바로 확인하기 어렵다.



이번 과제의 목표:

\- Rule 섹터 cap 기존 로직은 유지한다.

\- AI 자동매매에 AI\_MAX\_SECTOR\_WEIGHT 환경변수 경로를 추가한다.

\- 매일 섹터별 현재 노출 현황을 outputs/sector\_exposure\_summary.json으로 저장한다.

\- 섹터 비중이 경고 기준 이상이면 WARNING 알림을 보낸다.

\- 섹터 비중이 cap을 초과하면 CRITICAL 알림을 보낸다.



중요:

\- 기존 sector\_limit\_pass / sector\_limit\_failed guard 로직은 변경하지 않는다.

\- portfolio\_constructor.py 내부 로직은 변경하지 않는다.

\- rule\_account\_guard.py는 수정하지 않는다.

\- rule\_signal\_builder.py는 수정하지 않는다.

\- 기존 final\_score, ranking 산식은 변경하지 않는다.

\- 실계좌 주문/KIS API 호출은 테스트 목적으로 실행하지 않는다.

\- sector\_exposure\_summary.json 저장 실패가 포트폴리오 계획 또는 주문 preview 생성을 막으면 안 된다.

\## Step 4. 환경변수 추가 및 정리



.env.example에 아래 환경변수와 설명을 추가한다.



\# Rule 자동매매 단일 섹터 최대 비중

RULE\_MAX\_SECTOR\_WEIGHT=0.35



\# AI 자동매매 단일 섹터 최대 비중

AI\_MAX\_SECTOR\_WEIGHT=0.35



\# AI 자동매매 동시 보유 최대 섹터 수

AI\_MAX\_SECTOR\_COUNT=5



\# 섹터 cap 대비 경고 발동 비율

SECTOR\_WARN\_THRESHOLD\_RATIO=0.80



\# 섹터 노출 경고 알림 활성화

SECTOR\_EXPOSURE\_NOTIFY\_ENABLED=true



파싱 기준:

\- RULE\_MAX\_SECTOR\_WEIGHT는 기존 로직을 유지한다.

\- AI\_MAX\_SECTOR\_WEIGHT는 submit\_live\_orders.py에서 --sector-cap 기본값 계산 시 최우선 환경변수로 사용한다.

\- AI\_MAX\_SECTOR\_WEIGHT가 없으면 기존 production\_config sector\_cap 값을 사용한다.

\- production\_config 값도 없으면 0.35를 사용한다.

\- AI\_MAX\_SECTOR\_COUNT는 우선 문서/로그/summary 용도로 반영한다.

\- SECTOR\_WARN\_THRESHOLD\_RATIO는 0\~1 사이 float로 처리한다.

\- 잘못된 값이면 기본값을 사용하고 warning 로그를 남긴다.

\- SECTOR\_EXPOSURE\_NOTIFY\_ENABLED=false이면 알림을 보내지 않는다.



AI sector cap 우선순위:



1\. CLI에서 --sector-cap 명시

2\. AI\_MAX\_SECTOR\_WEIGHT 환경변수

3\. production\_config execution\_policy.sector\_cap

4\. production\_config portfolio.sector\_cap

5\. 기본값 0.35



주의:

\- argparse에서 CLI 인수를 명시한 경우와 기본값을 구분하기 어려운 구조라면,

&#x20; 기존 구조를 크게 바꾸지 말고 default 값을 AI\_MAX\_SECTOR\_WEIGHT 우선순위로 계산해 넣는다.

\- 사용자가 CLI로 --sector-cap을 넘기면 argparse가 그 값을 사용하게 한다.

\## Step 5. sector\_exposure\_summary.json 생성



Rule 포트폴리오 계획 완료 후 아래 파일을 best-effort로 저장한다.



출력 경로:



outputs/sector\_exposure\_summary.json



기본 구조:



{

&#x20; "generated\_at": "2026-05-07T09:05:00",

&#x20; "as\_of\_date": "2026-05-07",

&#x20; "run\_mode": "live",

&#x20; "engine": "rule",

&#x20; "sector\_cap": 0.35,

&#x20; "warn\_threshold": 0.28,

&#x20; "warn\_threshold\_ratio": 0.80,

&#x20; "total\_positions": 8,

&#x20; "sectors": \[

&#x20;   {

&#x20;     "sector": "반도체",

&#x20;     "position\_count": 3,

&#x20;     "total\_weight": 0.32,

&#x20;     "weight\_pct": 32.0,

&#x20;     "cap\_usage\_pct": 91.4,

&#x20;     "warn\_triggered": true,

&#x20;     "cap\_exceeded": false,

&#x20;     "codes": \["005930", "000660", "058470"]

&#x20;   }

&#x20; ],

&#x20; "warn\_triggered\_sectors": \["반도체"],

&#x20; "cap\_exceeded\_sectors": \[]

}



필드 설명:



\- generated\_at: 생성 시각 ISO

\- as\_of\_date: 기준일

\- run\_mode: paper / pilot / live 등

\- engine: rule

\- sector\_cap: 적용된 섹터 상한

\- warn\_threshold: sector\_cap \* SECTOR\_WARN\_THRESHOLD\_RATIO

\- warn\_threshold\_ratio: 환경변수 값

\- total\_positions: summary 계산 대상 포지션 수

\- sectors: 섹터별 노출 리스트

\- sector: 섹터명

\- position\_count: 해당 섹터 포지션 수

\- total\_weight: 해당 섹터 총 비중

\- weight\_pct: total\_weight \* 100

\- cap\_usage\_pct: total\_weight / sector\_cap \* 100

\- warn\_triggered: total\_weight >= warn\_threshold

\- cap\_exceeded: total\_weight > sector\_cap

\- codes: 해당 섹터 종목코드 목록

\- warn\_triggered\_sectors: 경고 발생 섹터 목록

\- cap\_exceeded\_sectors: cap 초과 섹터 목록



주의:

\- outputs 디렉터리가 없으면 생성한다.

\- sector가 없거나 NaN이면 "(none)"으로 그룹화한다.

\- weight가 없으면 가능한 기존 포트폴리오 weight 컬럼을 확인한다.

\- weight 컬럼이 전혀 없으면 position\_count 기반 summary만 만들고 total\_weight는 null 처리한다.

\- summary 저장 실패가 rule\_portfolio\_manager.py 실행 실패로 전파되면 안 된다.

\- 저장 실패 시 warning 로그만 남긴다.

\## Step 7. submit\_live\_orders.py 수정 — AI\_MAX\_SECTOR\_WEIGHT 연결



submit\_live\_orders.py의 --sector-cap 기본값 계산을 아래 우선순위로 변경한다.



우선순위:



1\. CLI에서 --sector-cap을 직접 지정한 값

2\. AI\_MAX\_SECTOR\_WEIGHT 환경변수

3\. production\_config execution\_policy.sector\_cap

4\. production\_config portfolio.sector\_cap

5\. 0.35



구현 방법:

\- argparse default 값을 계산하는 helper를 만든다.

\- 기존 get\_production\_config\_value 호출 구조를 최대한 유지한다.

\- AI\_MAX\_SECTOR\_WEIGHT가 유효한 float이면 그것을 default로 사용한다.

\- AI\_MAX\_SECTOR\_WEIGHT가 없거나 잘못된 값이면 기존 production\_config fallback을 사용한다.

\- 잘못된 값이 있을 때 warning 로그를 남긴다.

\- --sector-cap 인수의 설명에 AI\_MAX\_SECTOR\_WEIGHT 환경변수 우선순위를 명시한다.



AI\_MAX\_SECTOR\_COUNT:

\- 이번 과제에서 portfolio\_constructor.py를 수정하지 않으므로 hard 적용하지 않는다.

\- 가능하면 submit\_live\_orders.py 로그 또는 완료 보고에 "AI\_MAX\_SECTOR\_COUNT는 현재 문서화/후속 과제용"이라고 남긴다.

\- 무리해서 AI\_MAX\_SECTOR\_COUNT를 실제 로직에 연결하지 않는다.
