지금부터 Lee Trader 프로젝트의 5차 개선 과제인

"scheduler health ledger 구축"을 진행합니다.



이 과제는 1차 Ranking Trust Gate와 독립적으로 진행 가능한 운영 관측성 개선 과제입니다.



핵심 목표:

현재 run\_daily\_scheduler.py는 전체 cycle의 성공/실패만 auto\_ops\_scheduler\_status.json에 기록하고,

각 step별 실행 결과, 소요 시간, 산출물 row 수, 실패 사유를 구조화해서 남기지 않는다.



이번 과제에서는 기존 auto\_ops\_scheduler\_status.json을 대체하지 않고,

추가 산출물로 다음 파일을 생성한다.



\- outputs/scheduler\_health.json

\- outputs/scheduler\_health\_report.md



중요:

\- 기존 auto\_ops\_scheduler\_status.json 출력은 그대로 유지한다.

\- 기존 scheduler 실행 순서와 실패 시 동작을 변경하지 않는다.

\- 각 step 내부 스크립트는 수정하지 않는다.

\- run\_daily\_scheduler.py와 신설 scheduler\_health.py 중심으로만 구현한다.

\- health 기록 실패가 실제 scheduler 실행 실패로 이어지지 않게 한다.

\## Step 4. 구현 요구사항 A — scheduler\_health.py 신설



python/scheduler\_health.py를 신설한다.



필수 구조:



JobResult 데이터 구조를 만든다.

dataclass 사용을 권장한다.



필드:



\- job\_name: str

\- command\_set: str

\- started\_at: str

\- finished\_at: str | None

\- duration\_seconds: float | None

\- status: str

&#x20; - success

&#x20; - failed

&#x20; - skipped

\- exit\_code: int | None

\- error\_message: str | None

\- output\_rows: int | None

\- output\_file: str | None

\- notes: str | None



필수 함수:



1\. get\_health\_config()



환경변수에서 설정값을 읽는다.



2\. record\_job(result: JobResult, path: str | None = None) -> None



\- scheduler\_health.json에 job 결과를 추가 또는 갱신한다.

\- 동일 command\_set, 동일 job\_name, 동일 started\_at 기준으로 중복 기록을 피한다.

\- 파일이 없으면 새로 생성한다.

\- outputs 디렉터리가 없으면 생성한다.

\- 기록 실패 시 예외를 외부로 전파하지 말고 warning 로그만 남긴다.



3\. write\_health\_summary(date: str, command\_set: str, path: str | None = None, report\_path: str | None = None) -> None



\- scheduler\_health.json을 읽어 summary를 갱신한다.

\- scheduler\_health\_report.md를 생성한다.

\- 실패해도 scheduler를 중단하지 않는다.



4\. infer\_output\_metadata(job\_name: str) -> dict



job\_name별 주요 산출물 파일과 row 수를 best-effort로 추정한다.



출력 예:



{

&#x20; "output\_file": "data/ranking\_final.csv",

&#x20; "output\_rows": 150,

&#x20; "notes": "ranking rows=150"

}



row 수 파악 실패 시:



{

&#x20; "output\_file": "data/ranking\_final.csv",

&#x20; "output\_rows": null,

&#x20; "notes": "row\_count\_unavailable"

}



5\. notify\_scheduler\_failure\_if\_enabled(result: JobResult) -> None



\- SCHEDULER\_HEALTH\_NOTIFY\_ON\_FAILURE=true이고 result.status == "failed"이면 notifier warning을 시도한다.

\- notifier.py는 수정하지 않는다.

\- 알림 실패 시 warning 로그만 남긴다.

\- 기존 health 파일이 있으면 append/update 방식으로 처리하되 JSON이 깨지지 않게 한다.

\## Step 8. 구현 요구사항 E — run\_daily\_scheduler.py 수정



현재 \_run\_step(name, command)을 health 기록이 가능한 wrapper로 확장한다.



요구사항:



1\. step 시작 시 started\_at 기록

2\. subprocess.run 실행

3\. 성공 시:

&#x20;  - finished\_at

&#x20;  - duration\_seconds

&#x20;  - status=success

&#x20;  - exit\_code=0

&#x20;  - output metadata 추정

&#x20;  - record\_job 호출

4\. 실패 시:

&#x20;  - finished\_at

&#x20;  - duration\_seconds

&#x20;  - status=failed

&#x20;  - exit\_code=exc.returncode

&#x20;  - error\_message 저장

&#x20;  - output metadata best-effort 추정

&#x20;  - record\_job 호출

&#x20;  - notify\_scheduler\_failure\_if\_enabled 호출

&#x20;  - 기존처럼 예외를 다시 raise하여 기존 실패 흐름 유지

5\. step 실패 후 이후 step이 기존 구조상 실행되지 않는다면:

&#x20;  - 남은 step을 skipped로 기록할 수 있으면 기록한다

&#x20;  - 단, skipped 기록 때문에 기존 예외 흐름을 바꾸면 안 된다

6\. 모든 step 처리 후 또는 실패 처리 후:

&#x20;  - write\_health\_summary 호출

&#x20;  - 단, summary 생성 실패가 scheduler 실패로 전파되면 안 된다



subprocess 출력 관련 주의:

\- capture\_output=True를 추가하면 기존 콘솔 로그가 사라질 수 있다.

\- 기존 동작을 최대한 유지하라.

\- capture\_output을 사용해야 error\_message를 얻을 수 있다면 stdout/stderr를 logging에 다시 전달하라.

\- 더 안전한 경우 기존 subprocess.run 호출 방식은 유지하고 CalledProcessError 정보에서 가능한 범위만 기록하라.

\## Step 9. 환경변수 추가

1\. 기존 auto\_ops\_scheduler\_status.json 출력은 그대로 유지할 것

2\. scheduler\_health.json은 추가 파일이며 기존 파일을 대체하지 말 것

3\. 기존 scheduler 실행 순서와 실패 전파 방식을 변경하지 말 것

4\. 각 step 내부 스크립트는 수정하지 말 것

5\. 수정 금지 파일은 읽기만 할 것

6\. health 기록 실패가 scheduler 실패로 전파되지 않게 할 것

7\. row 수 파악 실패가 health 기록 실패로 이어지지 않게 할 것

8\. subprocess capture\_output 변경으로 기존 로그가 사라지지 않게 할 것

9\. 실제 KIS API나 실계좌 주문을 검증 목적으로 호출하지 말 것

10\. 기존 운영 파일을 삭제하지 말 것

11\. 변경 전후 영향 범위를 반드시 보고할 것
