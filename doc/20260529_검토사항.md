# 2026-05-29 시스템 검토사항

## 검토 목적

AI 자동매매 시스템을 실거래에 계속 적용하기 전에 다음 항목을 기준으로 현재 구조의 안정성, 위험 요소, 개선 우선순위를 정리한다.

1. 데이터 수집과정에서의 누락 및 버그 위험성
2. 모델 학습 로직 점검
3. 모델 예측 로직 점검
4. 랭킹 점수 산출 로직 점검
5. 자동매수 후보 선정 로직 점검
6. 종목 보유에 대한 로직 점검

## 종합 결론

현재 시스템은 소액 파일럿 운영은 가능한 상태로 보인다.

다만 아직 완전 자동매수 시스템으로 신뢰하기에는 몇 가지 중요한 보완점이 남아 있다. 특히 자동매수 실행 후 보유상태 동기화, 모델 confidence 보정 방식, 랭킹 KPI 검증 상태는 우선적으로 확인해야 한다.

현재 운영 게이트가 `PILOT`으로 판단되는 것은 시스템이 비정상적으로 막고 있는 것이 아니라, 아직 충분히 검증되지 않은 상태를 보수적으로 반영한 결과로 보는 것이 맞다.

## 핵심 리스크 요약

### 1. 자동매수 실행 후 보유상태 갱신 공백

`scheduler-auto-buy` 경로는 현재 대체로 다음 순서로 동작한다.

1. `run_operational_refresh`
2. `submit_live_orders`

반면 전체 라이브 자동매매 사이클은 주문 제출 이후 다음 작업까지 수행한다.

1. 실계좌 보유 동기화
2. AI 포지션 상태 갱신
3. 체결 내역 동기화
4. 실행 리포트 생성

따라서 자동매수 스케줄러 경로에서는 주문이 실제 제출된 뒤 `ai_position_state`가 즉시 갱신되지 않을 수 있다.

이 경우 다음날 최소보유일, 진입일, 최고가 기준 트레일링, 손절/익절 판단이 실제 보유 상태와 다르게 계산될 위험이 있다.

이 항목은 운영 안정성 측면에서 가장 먼저 보완해야 한다.

### 2. 모델 confidence 보정 로직의 과최적화 위험

모델 학습 로직은 시계열 분할과 타깃 제외 구조를 갖추고 있어 기본 방향은 맞다.

다만 분류 모델의 confidence calibration 과정에서 최종 모델을 전체 데이터로 학습한 뒤, 마지막 검증 구간으로 보정하는 구조가 있다. 이 경우 검증 구간이 이미 최종 모델 학습에 포함되어 있기 때문에 confidence가 실제보다 낙관적으로 보정될 수 있다.

자동매매에서는 confidence가 매수 후보 선정, 보유 판단, 매도 판단에 직접 영향을 주므로 이 문제는 중장기적으로 반드시 개선해야 한다.

### 3. 랭킹 KPI가 아직 ALERT 상태

`score_kpi_monitor` 기준 전체 상태가 `ALERT`이다.

특히 다음 항목이 안정권이 아니다.

- 최종 점수와 Top20 성과 overlap
- 최종 점수와 기술점수의 관계
- confidence calibration
- walk-forward 기반 검증 지표

따라서 현재는 `BUY_ALLOWED`가 아니라 `PILOT` 상태로 운영하는 것이 맞다.

### 4. 오래된 후보 파일 경고

`trade_intents` 산출물에서 `ai_filtered_top_candidates.csv`가 오래된 날짜로 남아 있다는 경고가 확인된다.

현재 실운영 후보 선정에는 사용되지 않은 것으로 보이지만, 운영자가 리포트를 볼 때 혼동할 수 있다. 사용하지 않는 산출물이면 제거하거나, 계속 사용할 계획이면 최신 날짜로 재생성하는 방식이 필요하다.

### 5. 한국 실거래 경로 테스트 부족

미국 모델/일부 공통 로직 테스트는 있으나, 한국 실거래 자동매매의 핵심 경로에 대한 테스트는 부족하다.

특히 다음 영역은 회귀 테스트가 필요하다.

- 주문 수량 계산
- 예산 초과 방지
- 초당 거래건수 제한 대응
- 최소보유일 보호
- confidence 누락 시 보유/매도 판단
- trim 수량 0인 경우 차단 처리

### 판단

데이터 수집 파이프라인 자체는 현재 큰 누락 없이 동작하고 있다.

다만 fundamental/quality 데이터는 최신 재무제표 기준 특성상 가격 데이터보다 늦게 따라온다. 현재 quality 관련 평균 결측 비율이 완전히 낮지는 않으므로, ranking과 confidence 판단에서 결측 페널티가 계속 정상 적용되는지 확인해야 한다.

### 주의사항

오래된 `ai_filtered_top_candidates.csv` 경고는 정리 대상이다. 현재 실거래 판단에 사용되지 않았더라도 운영 리포트의 신뢰도를 떨어뜨릴 수 있다.

## 2. 모델 학습 로직 점검

### 확인 내용

모델 학습은 대체로 다음 구조를 따른다.

- 시계열 기준 분할
- 30일, 60일, 90일 수익률 회귀 모델
- 60일 Top20 분류 모델
- 오래된 데이터보다 최근 데이터에 더 큰 가중치 부여
- 타깃 컬럼과 realized 계열 컬럼 제외

이 구조는 금융 시계열 모델에서 기본적으로 필요한 방향을 따르고 있다.

### 주요 리스크

가장 큰 리스크는 confidence calibration 방식이다.

최종 분류 모델을 전체 데이터로 학습한 뒤 마지막 검증 구간으로 calibration을 수행하면, calibration 구간이 이미 학습에 들어간 데이터가 된다. 이 경우 모델 confidence가 실제보다 좋아 보일 수 있다.

### 판단

수익률 예측 모델 자체를 당장 중단해야 할 정도의 구조적 문제는 보이지 않는다.

하지만 confidence를 실거래 의사결정의 핵심 조건으로 쓰는 현재 구조에서는 calibration 방식을 개선해야 한다.

## 3. 모델 예측 로직 점검

### 확인 내용

예측 로직은 최신 feature date만 사용하고, 필요한 feature가 없으면 실패시키는 구조다.

이 부분은 좋은 방어 로직이다. 오래된 feature로 조용히 예측하는 것보다, 명시적으로 실패하는 편이 실거래에서는 더 안전하다.

현재 예측 산출물은 204개 종목 기준으로 생성되어 있다.

### 판단

예측 실행 자체는 정상으로 보인다.

다만 예측값의 품질은 학습 모델과 calibration 품질에 의존한다. 따라서 예측 로직보다 더 중요한 문제는 모델 검증과 confidence 신뢰도다.

## 4. 랭킹 점수 산출 로직 점검

### 확인 내용

랭킹 점수는 대체로 다음 요소를 조합한다.

- 예측 수익률 점수
- Top20 확률 점수
- 기술적 점수
- 품질 점수
- 수급/flow 점수
- 리스크 페널티

현재 테마 오버레이는 실운영 점수에 강하게 개입하지 않는 것으로 보이며, 최종 점수는 비교적 명확한 방식으로 계산된다.

### 주요 리스크

랭킹 KPI가 아직 `ALERT` 상태다.

특히 기술점수와 최종 성과의 관계가 안정적이지 않고, confidence calibration도 충분히 검증되지 않았다.

### 판단

랭킹 산식이 없는 상태는 아니며, 점수 계산 구조도 운영 가능한 수준이다.

하지만 랭킹 점수를 근거로 자동매수 규모를 키우기에는 아직 검증이 부족하다. 현재처럼 게이트를 `PILOT`으로 유지하는 판단이 맞다.

## 5. 자동매수 후보 선정 로직 점검

### 확인 내용

자동매수 후보 선정은 보수적으로 동작한다.

주요 조건은 다음과 같다.

- confidence 기준
- 유동성 기준
- 거래대금 기준
- 단기 급등 과열 제한
- 섹터/테마 편중 제한
- 운영 게이트 상태 확인

최근 후보 선정 리포트 기준으로 204개 종목 중 대부분이 hard filter에서 제외되고, 최종 10개 후보만 남았다.

### 최근 보완 사항

주문 실행에서 확인된 문제는 다음과 같다.

- 초당 거래건수 초과
- 예산 부족으로 1주도 살 수 없는 주문
- 여러 BUY 주문이 같은 현금을 중복 사용하는 위험

이에 대해 주문 제출 로직에 다음 보완이 들어갔다.

- 주문 간격 설정
- 초당 거래건수 초과 시 1회 재시도
- BUY 주문별 현금 예약
- 제출 직전 가능수량 재확인

### 판단

후보 선정 자체는 공격적이지 않고, 실거래 제출 단계의 방어 로직도 보강되었다.

다만 현재 게이트가 `PILOT`이므로 자동매수 규모를 키우는 것은 아직 이르다.

## 6. 종목 보유 로직 점검

### 확인 내용

보유 종목에 대해서는 다음 로직이 존재한다.

- 손절
- 트레일링
- 최대보유일
- 목표비중 초과 시 trim
- 랭킹/신뢰도 하락 시 exit 후보

이 구조는 기본적으로 합리적이다.

### 최근 확인된 문제

리노공업 사례에서 하루 전 매수한 종목이 다음날 바로 매도 후보로 잡히는 문제가 있었다.

단순히 랭킹이 하락해서 매도된 것이 아니라, confidence가 누락된 경우 `hold_allowed`가 false가 되면서 최소보유일 보호를 충분히 받지 못한 것이 원인으로 보인다.

이에 대해 confidence가 누락되었더라도 명시적인 위험 신호가 아니고 최소보유일 이전이면 `EXIT` 대신 `HOLD_REVIEW`로 보호하도록 보완했다.

### 남은 리스크

보유 로직 자체보다 더 중요한 것은 보유상태 데이터의 최신성이다.

자동매수 후 `ai_position_state`가 바로 갱신되지 않으면, 아무리 보유 로직이 좋아도 다음 판단의 입력값이 틀어질 수 있다.

## 운영 판단

현재 시스템은 다음 상태로 보는 것이 적절하다.

- 데이터 수집: 대체로 정상
- 모델 학습: 구조는 적절하나 confidence calibration 개선 필요
- 모델 예측: 실행 로직은 정상
- 랭킹 점수: 산식은 있으나 KPI 검증 부족
- 자동매수 후보: 보수적으로 동작
- 보유 로직: 최근 문제는 일부 보완, 단 상태 동기화 보강 필요

## 우선순위 정리 — 진행 현황 (2026-05-29 갱신)

### ✅ 1순위: 자동매수 후 보유상태 동기화 — **이미 동작 중 (오해 정정)**

검토 문서 작성 시점에는 `scheduler-auto-buy`의 post_sync_steps가 누락된 것으로 추정했으나, 실제 코드 검증 결과 `_resolve_post_sync_steps()` 함수의 `auto_buy` 분기에 **이미 다음 단계들이 포함**되어 있음:

- `sync_live_account_holdings`
- `update_ai_position_state`
- `sync_live_order_fills`
- `build_live_trade_consistency_report`
- 외 6개 보고서/검증

실제 로그(2026-05-28 09:34:14 ~ 09:34:31)에서 submit_live_orders 직후 1초 내 sync_live_account_holdings → update_ai_position_state → sync_live_order_fills 순차 실행 확인됨.

**조치 없음. 우려는 코드 미확인에서 비롯된 것.**

### ✅ 2순위: 모델 confidence calibration 개선 — **완료 (2026-05-29)**

원인: `model_train.py:649`에서 `cls.fit(X, y)`로 전체 데이터 학습 후 `last_va_mask`(이미 학습에 포함)로 calibration → 누설 발생.

조치: **Out-of-fold (OOF) calibration 방식으로 교체**.

- CV 각 fold의 validation 예측을 `oof_proba` 배열에 수집
- 최종 분류기는 전체 데이터로 학습 (데이터 손실 없음)
- `IsotonicRegression`을 OOF 예측값으로 직접 학습 (모델이 본 적 없는 데이터)

검증 결과: 모델 재학습 완료 (`OOF n_cal=135573, 3 folds`), 새 calibration 적용. 예측 분포 변화 확인됨 (평균 0.027 → 0.154로 base rate에 근접).

### ⏸️ 3순위: 한국 자동매매 경로 테스트 추가 — **미진행 (보류)**

현재 KR 관련 단위 테스트는 `test_model_feature_importance.py` 1개. US 테스트 30+ 개와 대비됨.

**보류 사유**:
- 즉시 안정성 문제 없음 (운영 데이터로 검증 중)
- live 운영 1~2개월 누적 후 발견되는 패턴 기반으로 회귀 테스트 추가가 더 효과적
- 권장 시점: 2026-07~08

### ✅ 4순위: 오래된 산출물 정리 — **완료 (진단 정정 + 본질 해결)**

검토 문서는 단순 "stale 파일 삭제" 권고였으나, 실제 진단 결과 **파이프라인 결함**이 본질:
