# 2026-06-08 체류시간 증가 회의

## 1. 회의 목적

현재 LeeTrader에는 메인, 종목 상세화면, AI 자동매매, 수동매매, 랭킹분석, AI 성과 메뉴가 있다.

체류시간을 늘리기 위한 핵심 방향은 사용자를 억지로 오래 붙잡는 것이 아니라, 사용자가 매일 들어와서 더 많이 확인하고 더 깊게 탐색할 이유를 만드는 것이다.

현재 서비스의 자연스러운 사용 흐름은 다음과 같다.

1. 오늘 어떤 종목을 봐야 하는지 확인한다.
2. 왜 이 종목이 추천됐는지 확인한다.
3. 자동매매 또는 수동매매에서 어떻게 대응할지 판단한다.
4. AI 추천과 실제 성과가 믿을 만한지 검증한다.
5. 다음 날 다시 바뀐 내용을 확인한다.

따라서 체류시간 증가 전략은 다음 네 가지 축으로 설계한다.

| 축 | 설명 |
| --- | --- |
| 변화 | 어제와 오늘 사이 바뀐 종목, 점수, 리스크, 순위를 보여준다. |
| 이유 | AI가 왜 추천하거나 제외했는지 판단 근거를 설명한다. |
| 비교 | 종목끼리, 전략끼리, 과거 사례와 현재를 비교하게 한다. |
| 다음 행동 | 관심 추가, 비교 추가, 상세 분석, 모의투자, 주문 검토로 이어지게 한다. |

| 1 | 오늘의 변화 알림 + 메인 대시보드 강화 | 재방문, 첫 화면 체류 증가 | 중 | 가장 먼저 |
| 2 | 종목 상세화면 분석 여정 강화 | 종목별 탐색 시간 증가 | 중상 | 1순위와 병행 가능 |

| 7 | 개인화 관심종목 대시보드 | 반복 방문 습관화 | 상 | 로그인/저장 구조 확인 후 |

## 3. 우선순위 1: 오늘의 변화 알림 + 메인 대시보드 강화

### 목표

메인 화면을 단순 추천 종목 리스트가 아니라, 사용자가 매일 확인해야 하는 "오늘의 투자 대시보드"로 만든다.

현재 화면은 오늘의 추천 결과를 보여주는 힘은 있지만, 사용자가 어제도 봤다면 오늘 왜 다시 봐야 하는지에 대한 변화 정보가 약하다. 체류시간과 재방문을 늘리려면 "오늘 달라진 것"을 첫 화면에서 바로 보여줘야 한다.

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 오늘 새로 진입한 종목 | Top 20 또는 추천 후보에 새로 들어온 종목 표시 |
| 점수 급등 종목 | 전일 대비 final_score 상승폭 상위 종목 |
| 순위 급등 종목 | 전일 대비 ranking_rank 상승폭 상위 종목 |
| 리스크 증가 종목 | risk 관련 점수 또는 경고 수가 증가한 종목 |
| 수급 개선 종목 | 외국인/기관 수급이 개선된 종목 |
| 관심 필요 요약 | "오늘 새로 진입 3개, 리스크 증가 5개, 점수 급등 4개" 형태 요약 |

### 2026-06-08 구현 기준 메모

순위는 상대 지표라 하루 변동성이 크다. 따라서 메인 화면에서는 "랭킹 급등"을 단독으로 노출하지 않고, **오늘의 의미 있는 변화**로 표현한다.

현재 구현 기준은 다음과 같다.

| 변화 유형 | 노출 기준 |
| --- | --- |
| Top20 신규 | 전 비교일에는 Top20 밖, 오늘은 Top20 안 |
| 점수 상승 | 점수 +5 이상 또는 점수 +3 이상이면서 순위 10위 이상 상승 |
| 구간 상승 | 100위 밖/Top100/Top50/Top20 구간이 상승하고 점수 +2 이상 |
| 리스크 완화 | 리스크 페널티가 3 이상 감소하고 현재 100위 이내 |
| 순위 노이즈 | 순위 20위 이상 변동했지만 점수 변화가 2 미만인 경우. 요약에만 표시하고 주요 카드에서는 제외 |

### 2026-06-09 화면 적용 후 결정

실제 메인 화면에 적용해보니, 변화 영역을 큰 카드 섹션으로 펼쳐두면 사용자가 실제 랭킹 테이블을 보기 전에 지칠 수 있다. 메인은 "랭킹을 보러 온 화면"이므로, 변화 정보는 독립 콘텐츠처럼 크게 보여주기보다 랭킹 테이블을 보조하는 방식이 적합하다.

최종 적용 방향은 다음과 같다.

| 항목 | 결정 |
| --- | --- |
| 기본 노출 | `오늘의 의미 있는 변화`는 기본 접힘 상태 |
| 상단 문구 | 숫자 나열 대신 "현재 순위순 · 새 Top20 10개 · 점수 개선 많음 · 순위 노이즈 10개 제외 참고"처럼 해석형 한 줄로 표시 |
| 상세 펼침 | 사용자가 `자세히`를 누를 때만 변화 카드 표시 |
| 상세 카드 수 | 6개 표시 |
| 상세 카드 정렬 | 현재 랭킹 순위순 |
| 상세 카드 형태 | 한 줄에 6개 종목이 보이도록 압축 카드 사용 |
| 카드 내부 메트릭 | `순위/점수/리스크`를 큰 박스 3개가 아니라 얇은 한 줄 메타 정보로 표시 |
| 핵심 노출 위치 | 변화 종목 전체는 메인 랭킹 테이블의 종목명 옆 작은 뱃지로 표시 |

### 2026-06-09 추가 화면 조정

메인 상단의 `기준일/시장 흐름/수급 긍정/점수 우수/리스크 주의/운용 톤/상위20 점수/리스크 밀도/운영 후보` 카드들이 실제 랭킹 테이블 진입을 방해했다. 특히 수급/점수/리스크 3개 카드는 독립 카드로 볼 만큼 시선 효율이 높지 않았다.

다만 너무 작은 1줄 칩 형태로 압축하면 데이터가 눈에 들어오지 않는다. 따라서 상단 운영 요약은 다음처럼 조정한다.

| 기존 | 변경 |
| --- | --- |
| 5개 시장/추천 카드 + 4개 운영 카드 | 핵심 4개 카드 |
| 수급/점수/리스크를 각각 큰 카드로 표시 | 수급 카드는 제거, 점수/리스크는 운영 카드로 유지 |
| 운용 톤/상위20 점수/리스크 밀도/운영 후보를 2번째 줄 카드로 표시 | `시장 흐름`, `상위20 점수`, `리스크 밀도`, `운영 후보` 4개 카드만 표시 |

4개 카드 구성:

| 카드 | 내용 |
| --- | --- |
| 시장 흐름 | 기준일, 장세, 보수/공격 대응 톤 |
| 상위20 점수 | 상위20 평균 점수, 70점 이상 후보 수 |
| 리스크 밀도 | risk penalty 12 이상 종목 수 |
| 운영 검토 | 우선 검토 후보 수 / 주의 관찰 후보 수 |

이 조정의 목적은 **랭킹 테이블이 메인 화면의 주인공으로 빨리 보이게 하되, 중요한 운영 데이터는 카드 형태로 읽히게 하는 것**이다. 상단 정보는 사용자가 랭킹을 읽기 위한 상태 표시로만 남긴다.

운영 검토 용어:

| 용어 | 의미 |
| --- | --- |
| 우선 검토 | 운영 기준상 즉시 검토 우선순위가 높은 후보 |
| 주의 관찰 | 점수나 랭킹상 관찰 가치는 있지만 즉시 매수보다 확인이 필요한 후보 |

주의 관찰 선정은 `manual-trading/summary`의 `caution_candidates`를 사용한다. 우선 검토 후보를 먼저 제외한 뒤, `WATCHLIST`, `PAPER_ONLY`, `BLOCK`, 진입조건 미충족, 확신도 약화, 과열 플래그 등 운영 상태를 기준으로 분류한다.

메인 테이블에서는 주의 관찰 종목의 종목명 옆에 파란 `주의관찰` 뱃지를 붙인다. 이 뱃지는 수익/위험 신호가 아니라 "운영 검토상 바로 진입보다 관찰이 필요한 종목"이라는 의미다.

현재 구현 API:

```http
GET /api/ranking/meaningful-changes?date=YYYY-MM-DD
```

응답 핵심 필드:

| 필드 | 설명 |
| --- | --- |
| `summary` | Top20 신규, 점수 상승, 구간 상승, 리스크 완화, 순위 노이즈 요약 |
| `featured` | 펼침 영역에 표시할 현재 순위순 대표 변화 종목 |
| `items` | 메인 랭킹 테이블 뱃지에 사용할 전체 의미 있는 변화 종목 |

프론트 적용 방식:

| 위치 | 적용 |
| --- | --- |
| 변화 섹션 | 기본 접힘, 요약 한 줄만 표시 |
| 변화 상세 | 펼침 시 6개 압축 카드 |
| 메인 테이블 | 종목명 옆 `Top20 신규`, `점수 +5 이상`, `Top50 → Top20`, `리스크 완화` 등 작은 뱃지 표시 |
| 모바일 카드 | 종목명 옆 동일 뱃지 표시 |

이 결정의 핵심은 "변화 섹션을 키우는 것"이 아니라 **랭킹 테이블 자체를 더 똑똑하게 만드는 것**이다.

## 4. 우선순위 2: 종목 상세화면 분석 여정 강화

### 목표

종목 상세화면을 단순 정보 나열이 아니라 "AI 분석을 따라가며 판단하는 화면"으로 만든다.

사용자가 종목 상세에서 오래 머무는 이유는 차트 자체가 아니라 다음 질문에 답을 얻기 위해서다.

1. 왜 이 종목이 추천됐는가?
2. 지금 가격이 좋은 위치인가?
3. 어떤 조건이면 매수 또는 관망인가?
4. 틀렸을 때 어디서 위험을 줄여야 하는가?
5. 과거 비슷한 사례에서는 어떻게 움직였는가?

### 구현할 기능

| 섹션 | 설명 |
| --- | --- |
| AI 종합 의견 | 한 문단 요약. 추천 강도, 관망/주의 여부 포함 |
| 추천 근거 분해 | 점수에 기여한 상위 요인 3~5개 |
| 리스크 분해 | 감점 또는 주의 요인 3~5개 |
| 가격 위치 | 현재가가 20일/60일 추세, 변동성 구간에서 어디인지 표시 |
| 수급 추적 | 외국인/기관 5일, 20일 방향성 |
| 시나리오 | 상승, 횡보, 하락 조건별 대응 |
| 과거 유사 사례 | 유사한 점수/수급/기술 패턴 이후 성과 |
| 다음 행동 | 관심 추가, 비교 추가, 수동매매 검토, 모의투자 보기 |

### 화면 구성

권장 순서:

1. 상단: 종목명, 점수, 순위, 전일 대비 변화, 리스크 상태
2. AI 요약: "현재 AI 판단"
3. 왜 추천됐나: 긍정 요인
4. 왜 조심해야 하나: 리스크 요인
5. 지금 가격 위치: 차트 + 주요 기준선
6. 시나리오: 상승 / 횡보 / 하락
7. 과거 유사 사례
8. 행동 버튼

## 5. 우선순위 3: AI 판단 로그 / 자동매매 관제화

### 목표

AI 자동매매 화면을 단순 결과 확인 화면이 아니라 "AI가 지금 무엇을 감시하고 왜 행동하지 않는지 보여주는 관제실"로 만든다.

자동매매에서 사용자가 가장 궁금한 것은 체결 여부보다 다음이다.

1. AI가 지금 어떤 종목을 보고 있는가?
2. 왜 매수하지 않았는가?
3. 어떤 조건이 충족되면 매수하는가?
4. 보유 종목은 왜 계속 보유하는가?
5. 매도 위험은 어떤 기준으로 감시하는가?

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 현재 감시 종목 | 자동매매가 후보로 보고 있는 종목 리스트 |
| 조건 충족률 | 진입 조건 5개 중 3개 충족 같은 형태 |
| 매수 보류 사유 | 게이트, 가격, 수급, 리스크 등 미진입 이유 |
| 보유 판단 사유 | 보유 유지, 축소, 매도 검토 사유 |
| 최근 판단 로그 | 시간순으로 AI 판단 이벤트 표시 |
| 자동매매 사이클 타임라인 | 09:10 사전 점검, 09:30 실행, 10:00 재확인 등 |

### 화면 구성

AI 자동매매 메뉴를 다음 구조로 바꾼다.

| 영역 | 내용 |
| --- | --- |
| 상단 상태 | 운영 모드, BUY 허용 여부, 최신 데이터 기준일, 마지막 실행 시각 |
| 감시 리스트 | 현재 매수 후보와 조건 충족률 |
| 보유 리스트 | 보유 종목별 AI 판단과 매도 위험 |
| 판단 로그 | 최근 실행 사이클별 이벤트 |
| 예외/주의 | 데이터 지연, 주문 실패, 게이트 차단 등 |

### 데이터 구현

활용 가능한 산출물 후보:

| 파일/데이터 | 용도 |
| --- | --- |
| `outputs/order_requests_preview.json` | 주문 후보/미리보기 |
| `trade_intents` 계열 산출물 | 매수/매도 의도 |
| `ai_position_state.json` | 보유 종목 상태 |
| `auto_ops_auto_buy_scheduler_status.json` | 자동매매 스케줄 실행 상태 |
| `operational_buy_gate` 계열 | 매수 게이트 상태 |

```json
  "cycle": "auto_buy",
  "code": "083650",
  "name": "비에이치아이",
  "decision": "WATCH",
  "reason": "BUY gate 차단. 시장 국면 방어 우위.",
  "conditions": [
    {"name": "rank_top20", "passed": true},
    {"name": "score_threshold", "passed": true},
    {"name": "risk_limit", "passed": false},
    {"name": "market_gate", "passed": false}

```

### 백엔드 구현

권장 API:

```http

```

구현 원칙:

1. 주문 로직 자체를 먼저 바꾸지 않는다.
2. 기존 판단 결과를 읽어서 설명용 로그를 만든다.
3. 실거래 판단과 UI 설명 사이의 불일치를 막기 위해 같은 산출물에서 파생한다.
4. 데이터가 없을 때는 "판단 로그 없음"이 아니라 "오늘 자동매매 사이클 미실행"처럼 원인을 표시한다.

### 프론트 구현

| 작업 | 설명 |
| --- | --- |
| 조건 체크리스트 | 종목별 진입 조건 통과/실패 표시 |
| 타임라인 | 최근 사이클을 시간순 표시 |
| 보류 사유 뱃지 | 게이트 차단, 리스크 초과, 수급 부족 등 |
| 상세 펼침 | 각 판단의 근거 데이터 노출 |

### 지표

| 지표 | 목표 |
| --- | --- |
| AI 자동매매 화면 체류시간 | 증가 |
| 판단 로그 펼침률 | 증가 |
| 자동매매 화면 재방문율 | 증가 |
| 운영 상태 문의 감소 | 증가가 아니라 감소가 목표 |

## 6. 우선순위 4: 랭킹분석 탐색형 리그화 + 종목 비교

### 목표

랭킹분석을 단순 순위표가 아니라, 사용자가 여러 관점으로 종목을 찾아보는 탐색 도구로 만든다.

전체 1등만 보여주면 사용자는 금방 떠난다. 반대로 "수급 개선", "리스크 감소", "점수 급등", "섹터별 상위"처럼 여러 리그가 있으면 더 오래 탐색한다.

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 점수 급등 리그 | 전일 대비 점수 상승 상위 |
| 순위 급등 리그 | 전일 대비 순위 상승 상위 |
| 수급 개선 리그 | 외국인/기관 수급 개선 상위 |
| 리스크 감소 리그 | 리스크 penalty 감소 상위 |
| 섹터별 TOP 5 | 업종별 상위 종목 |
| 반전 후보 | 점수는 중위권이지만 개선 속도가 빠른 종목 |
| 종목 비교 | 2~3개 종목의 점수, 수급, 리스크, 기대수익 비교 |

### 화면 구성

랭킹분석 메뉴에 다음 탭을 둔다.

## 7. 우선순위 5: 수동매매 의사결정 보조

### 목표

수동매매 화면을 주문 입력 화면이 아니라, 주문 전에 AI가 리스크와 조건을 점검해주는 의사결정 보조 화면으로 만든다.

수동매매에서 사용자는 주문 직전에 가장 오래 고민한다. 이 구간에 정보가 있으면 체류시간과 신뢰가 함께 증가한다.

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 매수 전 AI 체크리스트 | 추세, 수급, 리스크, 가격 위치, 시장 게이트 |
| 현재가 적정성 | 추천 구간 대비 현재가 위치 |
| 손익비 계산 | 목표/손절 기준 입력 또는 자동 제안 |
| 손절 기준 제안 | 변동성 또는 최근 저점 기준 |
| 주문 전 경고 | 리스크 높음, 수급 악화, 게이트 차단 등 |
| 주문 메모 | 사용자가 매수 이유를 기록 |

### 화면 구성

수동매매 화면에서 종목 선택 시 우측 또는 상단에 AI 체크 패널을 표시한다.

| 무계획 주문 비율 | 감소 |

## 8. 우선순위 6: AI 성과 화면 신뢰 콘텐츠화

### 목표

AI 성과 화면을 단순 수익률 표시가 아니라, 사용자가 AI를 검증하고 학습할 수 있는 신뢰 콘텐츠로 만든다.

성과 화면에서 중요한 것은 좋은 성과만 보여주는 것이 아니다. 실패 사례와 시장 구간별 약점까지 보여줘야 오히려 신뢰가 올라간다.

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 추천 후 성과 | 추천 후 1일, 5일, 20일, 60일 성과 |
| 성공 사례 | 추천 근거와 실제 주가 흐름 |
| 실패 사례 | 실패 원인 분석 |
| 시장 구간별 성과 | 상승장, 하락장, 변동장 구분 |
| 전략별 성과 | 점수 상위, 수급 개선, 리스크 낮음 등 기준별 비교 |
| 만기 코호트 | 추천일 기준 코호트별 누적 성과 |

### 화면 구성

| 영역 | 내용 |
| --- | --- |
| 상단 요약 | 최근 30일/60일 추천 성과 |
| 코호트 차트 | 추천일별 누적 성과 |
| 성공/실패 사례 | 대표 종목 카드 |
| 시장 구간별 분석 | 어떤 장세에서 강하고 약한지 |
| 전략 비교 | 리그별 성과 비교 |

### 데이터 구현

필요 항목:

| 항목 | 설명 |
| --- | --- |
| 추천일 | 종목이 추천된 날짜 |
| 추천 당시 점수/순위 | 당시 기준 값 |
| 이후 가격 | 1일, 5일, 20일, 60일 후 가격 |
| 시장 상태 | 추천 당시 시장 국면 |
| 추천 근거 | 당시 top_driver |
| 리스크 요인 | 당시 risk_factor |

### 백엔드 구현

권장 API:

```http
GET /api/performance/cohorts
GET /api/performance/cases?type=success
GET /api/performance/cases?type=failure
GET /api/performance/by-market-regime
```

주의사항:

1. 아직 60일 만기 데이터가 충분하지 않으면 1일/5일/20일 중심으로 표시한다.
2. 성과가 불리한 구간도 숨기지 않는다.
3. "미래 수익 보장" 표현을 피하고 참고 지표로 표현한다.

### 프론트 구현

| 작업 | 설명 |

| 성공/실패 탭 | 케이스 전환 |

| 시장 구간 필터 | 방어/중립/공격 등 |

### 지표

| 지표 | 목표 |
| --- | --- |
| AI 성과 화면 체류시간 | 증가 |

## 9. 우선순위 7: 개인화 관심종목 대시보드

### 목표

사용자가 관심종목을 등록하고 매일 자신의 종목 변화를 확인하게 만든다.

개인화는 체류시간보다 재방문 습관에 더 강하다. 단, 사용자 식별, 저장소, 알림 구조가 필요하므로 우선순위는 뒤로 둔다.

### 구현할 기능

| 기능 | 설명 |
| --- | --- |
| 관심종목 추가 | 메인, 상세, 랭킹에서 추가 |
| 내 관심종목 변화 | 점수, 순위, 리스크 변화 |
| 관심종목 알림 | 신규 리스크, 점수 급등, 매수 조건 충족 |
| 관심종목 비교 | 내 종목끼리 비교 |
| 메모 | 사용자가 관심 이유 기록 |

### 백엔드 구현

권장 API:

```http
GET /api/watchlist
POST /api/watchlist
DELETE /api/watchlist/:code
GET /api/watchlist/changes
```

필요 테이블 예시:

```sql
CREATE TABLE user_watchlist (
  user_id TEXT NOT NULL,
  code TEXT NOT NULL,
  memo TEXT,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, code)
);
```

로그인 전이라면 임시로 브라우저 localStorage 기반 관심종목부터 시작할 수 있다. 이후 로그인 기능이 안정되면 서버 저장으로 이전한다.

### 프론트 구현

| 작업 | 설명 |
| --- | --- |
| 관심 추가 버튼 | 종목 행, 상세 화면, 비교 화면에 배치 |
| 내 관심 탭 | 메인 또는 별도 메뉴에 표시 |
| 변화 뱃지 | 점수 상승, 리스크 증가 등 |
| 메모 입력 | 간단한 텍스트 저장 |

### 지표

| 지표 | 목표 |
| --- | --- |
| 관심종목 등록률 | 증가 |
| 관심종목 사용자 재방문율 | 증가 |
| 관심종목 화면 체류시간 | 증가 |
| 알림 클릭률 | 증가 |

## 10. MVP 구현 순서

### 1차 MVP: 메인 변화 + 상세 분석

기간 목표: 가장 먼저 적용

작업:

1. 전일 대비 점수/순위 변화 계산
2. 메인 화면에 오늘의 변화 카드 추가
3. 랭킹 테이블에 점수 변화, 신규 진입 뱃지 표시
4. 종목 상세에 AI 요약, 추천 근거, 리스크 요인, 시나리오 섹션 추가

## 13. 구현 시 주의사항

1. 실거래 로직은 먼저 바꾸지 않는다.
   - 초기 체류시간 개선은 UI와 설명 데이터 중심으로 진행한다.
   - 자동매매 판단 설명은 실제 주문 산출물에서 파생해야 한다.

2. 추천 표현은 과장하지 않는다.
   - "매수 추천", "수익 보장" 같은 표현을 피한다.
   - "AI 관찰", "후보", "주의 필요", "조건 충족" 중심으로 표현한다.

3. 데이터가 없는 경우를 명확히 처리한다.
   - 전일 데이터 없음
   - 장중 갱신 전
   - 자동매매 사이클 미실행
   - 60일 성과 만기 전

4. 화면은 정보가 많아져도 복잡해 보이지 않게 한다.
   - 메인은 요약 위주
   - 메인 변화 정보는 기본 접힘으로 두고, 핵심 정보는 테이블 뱃지로 흡수
   - 상세는 분석 단계화
   - 랭킹은 탭으로 분리
   - 자동매매는 타임라인 중심

5. 성과 화면은 성공과 실패를 함께 보여준다.
   - 실패 사례를 숨기면 단기적으로 좋아 보일 수 있지만 장기 신뢰가 약해진다.

## 14. 최종 제안

현재까지 적용한 1차 방향은 다음과 같다.

1. 메인 "오늘의 의미 있는 변화"는 기본 접힘으로 유지한다.
2. 변화 상세는 현재 순위순 6개 압축 카드로만 제공한다.
3. 실제 탐색의 중심은 메인 랭킹 테이블이며, 변화 정보는 종목명 옆 작은 뱃지로 흡수한다.

다음 회의에서 이어갈 우선 논의 주제:

| 순서 | 논의 주제 | 이유 |
| --- | --- | --- |
| 1 | 메인 상단 운영 카드 축소 여부 | 랭킹 테이블 진입 전 정보량이 아직 많음 |
| 2 | 테이블 변화 뱃지의 문구/색상 정리 | 뱃지가 많아지면 행이 복잡해질 수 있음 |
| 3 | 종목 상세 진입 후 분석 여정 강화 | 테이블에서 상세로 넘어간 뒤 체류시간을 늘리는 핵심 단계 |
| 4 | 변화 뱃지 클릭 시 상세 내 해당 근거 위치로 이동 | 메인 변화 정보와 상세 분석을 연결 |

이 방향은 현재 서비스 구조를 크게 바꾸지 않으면서도 체류시간 증가에 직접적으로 작용한다.

특히 LeeTrader는 커뮤니티형 서비스보다 "오늘 시장에서 놓치면 안 되는 변화가 있다"는 감각을 만드는 쪽이 더 적합하다. 따라서 체류시간 증가의 핵심은 콘텐츠 양이 아니라 변화, 이유, 비교, 다음 행동을 촘촘하게 연결하는 것이다.
