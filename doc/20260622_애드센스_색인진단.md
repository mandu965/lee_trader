## 1. 결론

현재 문제는 robots.txt나 HTTP 장애보다 **사이트맵 과다 노출과 콘텐츠 가치 신호 부족**에 가깝다.

- Search Console: 색인 8개, 미색인 55개
- 미색인 중 `발견됨 - 현재 색인이 생성되지 않음`: 52개
- robots.txt 차단: 3개
- 운영 sitemap URL: 62개
- 운영 sitemap 62개는 모두 HTTP 200, canonical·H1 정상
- 운영 응답시간은 주요 페이지 기준 약 0.47~0.69초
- 62개 중 본문 500단어 미만 페이지: 38개
- Markdown 콘텐츠 51개 중 내부 품질 기준 500단어 미만: 41개

따라서 서버가 페이지를 제공하지 못해서가 아니라, 새 도메인에서 짧고 범용적인 금융 글이 한꺼번에 다수 발견되어 Google이 크롤링 우선순위를 낮게 두었을 가능성이 높다.

robots.txt 차단 3건은 현재 `/api/` 차단 URL로 추정된다. API는 검색 결과에 노출할 대상이 아니므로 정상이다. Search Console의 예시 URL이 `/api/`가 아니라면 별도 확인한다.

## 2. 발견한 기술 문제

### sitemap 수정일 오류

운영 sitemap의 정적 페이지 `lastmod`가 실제 수정일과 관계없이 매일 오늘 날짜로 생성됐다.

이 상태는 Google에 모든 정적 페이지가 매일 변경된 것처럼 잘못 알린다. 콘텐츠 갱신 신뢰도를 낮추고 불필요한 재평가 대상을 늘릴 수 있다.

### 준비도 검사의 거짓 PASS

기존 `python/check_adsense_readiness.py`는 아래만 확인했다.

- 콘텐츠 파일 20개 이상
- 필수 정적 페이지 존재
- ads.txt와 sitemap 선언 존재

본문 길이와 색인 대상 품질은 확인하지 않아, 짧은 콘텐츠가 41개여도 PASS였다.

## 3. 적용한 수정

배포 커밋:

- `1d2ee75` — 색인 품질 제어·콘텐츠 검수 상태
- `5f530c4` — sitemap `lastmod` 정확성 보정

### sitemap

- 정적 페이지는 실제 HTML 파일 수정일 사용
- 콘텐츠는 `modified`, 없으면 `date` 사용
- `indexable: false` 콘텐츠는 sitemap 제외
- robots.txt와 sitemap에 1시간 cache header 적용

### 콘텐츠 검수 상태

Markdown frontmatter에 다음 필드를 지원한다.

```yaml
modified: 2026-06-22
indexable: false
```

`indexable: false`인 글은:

- sitemap 제외
- 홈·블로그·리포트 목록 제외
- 상세 URL은 유지
- `noindex, follow` 적용
- AdSense 스크립트 미삽입

콘텐츠를 보강한 뒤 `indexable: true`로 되돌릴 수 있다.

## 6. AdSense 재신청 기준

Google은 공식적인 최소 글 수나 최소 단어 수를 제시하지 않는다. 아래는 Lee Trader Lab의 내부 재신청 기준이다.

- 운영 sitemap과 canonical 정상
- 핵심 콘텐츠 10개 이상 유지
- 고유 방법론·실제 사례 글 5개 이상 보강
- Search Console에서 핵심 콘텐츠가 실제 색인됨
- 모바일 메뉴·내부 링크·정책 페이지 정상
- 빈 화면, 데이터 로딩 실패, 공사 중 문구 없음
- 검수 대기 페이지에는 광고 스크립트 없음
- 수정 후 최소 2주간 수집·사용자 반응 확인

위 조건을 충족하기 전 반복 재신청하지 않는다.
