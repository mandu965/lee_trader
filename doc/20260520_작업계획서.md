### [KR-A] 모델 예측 기간과 보유 기간 정합 (핵심)

**파일**: `python/model_train.py`, `python/ai_position_risk.py`

**현재 문제**:

| 모델 예측 기간 | 실제 보유 기간 |
|---|---|
| `pred_return_60d` / `pred_return_90d` 중심 | `AI_MAX_HOLDING_DAYS=15일` |

60~90일 신호로 뽑은 종목을 15일 만에 끊으면 **모델이 맞아도 수익 실현이 안 됨.**  
이 불일치가 현재 0.55%/월에 가장 큰 영향을 주는 구조적 문제.

**작업 내용**:
1. `label_builder.py`에 이미 있는 `pred_return_30d` 레이블 → `model_train.py`에 학습 타겟 추가
2. `AI_MAX_HOLDING_DAYS` 를 30일로 조정 검토 (서버 확인 후)
3. 30일 타겟이 안정화되면 60/90d 혼합 가중치 재검토

**운영 반영 조건**:
- `pred_return_30d` 추가 모델이 기존 기준 대비 OOS 수익률·MDD·turnover 기준에서 열화되지 않을 것
- `AI_MAX_HOLDING_DAYS=30` 변경은 백테스트 또는 paper 재현 결과 확인 후 반영할 것
- 모델 타겟 변경과 보유기간 변경을 동시에 반영할 경우, 변경 전후 비교표를 남길 것

**우선순위**: 1순위 (서버 접속 후 즉시)

### [US-G] US AI 매수 정책 명세 정리 (2026-05-21 추가)

**목적**: KR에서 정리한 것과 같은 관점으로, US도 `무엇을 사는지`보다 `어떤 종목만 사도록 제한하는지`를 먼저 명확히 한다.  
US는 현재 매수 후보 필터가 비교적 잘 설계되어 있으므로, 당장 뒤엎기보다 **실운영 전 정책 문장과 실제 코드 기준을 정렬**하는 것이 우선이다.

**현재 코드 기준 매수 구조**:
1. ranking source 상위 종목 로드 (`top_n`)
2. grade / score / financial / benchmark strength / gap / intraday / volatility / cooldown / kill switch 다층 차단
3. 기존 포지션 보유, SELL 신호 존재, REVIEW_REQUIRED 존재 시 buy conflict guard로 추가 차단

**현재 장점**:
- KR보다 매수 필터가 더 분리되어 있고, `buy_automation` / `conflict_guard` / `trade_orchestration` 경계가 명확함
- 실운영 전 단계에서 `중복 매수`, `직전 청산 후 재진입`, `SELL 우선` 같은 운영 안전장치가 이미 들어가 있음

**현재 약점**:
- 문서상 `ranking grade는 자동 매수 신호가 아니다`라고 적혀 있지만, 실제 자동매수는 Top N + grade + score를 바로 후보로 사용
- `probability` 필드는 아직 안정적 공급이 부족하여 `US_BUY_MIN_PROB > 0` 사용 시 의도치 않게 대부분 차단될 수 있음
- 실운영 전이라도 `BUY`와 `STRONG_BUY`의 우선순위 차등 정책이 아직 약함

**권장 정책 원칙**:
1. **초기 실운영 전까지는 매수는 더 엄격하게 유지**
   - `Top N`은 5 또는 10 이내 유지
   - `recommend_grade in ('STRONG_BUY', 'BUY')` 유지
   - score 하한, financial data, benchmark strength, data fail-safe 유지
2. **`STRONG_BUY`를 `BUY`보다 우선 배정**
   - 동일 예산/슬롯이면 `STRONG_BUY` 먼저
   - `BUY`는 slot 여유가 있을 때만 진입
3. **probability는 안정화 전까지 보조 지표**
   - `US_BUY_MIN_PROB=0` 유지 또는 매우 보수적 적용
   - `latest_probability` 공급 안정 후에만 매수 필수 조건으로 승격
4. **실운영 오픈 전 섹터 집중 제한을 paper 기준으로 먼저 검증**
   - 단일 종목/단일 섹터 쏠림이 없는지 paper 20~60거래일 로그로 확인

**운영 적용 해석**:
- US 매수는 `좋은 종목을 많이 사는 구조`가 아니라 `좋은 종목만 소수로 제한 진입하는 구조`가 맞다.
- 따라서 KR처럼 매수 기준을 더 풀기보다, **현재의 엄격함을 유지한 채 매도/보유 정책을 개선**하는 것이 우선이다.

**우선순위**: 2순위 (정책 확정은 즉시 가능, 실제 반영은 US-H와 함께 검토)

### [US-H] US AI 매도 정책 명세 정리 — KR 노하우 전수 (2026-05-21 추가)

**배경**: 현재 US 매도 로직은 `stop_loss / trailing / max_holding / rank_score_deterioration / benchmark_underperformance / take_profit`가 분리되어 있으나, 실제 결과는 다수가 `FULL_SELL`로 귀결된다.  
이 구조는 손실 통제에는 유리하지만, KR에서 확인한 것처럼 **winner를 오래 보유하지 못하고 조기 청산할 가능성**이 크다.

**현재 코드 기준 핵심 문제**:
1. trailing stop이 `최소 수익 구간` 없이 고정 발동 성격
2. `max_holding_days` 도달 시 수익 여부와 무관하게 `FULL_SELL`
3. `rank/score/prob` 약화가 단계적 감액이 아니라 곧바로 `FULL_SELL`
4. `take_profit`도 partial 기본값이 아니면 전량청산

**권장 정책 원칙**:
1. **loser cut은 유지**
   - `stop_loss`는 즉시 청산 유지
   - `risk_off_market_exit`도 유지
2. **winner run 구조 추가**
   - trailing stop은 `충분한 수익 구간`에서만 발동
   - `max_holding`은 soft / hard 이중 구조로 분리
   - `take_profit`은 partial sell 기본값으로 전환
3. **순위/점수 약화는 단계화**
   - 단순 rank 이탈: REVIEW_REQUIRED 또는 PARTIAL_SELL
   - score/prob 의미 있는 약화: PARTIAL_SELL 우선
   - 구조적 붕괴 또는 손실 심화: FULL_SELL
4. **진입 직후 흔들림 유예**
   - rank 변동만으로 진입 직후 바로 전량청산하지 않도록 5~10영업일 교체/청산 유예 도입 검토
   - 단, stop_loss / risk_off / data error는 유예 없이 즉시 적용

**권장 설계안 A (단순형)**:
- `US_SELL_STOP_LOSS_PCT`: 현행 유지
- trailing:
  - `pnl < 8%` → trailing 미발동
  - `pnl >= 8%` → trailing 발동
  - trailing 폭은 `10%` 기준 유지 또는 소폭 완화 검토
- holding:
  - `soft max holding` 도입 (예: 30~40영업일)
  - `hard cap` 유지 (예: 60영업일)
  - soft max 초과 + 손실권 → FULL_SELL
  - soft max 초과 + 수익권 → HOLD 또는 PARTIAL_SELL
- deterioration:
  - `rank_exit_threshold` 이탈만으로는 즉시 FULL_SELL 금지
  - 1차는 REVIEW_REQUIRED 또는 PARTIAL_SELL
- take profit:
  - `US_SELL_PARTIAL_TAKE_PROFIT_ENABLED=true`
  - 예: +15% 도달 시 30~50% 익절, 잔여분은 trailing/hard cap로 관리

**권장 설계안 B (정교형, 2차 검토)**:
- trailing 구간별 차등
  - `8% <= pnl < 15%` → 고점 대비 -10%
  - `pnl >= 15%` → 고점 대비 -12%
- deterioration도 rank/score/prob 약화 정도에 따라 `PARTIAL_SELL -> FULL_SELL` 2단계화

**우선 적용 권장순서**:
1. trailing에 `최소 수익 구간` 추가
   - **코드 변경 필요**: 현재 `config.py`에 `trailing_stop_min_profit` 필드 없음 → `SellAutomationConfig`에 필드 추가 + `sell_rule_engine.py` 발동 조건 수정
   - 신규 env var: `US_SELL_TRAILING_MIN_PROFIT_PCT` (권장 기본값 `0.08`)
2. `max_holding_days` soft / hard 분리
   - **코드 변경 필요**: 현재 hard 60d만 존재 → `soft_max_holding_days` 필드 추가 + `sell_rule_engine.py` 에 soft/hard 이중 체크 로직 추가
   - 신규 env var: `US_SELL_SOFT_MAX_HOLDING_DAYS` (권장 기본값 `35`)
   - soft 초과 + 수익권 → HOLD, soft 초과 + 손실권 → FULL_SELL
3. `take_profit` partial sell 기본 활성화
   - **env var만 변경**: `US_SELL_PARTIAL_TAKE_PROFIT_ENABLED=true` (코드 이미 존재)
4. `rank/score/prob deterioration -> FULL_SELL` 완화
   - **코드 변경 필요**: `sell_rule_engine.py`에서 rank 이탈 즉시 FULL_SELL 분기를 REVIEW_REQUIRED/PARTIAL_SELL 분기로 전환
5. 진입 후 5~10영업일 유예 도입 검토
   - **코드 변경 필요**: KR-G-4와 동일 패턴, entry_date 기준 영업일 계산 + grace period 체크

**운영 해석**:
- US는 KR보다 매수 필터는 잘 잡혀 있으므로, **실운영 전 핵심 개선 포인트는 buy가 아니라 hold/sell lifecycle**이다.
- 목표는 `매수는 엄격`, `매도는 단계적`, `winner는 오래 보유`, `loser는 즉시 정리` 구조로 맞추는 것이다.

**우선순위**: 2순위 (US-E live 전환 전 정책 확정 필요)

     - 약화 신호 감액은 50% 내외
     - 서로 다른 성격의 partial sell을 분리 운영

2. **`partial take profit` 기본 정책 정렬**
   - 문서 방향이 `부분 익절 후 잔여 보유`라면, `US_SELL_PARTIAL_TAKE_PROFIT_ENABLED`는 기본 ON 정책으로 맞추는 것이 일관된다.
   - 반대로 기본 OFF를 유지할 경우, 문서도 “옵션 기능”으로 표현을 낮춰 코드와 맞춰야 한다.
   - 권장:
     - paper 단계에서는 ON으로 검증
     - live 전환 전 review에서 최종 기본값 확정

3. **`entry grace` 적용 범위 축소**
   - 현재 grace는 `rank`, `score`, `probability` 약화까지 넓게 유예할 수 있으므로, 유예 범위를 더 좁게 정의하는 것이 바람직하다.
   - 권장:
     - `RANK_EXIT_THRESHOLD` 기반 약화만 5~10영업일 유예
     - `SCORE_BELOW_HOLD`, `PROBABILITY_BELOW_HOLD`는 즉시 `PARTIAL_SELL` 또는 `REVIEW_REQUIRED`
   - 해석:
     - rank 하락은 초기 noise 가능성이 큼
     - score/prob 약화는 구조적 약화 가능성이 높아 무조건 유예하면 안 됨

**권장 운영 기본값 예시**:
```env
US_SELL_TRAILING_MIN_PROFIT_PCT=0.08
US_SELL_TRAILING_STOP_PCT=0.10
US_SELL_SOFT_MAX_HOLDING_DAYS=35
US_SELL_MAX_HOLDING_DAYS=60
US_SELL_ENTRY_GRACE_DAYS=7
US_SELL_PARTIAL_TAKE_PROFIT_ENABLED=true
US_SELL_PARTIAL_TAKE_PROFIT_RATIO=0.30
US_SELL_PARTIAL_DETERIORATION_RATIO=0.50
```

**정리**:
- `winner run` 방향 자체는 유지
- 수정 포인트는 “되돌리기”가 아니라 “partial sell 세분화”와 “grace 범위 정리”다.

## 6-1. 월 2% 달성을 위한 전략 정리

### 현재 판단

- 현재 KR/US 자동매매에는 `월 2%를 안정적으로 만드는 검증된 필승전략`이 이미 완성되어 있다고 보기 어렵다.
- KR은 종목 선정 엔진은 준수하나, 보유 기간과 청산 로직이 예측 기간과 정합되지 않아 알파가 누수되고 있다.
- US는 리스크 차단 규칙은 갖춰졌지만, 운영 로직 그대로의 실전형 백테스트와 충분한 paper 검증이 아직 부족하다.
- 따라서 지금 단계의 핵심 목표는 `고수익 약속`이 아니라 `알파가 나는 구조를 검증하고 복리형 운영 구조로 정렬하는 것`이다.

### KR AI 판단

- 강점:
  - `ret / prob / tech / qual / flow - risk_penalty` 구조의 다축 점수 체계가 이미 운영에 반영되어 있음
  - 단일 팩터 추종보다 안정적인 종목 선별 기반을 갖추고 있음
- 약점:
  - `pred_return_60d / 90d` 중심 예측과 `AI_MAX_HOLDING_DAYS=15`가 구조적으로 충돌
  - 상태 복구 취약점으로 trailing / holding rule이 무력화될 수 있음
  - 익절보다 조기 정리 쪽으로 기울어 있어 강한 종목을 오래 보유하는 구조가 약함
- 결론:
  - KR은 `종목 선정 엔진`보다 `보유/청산 엔진` 개선이 더 시급하다.

### US AI 판단

- 강점:
  - 매수 차단 규칙, 쿨다운, kill switch, benchmark strength, volatility 차단 등 방어 로직이 잘 갖춰져 있음
  - ML ranking 기반으로 확률·수익예측을 함께 활용할 수 있는 구조가 있음
- 약점:
  - 현재 기본 운용은 초기 safety cap 중심이라 포지션 수와 자본 투입이 너무 작음
  - 매수 시 확률 기준과 보유 시 확률 기준이 완전히 정합되지 않음
  - 현재 운영 로직을 그대로 재현한 net 백테스트 결과가 아직 없음
- 결론:
  - US는 `리스크 제어형 파일럿` 단계이며, 아직 `개인 ETF형 복리 전략`으로 보기 어렵다.

### 개인 ETF형 운영 원칙

- 목표는 단기 고배율 승부가 아니라 `분산 + 교체 + 손실 제한 + 재투자` 구조를 만드는 것이다.
- 소수 종목 집중 베팅보다, 검증된 상위 후보를 일정 규칙으로 반복 편입/교체하는 방식이 더 적합하다.
- 월 2%는 개별 종목 대박보다 `작은 우위의 반복`으로 접근해야 한다.
- 따라서 전략 운영 원칙은 아래와 같이 정리한다.

1. 종목 선정보다 운영 정합성을 우선한다.
2. 수익률 목표보다 MDD와 운영 오류를 먼저 통제한다.
3. 강한 종목을 너무 빨리 자르지 않는다.
4. 실거래 반영 전에는 반드시 paper / backtest / 비용 반영 검증을 거친다.
5. 원금 증액은 성과 검증 이후에만 한다.

### 실무 우선순위

1. KR: `pred_return_30d` 학습 + `AI_MAX_HOLDING_DAYS` 30일 정합 + hard cap 추가
2. KR: `ai_position_state` 복구 취약점 보완
3. US: 현재 운영 로직 그대로의 `gross / net` 백테스트 완료
4. US: paper 30거래일 이상 누적 후 buy/sell lifecycle 정합성 검증
5. KR/US 공통: 개인 ETF형 포지션 운영 규칙 확정
   - 종목 수
   - 종목당 비중
   - 교체 주기
   - 손실 제한
   - 현금 비중

### 최종 방향

- KR은 `좋은 종목을 더 오래 보유하도록` 바꾸는 것이 핵심이다.
- US는 `현재 전략이 실제로 돈을 버는지`를 먼저 증명하는 것이 핵심이다.
- 두 시스템 모두 검증이 끝난 뒤에야 비중 확대와 월 2% 재평가가 가능하다.
- 현 단계에서는 `필승전략 추구`보다 `검증된 복리 운영 시스템 구축`이 더 현실적이고 중요하다.

1. 유니버스 메타데이터
   - 현재 최신 `ml_v1` 응답은 `universe_label=UNKNOWN` 상태
   - 화면 표시는 되지만 `NASDAQ100`, `SP500` 등 범위 설명 정합성은 아직 미흡

2. 문서 이력 정합성
   - 본 문서 상단/중간의 `US-C`, `US-E`, `US-B` 진행 상황은 대체로 맞지만,
   - 하단 진행 현황에는 `smoke test 미실행`처럼 이후 결과와 충돌하는 표현이 남아 있었음
   - 아래 `진행 현황 재점검`에서 현재 기준으로 다시 정리함
