## 2. 기준일 원칙

- 운영 파이프라인 기준일은 `close 배치 시각(기본 16:00 KST)` 전후로 다르게 잡습니다.
- `16:00 이전` 실행은 직전 완료 거래일 기준입니다.
- `16:00 이후` close 배치는 당일 거래일이 확인되면 당일 기준으로 산출합니다.
- 휴장일이나 주말에는 가장 최근 거래일 기준으로 유지됩니다.
- 따라서 같은 날 오전 실행 결과가 전일 기준이면 정상이고, 16시 이후 close 배치는 당일 기준으로 올라와야 정상입니다.

### Docker 스케줄러 운영 원칙

- 메인 scheduler는 매일 `16:00`에 실행됩니다.
- `16:00` 배치는 당일 마감 기준 정식 배치입니다.
- scheduler-recovery 컨테이너는 이름은 그대로지만 현재는 `12:00 장중 refresh` 역할로 사용합니다.
- `12:00` 배치는 오전장 흐름을 반영해 오후장 대응 판단을 갱신하는 용도입니다.
- 따라서 현재 자동운영은 `12:00 장중 refresh + 16:00 마감 배치`의 2회 구조입니다.
- 운영 해석 시 `12:00 결과`와 `16:00 결과`는 같은 성격으로 보지 말고, 장중 기준과 마감 기준으로 구분해서 읽어야 합니다.
- Render 실운영에서는 위 시각을 GitHub Actions cron으로 실행합니다.
- GitHub Actions 실행 결과도 동일한 `auto_ops_scheduler_status`, `auto_ops_recovery_scheduler_status` payload를 갱신합니다.

## 7. confidence 기반 비중 규칙

- confidence_score는 표시용 숫자만이 아니라 실행 비중 판단에도 사용합니다.
- 추천 우선순위는 final_score로 보되, 실제 진입 강도는 confidence 구간으로 한 번 더 나눕니다.

### confidence 4구간

- <55: 진입 금지
- 55~70: 소액
- 70~85: 표준
- 85+: 확대 가능

### 실행 원칙

- <55
  - 신규 진입 금지
  - 기존 보유도 축소/청산 우선 검토
- 55~70
  - 신규 진입은 가능하더라도 소액만 허용
  - 목표 비중 계산 시 가중치 축소
  - 종목당 최대 비중도 기본 cap의 50% 수준으로 제한
- 70~85
  - 기본 표준 비중 사용
  - 기존 max position cap 그대로 사용
- 85+
  - 상위 후보 내에서 비중 확대 우선순위를 부여
  - 목표 비중 계산 시 가중치 소폭 확대
  - 종목당 최대 비중도 기본 cap 대비 15% 확대 가능

### quality_risk_guard shadow

- 최신 shadow 비교 파일: [walkforward_weight_variant_analysis.md](/d:/ai/Lee_trader/outputs/walkforward_weight_variant_analysis.md)
- baseline production 점수는 60일 기준 top20 < top50 ordering이 깨져 있습니다.
- 단순 가중치 재조정만으로는 ordering이 복원되지 않았습니다.
- quality_risk_guard shadow는 qual_score가 매우 낮거나 risk_penalty가 높은 종목에 추가 soft penalty를 적용했습니다.
- 최신 비교에서는 top20 > top50 > universe ordering을 회복했습니다.
- 아직 production 승격 전이며, ranking pipeline sidecar 지표로 관찰 중입니다.

### quality_risk_guard 승격 기준

현재 결론
- quality_risk_guard는 아직 production 승격 보류 상태입니다.
- 이유는 최신 one-shot walk-forward 개선은 확인됐지만, 반복성과 실운영 영향이 아직 충분히 쌓이지 않았기 때문입니다.

즉시 승격 금지 조건
- 최근 검증이 1개 matured run 수준이면 승격하지 않습니다.
- shadow가 ordering_ok = YES여도 top20 turnover가 과도하면 승격하지 않습니다.
- shadow 상위 개선 종목이 며칠 연속으로 완전히 바뀌면 승격하지 않습니다.
- penalty가 특정 섹터/테마에만 몰리면 점수 개선이 아니라 편향 가능성으로 보고 승격하지 않습니다.

승격 허용 조건
- 최근 3회 이상의 matured walk-forward 비교에서 top20 > top50 > universe ordering이 유지됩니다.
- 같은 비교 구간에서 shadow의 top20_avg_return이 baseline보다 낮아지지 않습니다.
- 같은 비교 구간에서 shadow의 top20_avg_mdd가 baseline보다 악화되지 않습니다.
- 최근 5영업일 shadow 일일 리포트 기준 상위 개선 후보가 완전 랜덤이 아니라 일부 반복 패턴을 보입니다.
- top20 신규 진입/이탈 종목 수가 baseline 대비 과도하지 않습니다.
  - 운영 기준: 20개 중 6개 이하 변화면 허용, 7개 이상이면 보류 검토
- shadow penalty 적용 종목의 공통 패턴이 설명 가능합니다.
  - 운영 기준: 저품질(qual 낮음) 또는 고위험(risk_penalty 높음) 축으로 일관되게 설명돼야 합니다.

현재 shadow 기준 해석
- 최신 비교에서는 quality_risk_guard가 top20 40.75%, top50 36.24%, universe 27.75%로 ordering을 회복했습니다.
- 동시에 top20 low qual 종목 수가 7 -> 2, top20 high risk 종목 수가 7 -> 4로 줄었습니다.
- 반면 아직 latest_matured_date = 2025-12-09 한 번만으로 본 결과라, 바로 production 점수 교체 근거로 쓰기에는 이릅니다.

승격 후 모니터링 조건
- production 승격 후에도 최소 10영업일은 baseline shadow 비교를 병행합니다.
- 승격 후 ordering 붕괴, top20 turnover 급증, 특정 섹터 편향 중 하나라도 다시 나타나면 즉시 sidecar 모드로 되돌립니다.
- 운영 화면과 상세 화면에서는 승격 전과 동일하게 why penalized 해석이 유지돼야 합니다.

## 10. live score 단일화 원칙

- 현재 production 설정에서는 theme overlay.enabled=false, theme overlay.mode=off입니다.
- 따라서 현재 실운영 점수는 final_score 하나로 고정합니다.
- final_score_v3는 연구/비교용 컬럼으로만 유지합니다.
- 운영 해석용 표준 컬럼은 최종적으로 live_score, live_rank, live_score_source입니다.

### 구현 원칙

- final_score, final_score_v3는 계산 결과로 보관합니다.
- 실제 운영 해석은 live_score 하나만 봅니다.
- 신규 기능은 final_score를 직접 읽지 말고 live_score를 읽도록 맞춥니다.
- dominant_theme는 설명축과 포트폴리오 집중도 제약 확인용으로만 유지합니다.
- theme 자체를 직접 가산점처럼 해석하지 않습니다.

### 전환 전 필수 확인

- ranking_builder.py 내부 정렬 기준과 DB/API 정렬 기준이 같은지 확인
- ranking_history, prediction_history, /api/ranking, /api/top20가 같은 시점과 기준을 따르는지 확인
- 설명 문구가 같은 시점과 기준을 쓰는지 확인
- final_score와 final_score_v3 차이 리포트를 보고 Top20 교체폭이 과도하지 않은지 확인

### theme 최종 역할

- 최종 결론: theme는 직접 점수축이 아니라 설명축/상황축입니다.
- production ranking은 ret / prob / tech / qual / risk 축으로 유지합니다.
- theme는 아래 용도로만 남깁니다.
  - dominant_theme 설명
  - 포트폴리오 theme cap 확인
  - shadow / overlay 연구 리포트 비교
- 추후 theme를 다시 점수축으로 올리려면 별도 acceptance와 반복 walk-forward 근거를 새로 쌓아야 합니다.
