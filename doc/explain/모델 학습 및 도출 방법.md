## 1. 사용 모델 개요 — LightGBM

### 1-1. LightGBM이란

LightGBM(Light Gradient Boosting Machine)은 Microsoft가 개발한 **그래디언트 부스팅 트리(Gradient Boosting Decision Tree)** 계열의 머신러닝 모델입니다.

**그래디언트 부스팅의 핵심 아이디어**:

```
약한 모델(얕은 결정 트리)을 순서대로 여러 개 쌓아서,
앞 모델이 틀린 부분을 다음 모델이 보정하는 방식으로 학습합니다.

모델 1 → 잔차(오차) 계산 → 모델 2가 잔차를 학습
→ 새 잔차 계산 → 모델 3이 학습 → ... → 400개 반복
```

예를 들어 "60일 후 수익률 예측":
- 모델 1이 전체 평균(5%)으로 예측
- 종목 A의 실제가 15%인데 5%로 예측 → 오차 10%
- 모델 2가 "이런 피처 조합이면 +10% 보정" 학습
- 이 과정을 400회 반복하면 점점 정밀해짐

### 1-2. 왜 LightGBM인가

| 특징 | 의미 |
|---|---|
| 트리 기반 | 피처 간 비선형 관계를 자동으로 포착 |
| Leaf-wise 성장 | 예측 오류가 큰 구간을 우선 분할 → 정확도 높음 |
| 빠른 학습 속도 | 매일 배치에서 전 종목 재학습이 가능한 속도 |
| 결측치 내부 처리 | NaN 피처가 있어도 별도 전처리 없이 학습 가능 |
| Feature Importance | 어떤 피처가 예측에 기여했는지 확인 가능 |

### 1-3. 두 가지 역할

Lee Trader에서 LightGBM은 두 가지 용도로 사용됩니다.

| 역할 | 모델 종류 | 예측 대상 |
|---|---|---|
| **회귀 (Regressor)** | `LGBMRegressor` | 수치값 예측 (수익률, MDD) |
| **분류 (Classifier)** | `LGBMClassifier` | 확률 예측 (Top20 진입 확률) |

## 3. Step 1 — 정답 레이블 생성 (`label_builder.py`)

### 3-1. 핵심 개념: Point-in-Time 레이블

레이블은 **t일 시점에서 h일 후 실제로 어떤 일이 일어났는가**를 기록합니다.  
모델은 이 과거 사례들을 학습해서 미래를 예측합니다.

```
t일          t+60일
 │              │
 ├─ 피처(X) ───►│
 │              │
 └─ 레이블(y) = close[t+60] 기반 계산값
```

### 3-2. 수익률 레이블 (`target_log_60d`)

```python
# 단순 수익률
target_60d = close[t+60] / close[t] - 1

# 로그 수익률 (모델 학습에 사용)
target_log_60d = log(close[t+60] / close[t])
```

로그 수익률을 쓰는 이유: 수익률의 분포를 더 정규분포에 가깝게 만들어  
회귀 모델 학습이 안정화됩니다.

**예시**:
- 오늘 종가 10,000원, 60일 후 종가 12,000원
- `target_60d = 0.20 (20%)`
- `target_log_60d = log(1.20) = 0.182`

### 3-3. MDD 레이블 (`target_mdd_60d`)

MDD(Maximum DrawDown) = 보유 기간 중 고점 대비 최대 낙폭

```python
window = close[t : t+60]           # t일부터 60일간 종가
run_max = cumulative_max(window)   # 매일 갱신되는 구간 내 최고가
drawdown = window / run_max - 1    # 각 시점의 고점 대비 손실률
target_mdd_60d = min(drawdown)     # 60일 중 가장 큰 낙폭 (음수값)
```

**예시**:
- 10,000원에 매수 후 60일 동안 최고 15,000원 달성
- 이후 12,000원으로 마감
- `MDD = 12,000/15,000 - 1 = -0.20` → 고점 대비 20% 하락이 최대 손실

### 3-4. Top20 레이블 (`target_60d_top20`)

같은 날 유니버스 내 종목들 중 60일 수익률이 **상위 20%**에 들면 1, 아니면 0

```python
# 날짜별로 80th percentile 계산 후 이진 분류
target_60d_top20 = groupby("date")[target_60d]
                   .transform(lambda s: (s >= s.quantile(0.8)).astype(int))
```

**중요**: 날짜별 상대 순위 기준이므로 미래 데이터 누출(leakage) 없음.

## 4. Step 2 — 모델 학습 (`model_train.py`)

### 4-1. 학습 데이터 구성

```
features.csv  ──┐
                ├── inner join on (date, code) ──► 학습 데이터
labels.csv    ──┘
```

- **X (입력 피처)**: 80개+ 수치형 컬럼 (RSI, 이동평균, 거래량, 수급, 재무점수 등)
- **y (정답 레이블)**: 타겟별로 별도 모델 학습

### 4-2. 학습하는 타겟 목록

| 타겟 컬럼 | 모델 유형 | 생성하는 예측값 |
|---|---|---|
| `target_log_60d` | 회귀 | `pred_return_60d` |
| `target_mdd_60d` | 회귀 | `pred_mdd_60d` |
| `target_log_90d` | 회귀 | `pred_return_90d` |
| `target_mdd_90d` | 회귀 | `pred_mdd_90d` |
| `target_60d_top20` | 분류 | `prob_top20_60d` |

> `target_90d_top20`은 2026-05-18부터 학습에서 제외.  
> `final_score.py`에서 점수에 반영되지 않으므로 학습 비용 낭비였음.

### 4-3. 시계열 교차검증 (TimeSeriesSplit CV)

일반적인 K-Fold CV는 미래 데이터로 과거를 예측하는 상황이 발생합니다.  
금융 시계열에서는 **미래 데이터가 학습에 쓰이면 안 됩니다(leakage)**.

```
일반 K-Fold (잘못된 방식):
  Fold 1: [1, 2, 4, 5월]로 학습 → [3월]로 검증  ← 미래로 과거 예측 = leakage

TimeSeriesSplit (올바른 방식):
  Fold 1: [1~3월]로 학습 → [4월]로 검증
  Fold 2: [1~4월]로 학습 → [5월]로 검증
  Fold 3: [1~5월]로 학습 → [6월]로 검증
```

`N_SPLITS = 3`으로 3개의 fold를 사용합니다.  
각 fold에서 RMSE(회귀), AUC(분류)를 로그로 출력하여 과적합 여부를 모니터링합니다.

### 4-4. 회귀 모델 파라미터

```python
LGBMRegressor(
    n_estimators=400,      # 트리 400개 순서대로 학습
    learning_rate=0.03,    # 각 트리의 기여도 (낮을수록 과적합 방지)
    max_depth=-1,          # 트리 깊이 제한 없음
    num_leaves=63,         # 리프 노드 최대 수 (복잡도 조절)
    subsample=0.8,         # 매 트리마다 데이터 80%만 랜덤 샘플링
    colsample_bytree=0.8,  # 매 트리마다 피처 80%만 랜덤 사용
    objective="regression",
)
```

### 4-5. 분류 모델 파라미터

```python
LGBMClassifier(
    n_estimators=400,
    learning_rate=0.05,    # 분류는 회귀보다 약간 높은 학습률
    num_leaves=31,         # 분류는 더 단순한 트리 구조
    subsample=0.8,
    colsample_bytree=0.8,
    objective="binary",    # 이진 분류 (0 또는 1)
)
```

### 4-6. 출력: model.pkl


## 5. Step 3 — 예측값 도출 (`model_predict.py`)

### 5-1. 입력: 오늘 기준 최신 피처

`features.csv`에서 종목별 **가장 최신 날짜 행만** 추출합니다.  
(과거 전체가 아닌 오늘 기준 스냅샷)

```
features.csv (전체 이력)
    → 종목별 최신 행 1개씩
    → 기준일이 다른 stale 종목은 제외
```

### 5-2. 예측값 계산

**수익률 예측**:

```python
# 회귀 모델 → 로그수익률 예측
log_pred = model["target_log_60d"].predict(X)

# 로그수익률 → 일반 수익률 역변환
pred_return_60d = exp(clip(log_pred, -5.0, 5.0)) - 1.0
```

`clip(-5, 5)` 처리 이유: 극단적 이상값이 exp() 변환 시 overflow가 발생하는 것을 방지

**MDD 예측**:

```python
# 회귀 모델 → MDD 수치 직접 예측 (변환 없음)
pred_mdd_60d = model["target_mdd_60d"].predict(X)
# 결과: 음수값 (예: -0.12 = 최대 12% 낙폭 예상)
```

**Top20 확률 예측**:

```python
# 분류 모델 → 클래스별 확률 반환 ([:, 1] = 양성 클래스 확률)
prob_top20_60d = model["target_60d_top20"].predict_proba(X)[:, 1]
# 결과: 0.0~1.0 사이 확률 (예: 0.73 = 73% 확률로 상위 20% 진입)
```

### 5-3. 출력: predictions.csv

| 컬럼 | 의미 | 범위 |
|---|---|---|
| `pred_return_60d` | 60일 후 예상 수익률 | -1.0 ~ 수 (소수) |
| `pred_return_90d` | 90일 후 예상 수익률 | -1.0 ~ 수 (소수) |
| `pred_mdd_60d` | 60일 내 예상 최대 낙폭 | -1.0 ~ 0.0 (음수) |
| `pred_mdd_90d` | 90일 내 예상 최대 낙폭 | -1.0 ~ 0.0 (음수) |
| `prob_top20_60d` | 60일 후 상위 20% 확률 | 0.0 ~ 1.0 |
| `prob_top20_90d` | (2026-05-18부터 NULL) | — |

## 6. Step 4 — 점수 공식에 투입 (`final_score.py`)

예측값은 바로 순위에 쓰이지 않고 **날짜 내 상대 순위(백분위)**로 변환됩니다.

```python
# pred_return_60d 절대값이 아닌 같은 날 종목 중 몇 등인지
ret_rank_60 = percentile_rank_by_date(pred_return_60d)  # 0.0~1.0

# ret_score: 60d 70%, 90d 30% 가중합 (0~100점)
ret_score = 100 * (0.7 * ret_rank_60 + 0.3 * ret_rank_90)

# prob_score: prob_top20_60d 날짜 내 상대 순위
prob_score = percentile_rank_by_date(prob_top20_60d) * 100

# risk_penalty: MDD 60d 60%, 90d 40% 혼합 → 낙폭이 클수록 페널티 큼
pred_mdd_mix = 0.6 * abs(pred_mdd_60d) + 0.4 * abs(pred_mdd_90d)
risk_penalty = f(pred_mdd_mix)  # 비선형 증가 (0~18점)
```

## 7. 모델의 가정과 한계

### 7-1. 기본 가정

모든 예측은 **"과거 패턴이 미래에도 반복된다"**는 가정 위에 세워집니다.

- 과거에 RSI가 낮고 외국인이 매수한 종목이 60일 후 오른 패턴이 있었다면
- 지금 같은 피처 조합의 종목도 비슷하게 오를 것으로 예측

### 7-2. 한계

| 한계 | 내용 |
|---|---|
| 레짐 전환 | 시장 구조가 급변하면 과거 패턴이 무력화됨 (예: 코로나, 금리 급등) |
| MDD 경로 의존성 | MDD는 언제 고점/저점이 형성되는지에 달려있어 예측이 어려움 |
| Calibration | `prob_top20_60d = 0.7`이 실제로 70% 확률인지 검증 필요 |
| 단기 노이즈 | 60일 이상 중기 예측이므로 단기(5~20일) 움직임에는 대응 못함 |

### 7-3. 보완 장치

| 보완 | 방법 |
|---|---|
| Walkforward 검증 | 실거래 수익률과 예측 수익률을 주기적으로 비교 |
| BUY 게이트 | 모델 신뢰도가 기준 미달이면 자동매매 차단 |
| 레짐별 가중치 | 시장 레짐에 따라 예측값 활용 비중 자동 조정 |
| 매일 재학습 | 18:10 배치에서 최신 데이터로 모델을 매일 업데이트 |
