# 2026-06-06 KR AI 자동매매 운영 베이스라인 동결안

> 목적: 안정화 단계에서 불필요한 소스/전략 변경을 줄이고, 2026-08~09 재검토 전까지 비교 가능한 운영 기준을 보존한다.

## 1. 결론

2026-06-06 기준 KR AI 자동매매는 **PILOT 제한 실운용 베이스라인**으로 동결한다.

지금의 핵심 과제는 새 알파를 찾는 것이 아니라, 현재 베이스라인이 실제 계좌에서 백테스트와 얼마나 동형적으로 작동하는지 관찰하는 것이다. 따라서 모델, 점수 공식, 유니버스, 주문 정책을 쉽게 바꾸지 않는다.

운영 판단:

- 소스 변경은 버그 수정, 안전장치, 관측/문서화에 한정한다.
- 성과 개선 목적의 점수/모델/피처 변경은 2026-08~09 이후 운영 데이터 누적 후 검토한다.
- 실계좌 비중 확대, 신규 유니버스 확대, 중형주 단일종목 모델 추가는 금지한다.
- 현재 시스템은 Top5 집중 실계좌 운용이 아니라, **Top20 후보군 안에서 최대 10종목까지 분산 보유하는 PILOT 제한 실운용**으로 해석한다.

## 2. 동결 기준

| 영역 | 동결값 | 근거 |
|---|---:|---|
| 운영 모듈 | KR AI 자동매매 단독 | `CLAUDE.md` |
| 운영 상태 | `PILOT` | `serving/buy_gate_status.json` |
| KPI 상태 | `ALERT` | `data/score_kpi_monitor.json` |
| 실계좌 모드 | LIVE, 소액 PILOT | `.env`, `performance_summary.json` |
| 점수 공식 | `ranking_builder_v9_flow` | `config/production_v1.yaml`, `score_kpi_monitor.metadata` |
| 후보 선정 | `buy_candidate_builder_v1` | `config/production_v1.yaml` |
| Gate | `operational_buy_gate_v1` | `config/production_v1.yaml` |
| Confidence | `confidence_four_axis_v1` | `config/production_v1.yaml` |
| 운영 유니버스 | KOSPI/KOSDAQ top-100 중심, 약 204종목 | `performance_summary`, `ranking_final` |
| 후보 검토 범위 | Top20 | `execution_policy.candidate_universe_top_n=20` |
| 실계좌 보유 상한 | 10종목 | `execution_policy.max_holdings=10` |
| 현금 최소 | 5% | `execution_policy.cash_minimum=0.05` |
| 포지션 상한 | 기본 20%, PILOT 신규 10% | `execution_policy.max_position_weight`, `pilot_limited_position_cap` |
| 신규 매수 | PILOT 제한 진입 | `pilot_limited_auto_buy_enabled=true` |
| stale BUY 차단 | ON | `AUTO_TRADE_BLOCK_BUY_ON_STALE_SIGNAL=1` |

주의: `serving/model_portfolio.json`은 Top5 모델 포트폴리오 preview다. 실계좌 집행 상한은 `execution_policy.max_holdings=10`이므로, 현재 실운용은 Top5 집중이 아니라 Top20 후보군 기반 Top10 분산 운용에 가깝다.

## 3. 현재 운영 리스크 기준

운영 실제값은 `.env` 기준으로 해석한다.

| 항목 | 현재 운영값 | 의미 |
|---|---:|---|
| Stop loss | 7% 손실 | `AI_POSITION_STOP_LOSS_PCT=0.07` |
| Trailing stop | 고점 대비 10% 하락 | `AI_TRAILING_STOP_PCT=0.10` |
| Trailing 발동 최소수익 | 8% | `AI_TRAILING_STOP_MIN_PROFIT=0.08` |
| Soft max holding | 30일 | `AI_MAX_HOLDING_DAYS=30` |
| Hard cap | 45일 | `AI_MAX_HOLDING_DAYS_HARD_CAP=45` |
| 조기 교체 보호 | 10영업일 | `min_hold_days_before_replace=10` |
| 최대 교체 | 사이클당 1개 | `max_replacements_per_cycle=1` |
| 재진입 쿨다운 | 10일 | `reentry_cooldown_days=10` |

코드 기본값이나 `.env.example` 값과 다르게 보일 수 있으므로, 운영 판단에서는 `.env` 실제값을 우선한다.

## 4. 2026-08~09 전까지 변경 금지

아래 변경은 베이스라인을 흐리므로 금지한다.

- `ranking_builder.py` 점수 공식 변경
- 신규 피처 추가 또는 피처 가중치 변경
- 모델 구조 변경, 재학습 방식 변경, 하이퍼파라미터 튜닝
- 운영 유니버스 확대
- 중형주 단일종목 모델 라이브화
- Gate 승격 조건 완화
- `max_holdings`, 포지션 상한, PILOT 노출 상한 완화
- 손절/trailing/보유기간 정책 완화
- 실계좌 자본 비중 확대

예외는 명확한 버그 수정, 주문 사고 방지, stale 데이터 차단, 상태 동기화, 모니터링/문서화 개선이다.

## 5. 허용되는 개선

베이스라인을 바꾸지 않는 개선만 허용한다.

| 허용 작업 | 설명 |
|---|---|
| 안전장치 보강 | stale 신호 차단, 중복 실행 방지, kill switch, 동기화 검증 |
| 상태 정합성 | `ai_position_state`, 잔고, 체결, 주문 preview 간 불일치 해소 |
| 관측성 개선 | 로그, 리포트, 대시보드 표시 개선 |
| 문서 정리 | 운영 기준, 변경 금지 항목, 점검 체크리스트 정리 |
| 테스트 추가 | 기존 동작을 고정하는 회귀 테스트 |
| 병목 분리 | 핵심 주문/랭킹 로직을 바꾸지 않는 후처리 분리 |

## 6. Top5 vs Top10 해석

현재 운영 해석은 다음과 같이 고정한다.

`model_portfolio`의 Top5는 모델이 보는 집중 preview다. 하지만 실계좌 집행은 `execution_policy.max_holdings=10`, `candidate_universe_top_n=20`, `max_hold_rank=20`을 기준으로 한다.

따라서 2026-06 PILOT에서는:

- Top5는 참고 포트폴리오다.
- Top20은 후보 검토 범위다.
- 실계좌는 최대 10종목까지 분산 보유한다.
- 신규 진입은 Gate가 `PILOT`인 한 제한 노출로만 허용한다.

이 해석은 코드 변경 없이 운영 문서 기준으로만 고정한다.

## 7. 다음 관찰 항목

다음 4가지만 관찰한다.

1. `score_kpi_monitor.overall_status`가 `ALERT`에서 `WATCH/GOOD`로 개선되는지
2. `buy_gate_status.overall_status`가 `PILOT`에서 자연스럽게 승격되는지
3. BUY intent의 실거래 성과가 음수 편향에서 벗어나는지
4. 백테스트/forward/paper/live 간 수익률과 drawdown의 괴리가 줄어드는지

관찰 결과가 충분히 쌓이기 전까지는 새 가설을 운영에 반영하지 않는다.

## 8. 변경 절차

운영 베이스라인을 바꾸려면 아래 절차를 따른다.

1. 변경 사유를 운영 데이터로 설명한다.
2. 변경 전 현재 베이스라인 산출물을 백업한다.
3. shadow 또는 paper에서 먼저 비교한다.
4. 변경 로그에 왜, 무엇을, 어떻게 바꿨는지 기록한다.
5. 실계좌에는 단계적으로 적용한다.
6. 효과가 없거나 베이스라인 비교가 흐려지면 롤백한다.

손실 직후, 일별 변동 대응, 단기 수익률 개선 욕심에 따른 변경은 금지한다.
