# US 운영 규칙 문장화 초안

*작성: 2026-05-19 | 목적: 현재 US 자동매매 전략을 문장으로 고정해 백테스트/실운영 기준선을 맞추기 위한 초안*

> 상태 메모: 2026-05-22 기준 현재 운영 원칙상 US는 `paper-only` 유지다.  
> 따라서 이 문서는 실전 자동매매 규칙이 아니라, **paper / backtest 해석 기준선 문서**로 읽어야 한다.

---

## 1. 문서 목적

이 문서는 현재 US 자동매매 전략을 `코드 기준의 운영 규칙`으로 문장화한 초안입니다.

이 문서가 필요한 이유는 단순합니다.

- 백테스트가 현재 운영 전략과 같아야 함
- paper 운영 결과를 해석할 때 기준이 있어야 함
- 규칙 변경 시 무엇이 바뀌었는지 비교할 수 있어야 함

즉 이 문서는 `US 자동매매가 지금 어떤 전략으로 움직이는가`를 설명하는 기준 문서입니다.

---

## 2. 현재 상태 요약

현재 확인된 운영 의도는 아래와 같습니다.

- `US_BUY_AUTOMATION_MODE=PAPER`
- `US_SELL_AUTOMATION_MODE=PAPER`
- `US_TRADE_ORCHESTRATION_MODE=PAPER`
- `US_PAPER_TRADING_ENABLED=1`
- `US_PAPER_REAL_ORDER_BLOCKED=1`
- `US_PAPER_INITIAL_CASH=100000`

즉 현재 US는 `실계좌가 아니라 paper 자동매매` 기준으로 설계되어 있습니다.

다만 주의할 점이 있습니다.

- 일부 Python config 로더는 `.env`를 직접 읽지 않으면 기본값으로 보일 수 있음
- 따라서 백테스트 기준 문서에는 `운영 의도(env)`와 `코드 기본값`을 구분해서 적는 것이 안전함

---

## 3. 전략 한 줄 정의

현재 US 전략은 다음으로 요약할 수 있습니다.

`NASDAQ100 기반 US 랭킹(rule_v1) 상위 후보 중 BUY 이상 종목을 선별하고, 가격·품질·상대강도·변동성·cooldown·포지션 충돌 규칙을 통과한 종목만 paper 계좌로 매수하며, 보유 후에는 손절·트레일링·보유기간·랭크/점수 저하·벤치마크 언더퍼폼 규칙으로 청산하는 paper 자동매매 전략`

## 4. 진입 전략

### 4-1. 후보 universe

후보의 원천은 `recommend.us_stock_rank_daily` 입니다.  
랭킹 source 기본값은 `rule_v1` 입니다.

관련 코드:

- [python/us/buy_automation/config.py](/d:/ai/lee_trader/python/us/buy_automation/config.py)
- [python/us/buy_automation/candidate_loader.py](/d:/ai/lee_trader/python/us/buy_automation/candidate_loader.py)

### 4-2. 후보 추출 방식

기본 buy 후보는 다음 조건으로 읽힙니다.

- 최신 `trade_date`
- `source = rule_v1`
- `top_n` 이내 종목

코드 기본값:

- `top_n = 5`
- `min_grade = BUY`
- `min_score = 70`
- `min_prob = 0`

즉 기본 해석은 아래와 같습니다.

- 상위 5개 우선 검토
- 등급이 `BUY` 이상이어야 함
- 총점이 70점 이상이어야 함
- 확률 점수는 기본적으로 필수 아님

## 5. 매수 차단 규칙

매수는 후보에 올랐다고 바로 실행되지 않습니다. 아래 risk guard를 모두 통과해야 합니다.

관련 코드:

- [python/us/buy_automation/risk_guard.py](/d:/ai/lee_trader/python/us/buy_automation/risk_guard.py)
- [python/us/trade_orchestration/conflict_guard.py](/d:/ai/lee_trader/python/us/trade_orchestration/conflict_guard.py)

### 5-1. 가격 범위

- 가격 데이터가 있어야 함
- 기준 가격이 `min_price ~ max_price` 범위 안이어야 함

기본값:

- 최소가 `5 USD`
- 최대가 `500 USD`

### 5-2. 점수 기준

- `score >= 70`

### 5-3. 등급 기준

- `BUY` 또는 `STRONG_BUY`

### 5-4. 재무 데이터

- 재무 데이터가 있어야 함
- `financial_quality_score`가 있어야 함

즉 재무 스냅샷이 비면 차단됩니다.

### 5-5. 벤치마크 상대강도

- SPY/QQQ 상대강도 스냅샷이 있어야 함
- 사용 가능한 상대강도 값 중 하나라도 `0 초과`여야 함

즉 시장 대비 약한 종목은 진입 대상에서 제외됩니다.

### 5-6. gap / intraday / volatility

- gap up이 너무 크면 차단
- 장중 상승폭이 너무 크면 차단
- 최근 변동성이 너무 크면 차단

코드 기본값:

- `max_gap_up_pct = 5%`
- `max_intraday_change_pct = 8%`
- `max_volatility_pct = 10%`

### 5-7. cooldown

- 최근 `cooldown_days` 이내에 샀던 종목은 다시 사지 않음

기본값:

- `cooldown_days = 10`

### 5-8. 일일 매수 개수 / 금액 제한

buy automation 기본값:

- `max_daily_symbols = 1`
- `max_daily_amount_usd = 100`
- `max_per_symbol_amount_usd = 100`

이 기본값만 보면 매우 보수적인 테스트 모드 성격이 강합니다.

다만 paper 계좌 설정 파일에는 별도 운영 의도가 보입니다.

`config/us_stock_paper_trading.yaml` 기준:

- `max_positions = 20`
- `max_position_weight = 10%`
- `max_sector_weight = 30%`
- `min_cash_weight = 5%`
- `max_daily_new_buys = 5`

즉 현재 구조는 `buy automation 기본 제약`과 `paper account 전략 제약`이 동시에 존재하며, 실제 어떤 값이 운영 기준인지 백테스트 전에 확정이 필요합니다.

### 5-9. conflict guard

아래 상황이면 buy가 차단됩니다.

- 이미 오픈 포지션이 있음
- 같은 종목에 sell signal이 있음
- review required 상태임
- full exit 후 cooldown 중임
- 같은 날 이미 산 종목임
- 포트폴리오 상태가 불일치함

특히 기본값으로 `sell priority over buy = true` 이므로, 매도 신호가 있으면 신규 매수보다 매도 판단이 우선됩니다.

## 6. 주문 생성 규칙

관련 코드:

- [python/us/buy_automation/paper_order.py](/d:/ai/lee_trader/python/us/buy_automation/paper_order.py)

현재 buy 주문 생성 방식은 아래와 같습니다.

- 기준 가격: candidate loader가 읽은 `reference_price`
- 수량: `floor(allocated_amount_usd / reference_price)`
- 정수 주식만 사용
- 가격이 없으면 주문 수량 0
- 상태는 `ASSUMED_FILLED` 또는 `PRICE_UNAVAILABLE`

즉 현재 buy paper 주문은 `정수 수량`, `기준 가격`, `즉시 가정 체결` 구조입니다.

---

## 7. 체결 가정

paper 전략 설정 파일 기준 실행 철학은 아래와 같습니다.

- `entry_price_basis = NEXT_DAY_CLOSE`
- `exit_price_basis = NEXT_DAY_CLOSE`
- `slippage_bps = 5`
- `commission_per_trade = 0`

즉 현재 설계 의도는 `다음 거래일 종가` 기준의 보수적 체결과 소폭 슬리피지 가정입니다.

다만 buy paper order 단일 함수는 `candidate reference price`를 사용하고 있으므로, 백테스트 시에는 아래를 먼저 고정해야 합니다.

1. 운영 paper에서 실제 reference price가 무엇인지
2. 백테스트는 next-day close를 기준으로 할지
3. 현재 화면상의 paper 체결과 동일하게 재현할지

## 8. 보유 전략

현재 포지션은 paper 스냅샷 기준으로 관리됩니다.

포지션에서 유지되는 핵심 값:

- 평균단가
- 현재가
- 보유수량
- 보유일
- 최고가
- 미실현 손익

즉 매도 판단은 단순 기간 청산이 아니라, 포지션 상태를 기반으로 동작합니다.

## 9. 매도 전략

관련 코드:

- [python/us/sell_automation/config.py](/d:/ai/lee_trader/python/us/sell_automation/config.py)
- [python/us/sell_automation/sell_rule_engine.py](/d:/ai/lee_trader/python/us/sell_automation/sell_decision_engine.py)

현재 sell rule 우선순위는 아래와 같습니다.

1. 데이터 품질 이상
2. 시장 risk-off
3. stop loss
4. trailing stop
5. 최대 보유일
6. rank/score deterioration
7. benchmark underperformance
8. take profit

### 9-1. 손절

기본값:

- `stop_loss_pct = -8%`

즉 미실현 손익률이 `-8% 이하`이면 full sell입니다.

### 9-2. 트레일링 스탑

기본값:

- `trailing_stop_pct = 10%`

즉 진입 후 최고가 대비 하락폭이 `-10% 이하`면 full sell입니다.

### 9-3. 최대 보유일

기본값:

- `max_holding_days = 60`

즉 60일 이상 보유하면 청산합니다.

### 9-4. 랭크 / 점수 악화

기본값:

- `rank_exit_threshold = 30`
- `min_score_hold = 0.50`
- `min_prob_hold = 0.50`

즉 보유 종목이:

- 순위 30위 밖으로 밀리거나
- 점수 비율이 0.5 미만이거나
- 확률이 0.5 미만이면

full sell 대상입니다.

### 9-5. 벤치마크 언더퍼폼

기본값:

- benchmark = `SPY`
- `benchmark_underperform_pct = -5%`

즉 종목 수익률이 벤치마크 대비 5%p 이상 뒤처지면 청산합니다.

### 9-6. 시장 risk-off

기본값:

- `risk_off_exit_enabled = true`
- `market_drawdown_exit_pct = -5%`

즉 벤치마크 최근 구간 성과가 임계치 이하로 나빠지면 보유 포지션을 청산하는 구조입니다.

### 9-7. 익절

기본값:

- `take_profit_pct = 15%`
- `partial_take_profit_enabled = false`

즉 현재는 15% 이상 수익이면 partial이 아니라 full sell 구조입니다.

## 10. 매수/매도 충돌 처리

trade orchestration 기본값 기준 충돌 처리 철학은 아래와 같습니다.

- 보유 종목에는 신규 매수 금지
- sell signal 있는 종목은 buy 금지
- review required 종목은 buy 금지
- full exit 후 10일 cooldown
- sell 우선

즉 현재 전략은 `신규 진입 공격성`보다 `기존 포지션 정리와 충돌 방지`를 더 우선합니다.

## 11. 자금 운용 철학

paper 설정 파일 기준 의도는 아래와 같습니다.

- 초기자금 `100,000 USD`
- 종목당 최대 비중 `10%`
- 섹터 최대 비중 `30%`
- 최소 현금 `5%`
- 동시 포지션 최대 `20개`
- 일일 신규 매수 최대 `5개`

즉 큰 방향은 `분산된 paper 계좌 운영`입니다.

다만 buy automation 기본 설정은 `1종목 / 100달러` 수준이라 훨씬 더 보수적입니다.  
따라서 현재 실운영 기준을 문서상 하나로 통일할 필요가 있습니다.

## 12. 백테스트에 그대로 반영해야 할 규칙

현재 전략 백테스트에는 최소 아래를 그대로 넣어야 합니다.

1. `rule_v1` 랭킹 소스
2. top-N 후보 추출
3. grade / score / financial / benchmark / gap / volatility 차단
4. cooldown 차단
5. conflict guard
6. 정수 수량 계산
7. 다음 거래일 기준 체결 가정
8. stop loss / trailing / 60일 보유 / rank deterioration / benchmark underperformance / take profit 매도

이 중 하나라도 빠지면 `현재 전략 백테스트`가 아니라 `단순화된 유사 전략 테스트`가 됩니다.

## 13. 현재 문서 기준 불확실한 부분

백테스트 전에 아래는 반드시 확정해야 합니다.

### 13-1. buy sizing 기준

- `buy automation 기본값`을 따를지
- `paper_trading.yaml`의 자금 운용 규칙을 따를지

현재 두 계층이 함께 존재합니다.

### 13-2. entry / exit 체결 기준

- 실제 현재 paper 주문이 reference price로 즉시 계산되는지
- 백테스트는 `NEXT_DAY_CLOSE`를 정식 기준으로 둘지

### 13-3. probability 사용 여부

buy에서는 `min_prob=0` 이라 사실상 확률 필수 아님  
sell에서는 `min_prob_hold=0.5` 가 기본값

즉 진입과 유지 기준이 다릅니다. 이것을 의도된 설계로 볼지 정해야 합니다.

## 14. 회의용 결론

현재 US 운영 규칙의 큰 방향은 명확합니다.

- rule 기반 랭킹 진입
- 다중 차단 규칙 통과 후 매수
- 충돌 방지 우선
- 보유 후 리스크/기간/벤치마크 기준 청산
- paper 계좌 기반 자산 추적

다만 백테스트 실행 전 아래 3가지는 최종 확정이 필요합니다.

1. 실제 자금 배분 기준
2. entry/exit 체결 기준
3. env 기준 운영값과 코드 기본값 중 어느 쪽을 정식 전략으로 볼지

한 줄 요약:

`현재 US 전략은 rule 기반 다중 필터 + 보수적 청산 구조이며, 백테스트 전에 sizing과 체결 기준만 명확히 고정하면 실전형 재현 테스트가 가능합니다.`
