## 현재 위치 요약

**코드 구현 완성도는 Phase 8-26 수준까지 도달해 있음.**
단, 아래 두 가지가 빠진 채로 모든 것이 대기 중인 상태:

1. **파이프라인 미활성** — `US_STOCK_ENABLED=0`, 일일 실행 없음
2. **브로커 미연결** — `US_LIVE_BROKER=none`, `live_implemented=False` 하드코딩

실제 병목은 "구현"이 아니라 **paper 운영 데이터 누적과 정책 검증**입니다.

## 실제 남은 과제 (재정의)

### Phase A — 파이프라인 활성화 (즉시)

**목적**: 데이터 수집 및 Shadow 운영 시작

```
# .env 변경
US_STOCK_ENABLED=1
US_BUY_AUTOMATION_ENABLED=1
US_BUY_AUTOMATION_MODE=SHADOW
```

- 일일 파이프라인 정상 실행 확인 (Universe → 가격 → 피처 → 랭킹)
- Shadow 주문 로그 누적 시작
- 데이터 품질 이상 없으면 즉시 착수 가능

---

### Phase B — Paper Trading 60일 운영 (20일 Shadow 후)

**목적**: `live_readiness_evaluator` 통과 조건 충족

```
# .env 변경
US_PAPER_TRADING_ENABLED=1
US_BUY_AUTOMATION_MODE=PAPER
```

통과 기준 (자동 측정됨):

| 기준 | 목표 |
|---|---|
| Shadow 운영 | ≥ 20일 |
| Paper 운영 | ≥ 60일 |
| Paper 주문 건수 | ≥ 20건 |
| Win Rate | ≥ 50% |
| Max Drawdown | ≤ 15% |
| SPY 초과수익 | > 0% |
| Scheduler 성공률 | ≥ 95% |

예상 소요: **약 80일 (2026-08 초)**

---

### Phase C — 브로커 선정 및 API 연결 (Paper 운영과 병행)

**목적**: `live_implemented=True` 전환 준비

현재 코드에 브로커 인터페이스(`us_micro_order_request.py`)는 구조만 있고 실제 API 호출은 미구현.

결정 필요 항목:

| 항목 | 옵션 |
|---|---|
| 브로커 | Interactive Brokers / Alpaca / Tiger Brokers |
| 계좌 종류 | 마진 / 현금 |
| 주문 방식 | REST API / WebSocket |
| 초기 테스트 금액 | 최소 $1,000 권장 |

작업 내용:
- 브로커 API 클라이언트 구현 (`us_micro_order_request.py` 실제 연결)
- Sandbox 환경에서 30일 주문 검증
- `live_implemented=False` → `True` 전환

---

### Phase D — 제한적 실거래 개시 (readiness 통과 + 수동 승인 후)

**목적**: 소액 실거래로 전체 흐름 검증

조건:
- `live_readiness_evaluator` 통과
- 수동 승인 (`require_manual_approval=True` — 자동 전환 불가)
- 초기 1종목, $100~$500 이내

해제 필요 환경변수:
```
US_LIVE_TRADING_ENABLED=1
US_LIVE_BROKER=<선정된 브로커>
```

코드에서: `send_us_micro_order_live.py` —  최종 확인 텍스트 입력 시 실주문 전송

---

### Phase E — ML 모델 랭킹 추가 (선택 과제)

**목적**: rule_v1 단독에서 AI + RULE 병행 구조로 전환 (한국 모듈과 동일 방식)

현재: rule_v1 점수만 사용
목표: LightGBM 기반 `prob_score` 추가 → 가중 합산

선행 조건:
- `validate_us_stock_ml_dataset.py` 통과 (레이블 데이터 충분)
- Paper 60일 이상 운영 데이터 확보

## 주의사항

- Phase A~B는 `AUTO_TRADE_EXECUTE` 등 한국 모듈과 독립적 — 동시 진행 가능
- 브로커 결정 전까지 실거래는 불가능 (코드 인터페이스만 있고 API 미구현)
- `live_implemented=False` 는 안전장치가 아니라 미완성 표시 — 브로커 연결 후 변경
- 수동 승인은 절대 원칙 — 자동 라이브 전환 없음
