# 20260518 US 실계좌연결 작업계획

> 최종 수정: 2026-05-19

## 목적

US 자동매매를 현재 `rule 기반 paper 운영` 상태에서 `실계좌 연결 가능한 live 운영` 상태로 전환한다.

목표 조건:

- `.env` 에 실계좌 관련 값과 브로커 설정을 넣으면 운영 가능해야 한다.
- `종목 후보선정 → 주문 초안 → 사전점검 → 승인 → 주문 제출 → 체결 동기화 → 잔고/현금/손익 반영` 이 끊기지 않아야 한다.
- paper 화면과 live 화면이 동일한 운영 포맷을 최대한 공유해야 한다.
- kill switch, 주문 한도, 승인 체계, 복구 절차가 포함되어야 한다.

## 현재 상태 요약

현재 US 모듈은 다음 수준까지 구현되어 있다.

- rule 기반 종목 후보선정 가능
- paper 주문 생성 가능
- paper 포지션/현금/평가금액 화면 확인 가능
- trade orchestration, dashboard, health check 구조 존재
- live pre-trade check, approval, micro-order 프레임워크 존재

현재 실전 전환을 막는 핵심 문제:

1. US live broker 어댑터에 `KIS(한투)` 가 없다.
2. BUY live 경로는 `LIVE_NOT_IMPLEMENTED` 로 차단되어 있다.
3. SELL live 경로도 `LIVE_NOT_IMPLEMENTED` 상태다.
4. 메인 orchestration 은 real order path 없이 paper 중심으로 설계되어 있다.
5. live order 생성 경로와 current US orchestration 이 자동 연결되어 있지 않다.
6. 체결/잔고/현금 reconciliation 이 KIS US 기준으로 붙어 있지 않다.

## 최종 아키텍처 목표

실계좌 연결 완료 후 목표 흐름:

```
US ranking/rule → 후보 추출
  → risk guard / conflict guard
  → live pre-trade check
  → approval 정책 (자동 통과 or 수동 승인)
  → micro live order 생성
  → KIS US broker 주문 제출
  → 주문 상태 / 체결 동기화
  → holdings / cash / equity / reconciliation 자동 반영
  → dashboard UI (paper 와 동일 포맷)
```

## 단계별 실행 계획

### Phase 1. KIS US 브로커 어댑터 구현 (예상 1~2주)

> 가장 불확실성이 높은 단계. KIS 미국주식 API 스펙이 국내 API와 체계가 다르다.

**필수 확인 사항 (착수 전)**

- KIS 미국주식 거래 신청 및 계좌 활성화 여부
- 해외주식 API App Key / Secret 발급 여부 (국내용과 별도 발급 필요할 수 있음)
- KIS OpenAPI 해외주식 주문 문서 확인:
  - 주문 경로: `TTTT1002U` (미국 매수), `TTTT1006U` (미국 매도)
  - 조회 경로: 체결내역, 잔고, 현금 (해외전용 TR 코드)
  - 주의: Pre-market / After-market 주문 가능 여부

**구현 대상**

- `brokers/us/kis_live_client.py` 신규 구현
  - 주문 제출 (`buy_market`, `buy_limit`, `sell_market`, `sell_limit`)
  - 주문 정정 / 취소
  - 주문 상태 조회
  - 체결 내역 조회
  - 계좌 잔고 / 현금 / 외화 환전 잔액 조회
- `utils/us_live_order_client.py` — KIS 어댑터 추가
- `utils/us_order_status_mapper.py` — KIS 응답코드 → 내부 상태 매핑
- `utils/us_live_account_client.py` — 계좌 정보 KIS 연동
- `.env.example` — KIS US 전용 환경변수 추가

**완료 기준**

- `US_LIVE_BROKER=KIS` 설정 시 adapter 정상 resolve
- sandbox / dry-run 경로에서 실제 API 호출 없이 구조 검증 가능
- 실계좌 환경에서 잔고 조회 1회 성공

**주요 리스크**

- KIS US API 응답 포맷이 국내와 달라 매핑 공수 발생 가능
- 해외주식 계좌 활성화까지 수일 소요될 수 있음
- 환율 처리 (USD 잔고 ↔ 원화 환산) 로직 별도 필요

### Phase 2. BUY / SELL Live 주문 경로 연결 (예상 1주)

> Phase 1 완료 후 착수. BUY와 SELL 동시에 설계하여 일관성 확보.

**BUY live 경로**

- `LIVE_NOT_IMPLEMENTED` 제거 (`buy_automation/decision_engine.py`)
- `allowed candidate → approval → micro order create → send_live` 경로 연결
- 주문 타입 / limit price 계산 규칙 확정 (시장가 vs 지정가 기본값)
- 주문 수량 계산 (USD 금액 기준 → 주수 변환)

**SELL live 경로**

- `LIVE_NOT_IMPLEMENTED` 제거 (`sell_automation/sell_decision_engine.py`)
- SELL signal → approval/auto path 정의
- full sell / partial sell 분기
- 보유 수량 vs 매도 가능 수량 검증
- 중복 매도 방지 로직

**반영 대상**

- `python/us/buy_automation/decision_engine.py`
- `python/us/sell_automation/sell_decision_engine.py`
- `python/us/trade_orchestration/daily_trade_orchestrator.py`
- `utils/us_micro_order_request.py`

**완료 기준**

- live mode 에서 `LIVE_NOT_IMPLEMENTED` 오류 없이 주문 생성 가능
- approval 통과 시 실제 micro order row 생성 및 KIS 전송 가능
- SELL 중복 방지 동작 확인

---

### Phase 3. 체결 / 잔고 / 현금 동기화 (예상 1주)

> Phase 2 주문 경로 완료 후 착수.

**구현 대상**

- broker order id 기준 체결 상태 조회 및 DB 반영
- partial fill / full fill / reject / cancel 각 케이스 처리
- 체결 반영 후 holdings, cash, equity 계산
- live reconciliation report 생성 (broker 잔고 ↔ 내부 잔고 비교)
- USD 잔고 기준 현금 추적 (환율 스냅샷 포함)

**반영 대상**

- `utils/us_micro_order_sync.py`
- `utils/us_micro_reconciliation.py`
- `utils/us_live_account_client.py`
- DB `live.us_stock_micro_order_*`, reconciliation tables

**완료 기준**

- 주문 제출 후 체결 상태가 DB와 UI에 자동 반영
- broker cash / internal cash 차이 검증 가능
- reconciliation report 에 불일치 항목이 있으면 알림 발생

### Phase 4. 승인 / Kill Switch / 안전장치 정비 (예상 3~5일)

> Phase 2~3 과 병행 또는 직후. 실전 전환 직전 필수.

**구현 대상**

- BUY / SELL 승인 정책 확정 및 env 제어 체계 정리
- kill switch 계층 점검:
  - `US_LIVE_TRADING_ENABLED=false` → 모든 실주문 차단
  - `US_MICRO_REAL_ORDER_BLOCKED=true` → micro order 생성 차단
  - `US_LIVE_BUY_ENABLED=false` / `US_LIVE_SELL_ENABLED=false` 개별 제어
- 장 시간 외 주문 차단 규칙 (미국 장 09:30~16:00 ET 기준)
- 주문 한도 검증 (종목당, 전체 포지션 비중)
- 장애 복구 runbook 작성

**반영 대상**

- `utils/us_live_order_safety.py`
- `utils/us_live_order_approval.py`
- `utils/us_live_kill_switch.py`
- `python/us/run_us_live_pre_trade_check.py`

**완료 기준**

- 승인 없이 실주문이 나가지 않도록 정책 강제 가능
- kill switch 전 계층 동작 확인
- 장외시간 주문 시도 시 차단 동작 확인

## 필수 env 항목

Phase 1 완료 후 실전 전환 시 최소 필요:

```env
# 브로커 선택
US_LIVE_BROKER=KIS

# 실주문 활성화 스위치 (기본값: 차단)
US_MICRO_ALLOW_LIVE=true
US_MICRO_REAL_ORDER_BLOCKED=false
US_LIVE_TRADING_ENABLED=true
US_LIVE_ORDER_ENABLED=true
US_LIVE_BUY_ENABLED=true
US_LIVE_SELL_ENABLED=true

# KIS US 전용 자격증명 (국내 계좌와 별도)
KIS_US_APP_KEY=
KIS_US_APP_SECRET=
KIS_US_CANO=
KIS_US_ACNT_PRDT_CD=
KIS_US_BASE_URL=https://openapi.koreainvestment.com:9443

# 실전 전환 전까지 반드시 차단 상태 유지
# US_MICRO_REAL_ORDER_BLOCKED=true  ← 기본값
```
