# RULE 자동매매 로직 진단

작성일: 2026-05-19

## 결론

현재 RULE 자동매매는 아이디어 자체보다 구현 정합성 문제가 더 큽니다.

- 컨셉은 납득 가능하다.
  - 유동성 있는 추세 종목을 고르고
  - 시장이 나쁘면 신규 진입을 줄이고
  - 손절과 일부 축소로 리스크를 관리하려는 구조다.
- 하지만 실제 운용 경로는 일관성이 약하다.
  - 진입 점수와 청산 점수가 다르고
  - 백테스트와 실거래 행동이 다르고
  - 체결을 위해 매수 가격을 불리하게 잡는 구조가 있다.

즉, 지금 상태에서 "수익이 날 만한 구조인가"라는 질문에는
"아이디어는 가능하지만 현재 구현은 납득도가 낮고, 백테스트 수익률을 그대로 믿기 어렵다"가 맞다.

## 현재 전략 컨셉

실제 코드 기준으로 보면 RULE은 아래 구조다.

1. 신호 생성
   - `rule_signal_builder.py`
   - 추세, 유동성, 안정성, 시장 상태, 수급(flow), 섹터 상대 모멘텀을 합쳐 `rule_score_v3`를 만든다.
   - 진입 신호는 기본 추세 조건을 통과하고 과열이 아니어야 하며, `rule_score` 또는 `rule_score_v3` 기준을 넘겨야 한다.

2. 포트폴리오 액션 결정
   - `rule_portfolio_manager.py`
   - 보유 종목은 `hold/reduce/exit`
   - 미보유 종목은 `buy/skip`
   - 최대 보유 수, 현금 비중, 섹터 비중, 쿨다운을 함께 본다.

3. 주문 가격 및 수량 계산
   - `rule_order_preview_builder.py`
   - BUY는 `expected_entry_price` 기준 지정가
   - SELL은 `last_price` 기준 지정가

4. 장전 주문 제출, 장후 체결 동기화
   - `run_rule_before_open_cycle.py`
   - `run_rule_after_open_cycle.py`

## 핵심 문제

### 1. 백테스트와 실거래가 다르다

가장 큰 문제다.

- 실거래 진입은 `rule_score_v3` 정렬을 사용한다.
- 백테스트 포트폴리오는 `rule_score_v2 -> rule_score -> liquidity -> vol_20` 순으로 뽑는다.
- 백테스트는 `D+1 시가 진입 후 20일 고정 보유`다.
- 실거래는 손절, trailing, 점수 하락 청산, 장전 지정가 주문, 장후 체결 확인을 사용한다.

즉 백테스트는 "이 전략이 실제로 어떻게 거래되는지"를 재현하지 못한다.

현재 `outputs/rule_strategy_backtest_report.json`의 수익률은 참고용일 수는 있어도,
실거래 기대수익을 대표한다고 보기 어렵다.

### 2. 진입과 청산 기준 점수가 다르다

- 진입 후보 정렬: `rule_score_v3`
- 진입 신호: `rule_score_v3`
- 보유 종목 청산/축소: `rule_score_v2`

이건 버전 혼재다.

들어올 때 본 점수와 나갈 때 보는 점수가 다르면,
보유 중 판단이 전략 의도와 어긋날 수밖에 없다.

### 3. 매수 주문 가격이 수익 기대를 깎는다

현재 BUY 가격 경로는 아래와 같다.

- `expected_entry_price = 전일 종가 * (1 + 과거 gap 중앙값)`
- 실제 주문 지정가 = `expected_entry_price * (1 + 1~2%)`

즉 원래도 약간 추격 진입인데, 주문 단계에서 다시 1~2%를 더 얹는다.

이 방식은 체결률에는 유리할 수 있지만,
모멘텀 전략의 초과수익을 체결 단계에서 상당 부분 반납할 가능성이 크다.

### 4. 익절보다 손절 중심 구조다

현재 설정 기준:

- `RULE_PROFIT_TARGET_PCT=0.0`
- 익절 목표 비활성
- trailing도 고점 수익이 충분히 나야 작동
- 그마저도 이익 상태에서는 완전 청산보다 `reduce`가 많다

즉 "잘 가면 오래 들고, 애매하면 버티고, 크게 틀리면 손절"에 가깝다.
이 구조는 강한 추세장에서는 괜찮을 수 있지만,
횡보장이나 빠른 순환장에서는 수익 실현 효율이 낮아질 수 있다.

### 5. 보유 메타 누락 시 리스크 관리가 약해진다

실운용에서 이미 확인된 것처럼 아래 값이 누락될 수 있다.

- `entry_date_missing`
- `highest_price_missing`

이 경우:

- 최대 보유일 기반 청산이 약해지고
- trailing stop 품질이 떨어지고
- 사실상 단순 손절 위주로만 동작하게 된다

즉 전략 설명서와 실제 행동이 달라진다.

### 6. 일부 필터는 실질 기여가 작다

최근 리포트 기준으로:

- `trading_value` 임계값을 바꿔도 후보 수와 성과가 거의 동일하다
- `rule_score_v2` 민감도도 특정 구간에서는 결과가 거의 안 바뀐다

이건 필터가 많아 보여도 실제 선택력은 약하다는 뜻이다.
설계가 복잡해진 것 대비 설명력은 낮다.

## 현재 구조가 납득 가능한 부분

아래는 컨셉 차원에서 납득 가능하다.

- 추세 + 유동성 + 안정성 + 시장 상태를 함께 보는 것
- 시장 방어 모드에서 진입을 줄이는 것
- 신규 진입 비중과 섹터 비중, 현금 비중을 제한하는 것
- 장후 계획 수립, 장전 주문, 장후 체결 동기화로 파이프라인을 나눈 것

즉 완전히 잘못 설계된 전략은 아니다.
문제는 "각 단계가 서로 같은 전략을 보고 있지 않다"는 점이다.

## 우선 수정 순서

### 1순위. 백테스트를 실거래 동형으로 맞추기

최우선 과제다.

반영 필요:

- `rule_score_v3` 기준 정렬
- 실제 `buy/hold/reduce/exit` 로직
- 손절, trailing, 보유기간 청산
- 실제 주문 가격 가정
- 장전 지정가 미체결 가능성

이게 맞지 않으면 현재 백테스트 수익률은 의사결정 근거로 쓰기 어렵다.

### 2순위. 진입/보유/청산 점수 체계 통일

둘 중 하나로 정리해야 한다.

- `v3`를 표준으로 삼고 보유/청산도 `v3`로 통일
- 또는 `v2/v3` 역할을 명확히 분리

지금처럼 진입은 `v3`, 청산은 `v2`인 구조는 지속하기 어렵다.

### 3순위. BUY 가격 정책 완화

검토 우선순위:

- `expected_entry_price` 그대로
- 또는 `+1%` 버퍼 축소
- 또는 조건부 버퍼 적용

현재처럼 기본적으로 1~2%를 더 얹는 방식은 기대수익을 잠식할 가능성이 높다.

### 4순위. 포지션 메타 품질 복구

필수 보강:

- `entry_date`
- `highest_price`
- `highest_return_since_entry`

이 값이 안정적으로 채워져야 max-hold와 trailing이 전략 설명대로 동작한다.

"추세 전략 아이디어는 납득 가능하지만, 백테스트/실거래/청산 로직의 불일치가 커서 수익 구조를 신뢰하기 어려운 상태"다.

- 기존 strong 포트폴리오 백테스트: 총수익 `29.46%`, Sharpe `0.62`
- 실거래 유사 strong, 시가 체결 가정: 총수익 `86.19%`, Sharpe `1.01`

- 주문 가격 정책을 넣자 strong 수익률이 `86.19% -> 51.66%`로 크게 낮아졌다.
- 즉 기존 백테스트는 체결 가정을 낙관적으로 본 측면이 있다.
- 반면 relaxed 진입은 지정가/미체결을 넣은 뒤 strong보다 결과가 더 낫게 나왔다.
- 따라서 "entry 완화가 무조건 나쁘다"보다는 "현재 strong 체결 구조가 더 불리할 수 있다"는 쪽으로 해석을 조정해야 한다.

남은 과제:

- 장전 주문 이후 after-open 재호가 경로까지 백테스트 반영
- BUY/SELL limit 정책을 파라미터화해서 민감도 비교
- exit 판단도 `v3` 기준으로 통일한 대안 시나리오 비교

- 즉 1차적으로 더 큰 영향 변수는 `SELL 재호가`보다는 `BUY 지정가 정책`과 `진입 후보 선택 구조`다.
- 실행 안정성 관점에서 재호가는 여전히 필요하지만, 전략 성과의 핵심 드라이버는 아니라는 해석이 가능하다.

## 2026-05-20 추가 메모: 청산 점수 통일과 BUY 버퍼 민감도

### 1. 청산 점수 `mixed` vs `v3`

백테스트에 `exit_score_mode`를 추가해 `mixed`와 `v3`를 비교했다.

결과는 strong / relaxed 모두 동일했다.

해석:

- 현재 최신 신호 집합에서는 `35점` / `45점` 임계값 근처에서 `v2`와 `v3`가 다르게 행동하는 종목이 거의 없다.
- 최신 스냅샷 기준 `35점` 임계값 불일치 종목은 `1개`뿐이었고, `45점 defensive` 불일치는 `0개`였다.
- 따라서 지금 시점에서는 `v2/v3 혼재`가 설계상 문제이긴 하지만, 단기 성과 차이의 직접 원인은 아니었다.

### 2. BUY 지정가 버퍼 민감도

strong 진입 기준으로 BUY 지정가 버퍼를 바꿔 비교했다.

- 버퍼 `0% / 0%`: 총수익 `77.96%`, Sharpe `0.92`, MDD `-23.16%`
- 버퍼 `0.25% / 0.5%`: 총수익 `127.96%`, Sharpe `1.29`, MDD `-17.64%`
- 버퍼 `0.5% / 1.0%`: 총수익 `59.48%`, Sharpe `0.75`, MDD `-28.58%`
- 버퍼 `0.75% / 1.5%`: 총수익 `62.09%`, Sharpe `0.78`, MDD `-22.22%`
- 버퍼 `1.0% / 2.0%`: 총수익 `51.66%`, Sharpe `0.69`, MDD `-24.31%`

해석:

- `0%`보다 `0.25% / 0.5%`가 더 좋게 나온 것은, 약간의 추격 버퍼가 체결률과 가격 품질의 균형점을 만들 수 있음을 시사한다.
- BUY 버퍼를 키울수록 성과가 눈에 띄게 악화됐다.
- 특히 현재 운영값인 `1% / 2%` 버퍼는 백테스트 기준 기대수익을 크게 깎는 편이다.
- 즉 지금 RULE의 수익 구조를 가장 크게 흔드는 변수는 `청산 점수 혼재`보다 `BUY 추격 지정가 정책`이다.
- 1차 후보 운영값은 `0.25% / 0.5%` 또는 `0.5% / 1.0%` 구간으로 보는 것이 합리적이다.
- `2026-05-20` 기준 실제 운영값도 `0.25% / 0.5%`로 조정했다.
