# Documentation Rules

이 문서는 AI 협업과 장기 운영을 위한 문서 작성 규칙입니다.

## Primary Principle

문서는 "현재 기준 진실"을 남겨야 합니다.

즉:

- 지금 실제로 쓰는 흐름
- 지금 실제로 쓰는 환경변수
- 지금 실제로 생성되는 산출물
- 지금 실제로 동작하는 화면/API

를 기준으로 씁니다.

## What Must Be Updated

아래가 바뀌면 문서도 같이 수정합니다.

- 실행 흐름 변경
- 환경변수 추가/삭제/기본값 변경
- output JSON/CSV schema 변경
- scheduler 변경
- order guard 변경
- 계좌 동기화 경로 변경
- 화면/API payload 변경

## Writing Rules

- 상대 날짜보다 절대 날짜를 우선합니다.
  - 예: `2026-05-06`
- `today`, `current`, `latest` 같은 표현은 기준 파일이나 생성 시각과 함께 씁니다.
- 추측과 사실을 섞지 않습니다.
- 사람이 결정한 정책과 코드상 현재 동작을 분리해서 씁니다.
- 민감정보는 문서에 쓰지 않습니다.

## AI Collaboration Rules

- 새 작업을 시작할 때는 관련 모듈 문서를 먼저 읽습니다.
- 코드 수정 후에는 반드시 문서 반영 여부를 확인합니다.
- 문서가 오래된 것 같으면 코드를 기준으로 갱신합니다.
- 문서가 코드보다 우선 진실이 아니라, 코드와 산출물이 우선 진실입니다.

## Recommended Completion Checklist

작업 완료 전 확인:

1. 관련 모듈 문서를 읽었는가
2. 코드 변경이 흐름/환경변수/산출물에 영향을 주는가
3. 영향을 준다면 문서를 수정했는가
4. 실행 또는 산출물 검증을 했는가
5. 최종 요약에 문서 변경 파일을 포함했는가

## Naming Rules

- 모듈 문서 이름은 되도록 고정합니다.
- 새 문서가 필요하면 역할이 드러나는 이름을 씁니다.
  - `RUNTIME_SORTING.md`
  - `OPERATIONS.md`
  - `ENV.md`
  - `CHANGELOG.md`

## Scope Rules

- 모듈 내부 문서는 해당 모듈 책임 범위만 씁니다.
- 여러 모듈에 걸친 내용은 `docs/` 루트 문서로 분리합니다.
- 운영 명령어, 비교 리포트, 릴리즈 노트는 `docs/`에 두는 편이 낫습니다.
