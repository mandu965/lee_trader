# 문의사항

## 1. 수급데이터는 외국인, 기관의 매수/매도인데 시스템에서 어떻게 활용되고 있나요?

**답변**

`flow_daily` 테이블에 외국인·기관 일별 순매수 금액을 수집하고, `feature_builder.py`에서 4개 피처로 가공합니다.

| 피처 | 내용 |
|---|---|
| `flow_foreign_net_5d` | 외국인 순매수 5일 누적 |
| `flow_foreign_net_20d` | 외국인 순매수 20일 누적 |
| `flow_inst_net_5d` | 기관 순매수 5일 누적 |
| `flow_inst_net_20d` | 기관 순매수 20일 누적 |

이 값들을 같은 날짜 전 종목 대비 percentile(0~100)로 환산해 `flow_score`를 만들고, 두 곳에 반영합니다.

- **AI 랭킹 (`final_score`)**: flow_score가 12%(Bull) / 10%(Neutral) / 8%(Defensive) 가중치로 최종 점수에 합산됩니다.
- **RULE 신호 (`rule_score_v3`)**: flow_score가 25% 가중치(외국인 60% + 기관 40%)로 반영됩니다.

데이터가 없는 종목은 50점(중립)으로 처리되어 페널티 없이 통과합니다.

## 2. 메인 페이지에서의 매수·매도 화살표 방향은 당일 순매수 혹은 매수 비율로 따지나요?

**답변**

당일 순매수가 아닙니다. **5일 누적 외국인+기관 순매수를 전체 종목 대비 상대 순위(percentile)로 환산한 `flow_score`** 기준입니다.

```
flow_score >= 70  →  ▲  (전체 종목 상위 30% — 수급 집중)
flow_score <  35  →  ▼  (전체 종목 하위 35% — 수급 이탈)
그 외             →  —  (중립)
```

절대 금액이 아니라 같은 날 전 종목 내 상대적 위치이므로, 전체 시장이 하락하는 날에도 상대적으로 수급이 나은 종목은 ▲가 나올 수 있습니다.

## 3. 지금 상황에서 상세 페이지에 외국인·기관 수급 현황을 보여줄 수 있나요? 지금은 종가 90일 데이터 확인 가능합니다.

**답변**

구현 가능합니다. 필요한 데이터는 이미 모두 존재합니다.

- `daily_ranking` 테이블: `flow_foreign_net_5d`, `flow_inst_net_5d`, `flow_score` 등 컬럼 저장됨 (당일 스냅샷)

상세 페이지에 수급 추이 차트 또는 테이블로 추가할 수 있습니다. 구현 범위 예시:

## 6. 모델 학습에 필요한 데이터 및 방향성, 어떤 식으로 미래 결과를 도출하는지 알려주세요.

**답변**

**입력 피처 (350개 이상)**
```
기술지표:  RSI, MACD, 볼린저밴드, 거래대금, ATR 등
모멘텀:    ret_5d ~ ret_120d, high_52w_ratio (52주 고점 근접도)
퀄리티:    PER, PBR, ROE, 부채비율, 매출성장 등 (DART 기반)
수급:      flow_foreign/inst_net_5d/20d (외국인·기관 누적 순매수)
```

**타겟 변수**
```
D+20 수익률이 KOSPI 대비 일정 기준 초과 → 1 (상승 후보)
그렇지 않으면 → 0
```

**모델 구조**
- LightGBM 이진 분류 → 종목별 "D+20 상승 확률(prob_score)" 예측
- 과거 데이터를 시간 순서로 분할 (train/validation 시간 분할) — 미래 데이터가 학습에 섞이지 않도록 보호

**출력 흐름**
```
prob_score → ret_score, tech_score, qual_score, flow_score와 가중 합산
→ final_score → 순위 → trade intent (BUY 후보 선정)
```

예측의 의미는 "20영업일 후 수익률이 시장 평균보다 높을 확률"이며, 절대 수익률 예측이 아닙니다.

## A-1. AI 자동매매에서 매도 조건 확인 바랍니다. 랭킹 순위가 매일 변하는 폭이 제법 커서 전날과 당일에 종목의 등급, C·D가 무조건 되는 경향이 있는 것 같습니다.

**답변**

AI 자동매매 SELL 트리거는 5가지 계층으로 구성됩니다. 랭킹 순위 변동 → 등급 변동 순서로 작동합니다.

| 순서 | 조건 | 임계값 | 결과 |
|---|---|---|---|
| 1 | 손절 (stop_loss) | 손익률 ≤ -7% | EXIT_CANDIDATE |
| 2 | 트레일링 스탑 | 고점 수익 ≥ 3% 도달 후 -5%p 이상 반락 | EXIT_CANDIDATE |
| 3 | 익절 (take_profit) | 손익률 ≥ 설정값 | EXIT_CANDIDATE |
| 4 | 최대 보유기간 | 보유 15일 초과 & 수익 <2% | EXIT_CANDIDATE/TRIM |
| 5 | 신뢰도 급락 | `confidence_score` < 55점 (force_exit_floor) | EXIT_CANDIDATE |
| 6 | 신뢰도 하락 | `confidence_score` < 55점 (min_hold_floor) | REPLACE_CANDIDATE |
| 7 | 순위 이탈 | 종목이 top10 밖으로 밀려남 (max_hold_rank=10) | REPLACE_CANDIDATE |

**C·D 등급 문제에 대해:**

`live_confidence_grade`는 매일 재계산되는 신뢰도 점수 버켓입니다.
- **A**: 높은 신뢰도 → 표준 비중
- **B**: 중간 신뢰도 → 0.5배 비중 축소
- **C**: 낮은 신뢰도 → watch-only (신규 매수는 파라미터에 따라 허용 여부 결정)
- **D**: 매우 낮은 신뢰도 → 신규 BUY 차단

**문제의 원인**: 운영 시작 7주밖에 되지 않아 실거래 기반 신뢰도 데이터가 부족합니다. 신뢰도 점수가 매일 조금씩 흔들리면서 C↔D 경계를 넘나드는 현상이 발생할 수 있습니다. 현재 production 설정은 `min_hold_confidence=55`, `force_exit_confidence=55`로 낮게 설정되어 있어 대부분 HOLD를 유지합니다.

**개선 방향**:
- 랭킹 순위 변동 폭이 크면 SELL 신호가 자주 발생 → 순위 안정화를 위해 rolling 평균 순위 기준 도입 검토 필요
- 등급 C/D 경계 진동 문제 → 등급 변경에 hysteresis(완충 구간) 추가 검토

## A-3. AI 자동매매 차단 문구 설명: 'AI 종목 KOSPI 대비 -2.3% 초과수익 (27일 기준)'

**답변**

**용어 해설**:

"초과수익(excess return)"은 AI가 선택한 종목들의 수익률 - KOSPI 수익률 입니다.

- **+2.3%** 초과수익 → AI 종목이 KOSPI보다 2.3% **더 올랐다** (좋음)
- **-2.3%** 초과수익 → AI 종목이 KOSPI보다 2.3% **덜 올랐다** (나쁨 → Gate BLOCK 사유)

즉, 현재 AI가 선택한 4개 종목이 진입한 날부터 27일간의 수익률을 추적해보면 KOSPI 대비 평균 **-2.3% 낮은 성과**를 기록 중이라는 뜻입니다.

**왜 27일 기준인가**: 60일 기준으로 비교해야 통계적으로 의미 있는데, 아직 운영 7주밖에 안 되어 성숙한 날짜(matured dates)가 27일분밖에 없습니다.

**왜 BLOCK이 되는가**: 시스템은 "AI 종목이 KOSPI를 이기고 있을 때만 신규 진입"이라는 보수적 기준을 적용합니다. 현재 언더퍼폼 중이므로 신규 BUY를 차단합니다. 5/28 이후 60일치 데이터가 쌓이면 이 기준을 더 정확하게 판단할 수 있습니다.


**문구 개선**: "AI 종목 KOSPI 대비 -2.3% 초과수익"은 오해를 유발합니다. → **"AI 종목이 KOSPI 대비 -2.3%p 낮은 수익 (27일 기준)"** 으로 변경했습니다. *(코드 변경 완료)*
