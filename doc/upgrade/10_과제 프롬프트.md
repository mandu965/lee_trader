지금부터 Lee Trader 프로젝트의 10차 개선 과제인

"theme overlay 활성화 시 알림/로그 추가"를 진행합니다.



이 과제는 1차 Ranking Trust Gate와 독립적으로 진행 가능한

랭킹 운영 투명성 개선 과제입니다.



핵심 목표:

현재 ENABLE\_THEME\_OVERLAY 환경변수 또는 config/production\_v1.yaml의 ranking.theme\_overlay.enabled 설정,

그리고 THEME\_OVERLAY\_MODE 조건에 따라 운영 랭킹 정렬 기준이 final\_score에서 final\_score\_v3로 바뀔 수 있다.



이 변경이 조용히 발생하면 운영자가 인지하지 못한 상태에서

다른 기준으로 자동매매 BUY 후보 정렬이 실행될 수 있다.



이번 과제에서는 theme overlay의 활성화/비활성화 조건 자체는 변경하지 않고,

다음만 추가한다.



1\. theme overlay 활성화 시 WARNING 구조화 로그

2\. theme overlay 비활성화 시 INFO 로그

3\. 정렬 기준 변경 감지 시 WARNING 로그

4\. 활성화 또는 변경 시 notifier WARNING 알림

5\. 현재 적용 중인 ranking sort basis를 JSON 파일로 저장

6\. 운영 문서에 확인 방법 추가



중요:

\- theme overlay 활성화/비활성화 판단 로직은 변경하지 않는다.

\- final\_score / final\_score\_v3 산식은 변경하지 않는다.

\- rank\_final 산정 로직은 변경하지 않는다.

\- config/production\_v1.yaml은 수정하지 않는다.

\- notifier.py는 수정하지 않는다.

\- 알림/JSON 저장 실패가 ranking 생성을 중단시키면 안 된다.

\## Step 4. 환경변수 추가



.env.example에 아래 환경변수와 설명을 추가한다.



THEME\_OVERLAY\_NOTIFY\_ON\_ACTIVATE=true

THEME\_OVERLAY\_NOTIFY\_ON\_CHANGE=true

THEME\_OVERLAY\_SORT\_BASIS\_JSON=outputs/ranking\_sort\_basis.json



기존 환경변수는 변경하지 않는다.



기존 환경변수:



ENABLE\_THEME\_OVERLAY=0

THEME\_OVERLAY\_MODE=off



환경변수 파싱 기준:



\- THEME\_OVERLAY\_NOTIFY\_ON\_ACTIVATE:

&#x20; - true이면 live\_uses\_theme=true일 때 알림 발송

&#x20; - false이면 로그만 남기고 알림은 보내지 않음



\- THEME\_OVERLAY\_NOTIFY\_ON\_CHANGE:

&#x20; - true이면 직전 실행과 현재 실행의 live\_score\_col이 다를 때 알림 발송

&#x20; - false이면 변경 로그만 남기고 알림은 보내지 않음



\- THEME\_OVERLAY\_SORT\_BASIS\_JSON:

&#x20; - 정렬 기준 저장 파일 경로

&#x20; - 상대 경로는 프로젝트 ROOT 기준으로 처리

&#x20; - 기본값 outputs/ranking\_sort\_basis.json



주의:

\- true/false 문자열을 안전하게 bool로 변환한다.

\- 경로가 잘못되었거나 저장 실패해도 ranking 생성을 중단하지 않는다.

\- 잘못된 bool 값은 기본값을 사용하고 warning 로그를 남긴다.

\## Step 5. ranking\_builder.py 구현 요구사항 A — 구조화 로그 추가



live\_uses\_theme가 결정된 직후 또는 live\_score\_col이 결정된 직후 로그를 추가한다.



활성화 시 WARNING 로그:



THEME\_OVERLAY\_ACTIVATED | date=2026-05-07 | live\_score\_col=final\_score\_v3 | rank\_final=final\_score\_v3 기준 | trigger=ENABLE\_THEME\_OVERLAY=1



비활성화 시 INFO 로그:



THEME\_OVERLAY\_INACTIVE | date=2026-05-07 | live\_score\_col=final\_score | rank\_final=final\_score 기준



로그에 포함할 필드:



\- date 또는 as\_of\_date

\- live\_score\_col

\- rank\_final\_basis

\- live\_uses\_theme

\- theme\_overlay\_mode 또는 resolved\_mode

\- ENABLE\_THEME\_OVERLAY 원본값을 확인할 수 있으면 trigger에 포함

\- config\_enabled 값을 확인할 수 있으면 포함



주의:

\- live\_uses\_theme 판단 로직 자체는 변경하지 않는다.

\- \_resolve\_theme\_overlay\_runtime\_flags() 내부 판단 로직을 바꾸지 않는다.

\- 필요한 경우 해당 함수의 반환값을 확장하지 말고, 이미 있는 반환값/변수에서 가능한 범위로 로그를 작성한다.

\- 반환값 확장이 불가피하면 기존 호출부 호환성을 깨지 않게 한다.



\---



\## Step 6. ranking\_builder.py 구현 요구사항 B — notifier 알림 추가



live\_uses\_theme=true인 경우 THEME\_OVERLAY\_NOTIFY\_ON\_ACTIVATE=true이면 notify\_warning을 호출한다.



알림 title:



\[랭킹] theme overlay 활성화 — 정렬 기준 변경됨



알림 message:



{as\_of\_date} 랭킹 정렬 기준이 final\_score → final\_score\_v3로 변경되었습니다.



details 예시:



{

&#x20; "as\_of\_date": as\_of\_date,

&#x20; "live\_score\_col": "final\_score\_v3",

&#x20; "rank\_final\_basis": "final\_score\_v3",

&#x20; "live\_uses\_theme": true,

&#x20; "theme\_overlay\_mode": resolved\_mode,

&#x20; "enable\_theme\_overlay": enable\_theme\_overlay\_raw,

&#x20; "config\_enabled": config\_enabled,

&#x20; "action\_note": "자동매매 BUY 후보 정렬이 final\_score\_v3 기준으로 실행됩니다. 의도한 변경인지 확인하세요."

}



주의:

\- notifier.py는 수정하지 않는다.

\- notify\_warning 함수가 없거나 시그니처가 다르면 기존 구조에 맞춰 best-effort로 호출한다.

\- 알림 실패가 ranking 생성을 중단시키지 않도록 try/except로 감싼다.

\- 알림 실패 시 warning 로그만 남긴다.

\- THEME\_OVERLAY\_NOTIFY\_ON\_ACTIVATE=false이면 알림은 보내지 않고 로그만 남긴다.

\## Step 7. ranking\_sort\_basis.json 저장



ranking\_builder.py 실행 시 현재 적용 중인 정렬 기준을 JSON 파일로 저장한다.



기본 경로:



outputs/ranking\_sort\_basis.json



환경변수:



THEME\_OVERLAY\_SORT\_BASIS\_JSON



JSON 구조 예시:



{

&#x20; "generated\_at": "2026-05-07T09:05:00",

&#x20; "as\_of\_date": "2026-05-07",

&#x20; "live\_score\_col": "final\_score",

&#x20; "live\_uses\_theme": false,

&#x20; "theme\_overlay\_mode": "off",

&#x20; "rank\_final\_basis": "final\_score",

&#x20; "enable\_theme\_overlay": "0",

&#x20; "config\_enabled": false,

&#x20; "runtime\_mode": "operational"

}



필수 필드:



\- generated\_at

\- as\_of\_date

\- live\_score\_col

\- live\_uses\_theme

\- theme\_overlay\_mode 또는 resolved\_mode

\- rank\_final\_basis

\- runtime\_mode



가능하면 포함할 필드:



\- enable\_theme\_overlay

\- config\_enabled

\- theme\_overlay\_trigger\_info



주의:

\- outputs 디렉터리가 없으면 생성한다.

\- 저장 실패가 ranking 생성을 중단시키면 안 된다.

\- 저장 실패 시 warning 로그만 남긴다.

\## Step 8. 이전 기준과 비교 로그 추가



ranking\_sort\_basis.json을 쓰기 전에 직전 파일을 읽어 이전 live\_score\_col을 확인한다.



비교 기준:



previous\_live\_score\_col != current\_live\_score\_col



변경 감지 시 WARNING 로그:



THEME\_OVERLAY\_CHANGED | date=2026-05-07 | previous=final\_score | current=final\_score\_v3 | 정렬 기준이 변경되었습니다



THEME\_OVERLAY\_NOTIFY\_ON\_CHANGE=true이면 notify\_warning을 호출한다.



알림 title:



\[랭킹] 정렬 기준 변경 감지



알림 message:



이전: {previous\_live\_score\_col} → 현재: {current\_live\_score\_col}



details 예시:



{

&#x20; "as\_of\_date": as\_of\_date,

&#x20; "previous\_live\_score\_col": previous\_live\_score\_col,

&#x20; "current\_live\_score\_col": current\_live\_score\_col,

&#x20; "previous\_live\_uses\_theme": previous\_live\_uses\_theme,

&#x20; "current\_live\_uses\_theme": live\_uses\_theme,

&#x20; "theme\_overlay\_mode": resolved\_mode,

&#x20; "action\_note": "정렬 기준 변경이 의도된 것인지 확인하세요."

}



주의:

\- 이전 파일이 없으면 변경 비교를 생략한다.

\- 이전 파일이 깨져 있거나 읽기 실패하면 변경 비교를 생략하고 warning 로그만 남긴다.

\- 비교 실패가 ranking 생성을 중단시키면 안 된다.

\- 현재 파일 저장은 비교 후 진행한다.

\## Step 9. ranking\_trust\_summary.json 연동



1차 과제에서 outputs/ranking\_trust\_summary.json 생성 로직이 이미 존재하는 경우,

가능하면 아래 필드를 추가한다.



"ranking\_sort\_basis": {

&#x20; "live\_score\_col": "final\_score",

&#x20; "live\_uses\_theme": false,

&#x20; "theme\_overlay\_mode": "off",

&#x20; "rank\_final\_basis": "final\_score"

}



주의:

\- 1차 과제가 아직 반영되지 않았거나 해당 summary 생성 로직이 없다면 이 작업은 생략한다.

\- 이 경우에도 outputs/ranking\_sort\_basis.json은 반드시 독립적으로 생성한다.

\- ranking\_trust\_summary.json 연동을 위해 무리하게 1차 과제 코드를 새로 만들지 않는다.
