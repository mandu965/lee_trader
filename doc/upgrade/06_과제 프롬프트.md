지금부터 Lee Trader 프로젝트의 6차 개선 과제인

"Rule live strong\_entry 기준 고정"을 진행합니다.



이 과제는 1차 Ranking Trust Gate와 독립적으로 진행 가능한 Rule 자동매매 진입 기준 개선 과제입니다.



핵심 목표:

Rule 자동매매에서 entry\_signal / strong\_entry\_signal 생성 로직은 그대로 유지하되,

BUY guard 단계에서 run\_mode별로 strong\_entry 필수 여부를 환경변수로 제어한다.



운영 원칙:

\- pilot/live에서는 기본적으로 strong\_entry\_signal만 BUY 허용한다.

\- paper에서는 기본적으로 entry\_signal도 BUY 허용한다.

\- entry\_signal / strong\_entry\_signal 산식 자체는 변경하지 않는다.



중요:

\- 이번 과제는 Rule BUY guard 정책만 다룬다.

\- rule\_signal\_builder.py의 신호 생성 로직은 수정하지 않는다.

\- rule\_order\_preview\_builder.py, rule\_order\_submitter.py, rule\_portfolio\_manager.py는 수정하지 않는다.

\- 실계좌 주문/KIS API 호출은 테스트 목적으로 실행하지 않는다.

\## Step 4. 구현 요구사항



현재 rule\_account\_guard.py에는 다음 성격의 guard가 있다.



if order\_context.get("signal\_strength") != "strong\_entry":

&#x20;   reasons.append("buy\_requires\_strong\_entry")



이 로직을 아래 방식으로 변경한다.



\### 4-1. run\_mode 판정



order\_context에서 run\_mode를 읽는다.



권장:



run\_mode = str(order\_context.get("run\_mode") or "paper").lower()



단, 실제 소스에서 run\_mode가 다른 키 이름으로 전달된다면 기존 구조를 우선한다.

예:

\- run\_mode

\- mode

\- trading\_mode

\- rule\_run\_mode



없으면 안전하게 paper로 간주한다.



\### 4-2. 환경변수 추가



아래 환경변수를 사용한다.



RULE\_LIVE\_BUY\_REQUIRES\_STRONG\_ENTRY=true



\- pilot/live에서 strong\_entry 필수 여부

\- 기본값 true

\- true이면 pilot/live에서 signal\_strength != strong\_entry인 BUY를 차단한다.

\- false이면 pilot/live에서도 entry\_signal BUY를 허용할 수 있다.



RULE\_PAPER\_ALLOW\_ENTRY\_SIGNAL=true



\- paper에서 entry\_signal 허용 여부

\- 기본값 true

\- true이면 paper에서 signal\_strength == entry도 허용한다.

\- false이면 paper에서도 strong\_entry만 허용한다.



\### 4-3. require\_strong 판정



구현 방향:



run\_mode = str(order\_context.get("run\_mode") or "paper").lower()



if run\_mode in {"pilot", "live"}:

&#x20;   require\_strong = \_flag("RULE\_LIVE\_BUY\_REQUIRES\_STRONG\_ENTRY", "1")

else:

&#x20;   require\_strong = not \_flag("RULE\_PAPER\_ALLOW\_ENTRY\_SIGNAL", "1")



if require\_strong and order\_context.get("signal\_strength") != "strong\_entry":

&#x20;   reasons.append("buy\_requires\_strong\_entry")



주의:

\- \_flag 유틸이 이미 있으면 기존 함수를 사용한다.

\- 없으면 기존 코드 스타일에 맞춰 bool env 파싱을 최소 구현한다.

\- bool 파싱은 true/false, 1/0, yes/no 등을 안전하게 처리한다.

\- 잘못된 값이면 기본값을 사용하고 warning 로그를 남긴다.



\### 4-4. reason 유지



차단 사유는 기존 문자열을 그대로 사용한다.



buy\_requires\_strong\_entry



새로운 reason명을 만들지 않는다.

기존 리포트/운영 문서와 호환성을 유지한다.

.env.example에 아래 내용을 추가한다.

\- RULE\_ENTRY\_RULE\_SCORE\_V2\_MIN
