# 2026-04-08 애드센스 준비 계획

기준일: 2026-04-08 KST

이 문서는 `Lee_trader` 프로젝트를 공개 사이트로 확장하고, 향후 Google AdSense 승인을 받을 수 있는 형태로 준비하기 위한 실행 문서입니다.

- 원본성 있는 글과 신뢰 페이지를 먼저 확보
- 그 이후 도메인 연결, 호스팅, Search Console, AdSense 순서로 진행

## 1. 기본 방향

현재 사이트는 운영자와 분석자를 위한 대시보드 성격이 강합니다.

현재 특성:
- `ranking`, `ops-readiness`, `paper-trading`, `manual-trading` 중심
- 앱/도구형 UI 비중이 큼
- 일반 방문자가 읽을 공개형 글 콘텐츠는 부족

따라서 애드센스 승인을 목표로 한다면 사이트를 아래 2개 층으로 분리하는 것이 맞습니다.

### 1.1 공개 콘텐츠 사이트

목적:
- 일반 방문자가 읽을 수 있는 글과 안내 페이지 제공
- 검색 유입과 콘텐츠 평가 대상 확보
- 애드센스 심사 대상 역할

### 1.2 운영 도구 영역

목적:
- 현재 분석 및 운영 화면 유지
- 추천/운영/종목 관리 기능 제공
- 광고보다 기능 중심 화면으로 관리

## 2. 권장 사이트 구조

## 2.1 공개 영역

추천 URL 구조:

- `/`
- `/about`
- `/methodology`
- `/reports`
- `/reports/:slug`
- `/blog`
- `/blog/:slug`
- `/contact`
- `/privacy`
- `/terms`
- `/disclaimer`

페이지 역할:

### `/`
- 서비스 소개
- 어떤 데이터를 보고 어떤 방식으로 종목을 해석하는지 간단 설명
- 최신 리포트/최신 글 링크
- 앱 영역으로 가는 링크 분리

### `/about`
- 프로젝트 소개
- 운영 목적
- 누가 어떤 기준으로 사이트를 운영하는지 설명

### `/methodology`
- 점수 구조 설명
- quality/risk/confidence 개념 설명
- watchlist / BUY_ALLOWED / BLOCK 해석 설명
- 투자 자문이 아니라는 점 명시

### `/reports`
- 시장/전략 리포트 목록
- 공개형 분석 리포트 아카이브

### `/reports/:slug`
- 실제 분석 글 본문
- 검색 유입 핵심 페이지

### `/blog`
- 운영 회고, 실험 로그, 시스템 개선 기록

### `/blog/:slug`
- 블로그 상세 글
- 모델 실험, 회고, 운영 관찰 기록

### `/contact`
- 문의 방법
- 이메일 또는 폼 안내

### `/privacy`
- 개인정보 처리방침

### `/terms`
- 이용약관

### `/disclaimer`
- 투자 책임, 정보 제공 목적, 정확성 한계 안내

## 4. 콘텐츠 전략

애드센스 승인 관점에서 중요한 것은 `글자 수 자체`보다 `원본성`, `완성도`, `방문자 유용성`입니다.

다만 초기 운영 기준으로는 아래 수준을 권장합니다.

### 4.1 초기 목표 수량

- 공개 글 15개 이상
- 가능하면 20개 전후까지 확보

### 4.2 권장 분량

- 글당 1,000자 이상 권장
- 핵심 글은 1,500자~2,500자 권장

### 4.3 금지에 가까운 패턴

- 자동 생성 티가 강한 짧은 글 대량 게시
- 제목만 바꾼 유사 글 반복
- 차트 숫자만 나열한 페이지
- 설명 없이 종목 코드만 모아둔 페이지
- 앱 화면을 그대로 공개 콘텐츠처럼 포장하는 방식

### 4.4 권장 콘텐츠 원칙

- 사람의 해석이 들어가야 함
- 왜 중요한지 설명해야 함
- 초보자도 읽을 수 있어야 함
- 데이터 출처나 판단 한계를 함께 적어야 함

## 5. 추천 콘텐츠 카테고리

초기에는 아래 4개 카테고리로 시작하는 것이 가장 현실적입니다.

### 5.1 시장 리포트

예시:
- 이번 주 시장 해석
- 변동성 확대 구간에서 체크할 신호
- 최근 시장 국면이 neutral인 이유
- breadth와 volatility를 같이 보는 이유

### 5.2 모델 해설

예시:
- quality_risk_guard란 무엇인가
- confidence score는 어떻게 읽는가
- watchlist와 BUY_ALLOWED의 차이
- final_score와 buyability_score의 차이

### 5.3 케이스 스터디

예시:
- 특정 종목이 상위에 오른 이유
- 상위 후보가 실제로는 보류된 이유
- 좋은 점수를 받아도 매수하면 안 되는 경우
- shadow 후보를 어떻게 해석해야 하는가

### 5.4 운영 회고

예시:
- 이번 주 paper trading 요약
- 운영 blocker가 발생한 이유
- repeatability가 중요한 이유
- 실험을 production에 바로 올리지 않는 이유

## 6. 초기 글 20개 주제안

아래 20개는 이 프로젝트 구조에 바로 맞는 주제입니다.

1. 이 사이트는 어떤 방식으로 종목을 분석하나요
2. 점수는 높아도 바로 매수하지 않는 이유
3. watchlist와 BUY_ALLOWED는 어떻게 다른가
4. confidence score를 투자 판단에 바로 쓰면 안 되는 이유
5. quality_risk_guard가 필요한 이유
6. 최근 시장 국면이 neutral로 판단된 배경
7. breadth와 volatility를 함께 보는 이유
8. final_score와 buyability_score의 차이 설명
9. 좋은 종목과 좋은 매수 타이밍은 왜 다른가
10. 실운영 전에 paper trading이 필요한 이유
11. 운영자 페이지에서 꼭 봐야 하는 5가지 항목
12. matured benchmark dates가 왜 중요한가
13. walk-forward acceptance는 무엇을 의미하나
14. repeatability가 없으면 모델 승격을 보류하는 이유
15. quality coverage가 낮을 때 생기는 문제
16. 특정 종목이 상위 후보였지만 보류된 사례
17. shadow 후보가 상위로 올라오는 구조 설명
18. 운영 판단에서 BLOCK이 나오는 대표 패턴
19. 모델 개선보다 운영 신뢰도가 중요한 이유
20. 이 사이트의 데이터와 해석은 어떻게 활용해야 하나

## 8. 도메인과 호스팅 방향

## 8.1 도메인 방향

가능하면 아래 형태가 좋습니다.

- 브랜드형 도메인
- 너무 일반적이지 않은 이름
- 투자/리포트 성격이 드러나는 이름

예:
- `leetrader.ai`
- `leetraderlab.com`
- `kstocksignals.com`

실제 선택 원칙:
- 짧고 기억하기 쉬울 것
- 한국어 콘텐츠와 어울릴 것
- 향후 블로그/서비스 둘 다 수용 가능할 것

## 8.2 호스팅 방향

현재 프로젝트 구조를 보면 첫 배포는 아래가 가장 현실적입니다.

### 추천: VPS + Docker Compose

이유:
- 현재 구조 유지 가능
- Node + Python + Postgres 조합과 잘 맞음
- 앱 영역과 공개 콘텐츠 영역을 함께 운영 가능

### 대안: 공개 사이트는 정적, 앱은 별도 서비스

구조:
- 공개 콘텐츠: 정적 페이지/블로그
- 운영 앱: 현재 Node 서비스

이 방식은 애드센스 심사 관점에서 더 깔끔할 수 있습니다.

## 9. 이 프로젝트에 실제 적용하는 방법

가장 현실적인 적용안은 아래와 같습니다.

- 공개 콘텐츠와 앱 메뉴 분리

- 운영 데이터에서 공개 가능한 요약만 콘텐츠화
- 예:
  - market regime 요약
  - weekly report 요약
  - paper trading 회고

단, 그대로 자동 게시하지 말고 사람 해설을 추가해야 합니다.

## 11. 결론

이 프로젝트는 애드센스용 사이트로 확장할 수 있습니다.  
하지만 현재 운영 도구 중심 구조만으로는 승인 가능성이 높지 않습니다.

핵심은 아래 3가지입니다.

- 공개 콘텐츠 레이어를 따로 만든다
- 원본성 있는 글을 충분히 쌓는다
- 신뢰 페이지와 사이트 구조를 완성한다

즉, 방향은 `운영 도구를 광고 사이트로 바꾸는 것`이 아니라 `운영 도구를 가진 콘텐츠 사이트`로 확장하는 것입니다.

이 방향으로 가면:
- 애드센스 승인 가능성 확보
- 검색 유입 확보
- 브랜드 사이트화
- 향후 유료화/구독형 확장 기반 확보
