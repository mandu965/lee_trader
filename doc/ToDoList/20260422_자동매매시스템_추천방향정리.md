# 20260422 자동매매시스템 추천방향 정리

## 0. 정리 목적

현재 구조에서는 `모의투자 추천 엔진`과 `실자동매매 실행 엔진`이 같은 역할을 하지 않습니다.

겉으로 보면 같은 추천 결과를 쓰는 것처럼 보이지만, 실제로는 아래 두 층이 분리되어 있습니다.

- 추천 엔진: 어떤 종목이 상대적으로 좋아 보이는가
- 실행 엔진: 지금 실제 돈으로 어디까지 자동 진입을 허용할 것인가

이 둘을 분리해서 보지 않으면 아래와 같은 혼선이 계속 발생합니다.

- 모의투자에서는 잘 나오는데 왜 실매수는 거의 안 되는가
- 추천이 약한 것인가, 아니면 실행 조건이 너무 강한 것인가
- top8 전략인데 왜 실제로는 8종목이 안 채워지는가

이 문서는 위 혼선을 정리하고, 현재 시점에서 어떤 방향으로 운영하는 것이 맞는지 추천하기 위해 작성합니다.

---

## 1. 현재 구조를 한 문장으로 요약하면

현재 실자동매매는 `모의투자 top8을 그대로 복제해서 매수하는 구조`가 아닙니다.

실제 구조는 아래에 가깝습니다.

`top20 후보를 만들고 -> top8/top10 수준의 추천 검토를 거친 뒤 -> gate, confidence, 유동성, cap, 현금, cooldown, 실행 승인 조건을 통과한 일부만 실제 매수하는 구조`

즉, 모의투자는 `추천 성능을 보는 구조`에 가깝고, 실자동매매는 `추천 이후에도 여러 안전장치를 거쳐 제한적으로만 진입하는 구조`에 가깝습니다.

---

## 2. 왜 모의투자와 실자동매매가 다르게 보이는가

### 2-1. 모의투자의 역할

모의투자는 주로 아래 질문에 답하기 위한 구조입니다.

- 오늘 기준으로 상위 추천 종목은 무엇인가
- top5, top8, top10으로 묶었을 때 성과가 어떤가
- 점수 체계와 랭킹 체계가 유효한가

즉, `좋아 보이는 종목 묶음의 성과를 평가하는 구조`입니다.

### 2-2. 실자동매매의 역할

실자동매매는 추천 이후에 아래 질문을 다시 확인합니다.

- 지금 시장 상태에서 신규 진입을 허용해야 하는가
- 이 종목은 지금 실제 주문 가능한 상태인가
- 현재 보유/현금/섹터 집중도 기준에서 진입해도 되는가
- 실행 스위치, 승인 조건, 확인 텍스트까지 모두 통과했는가

즉, `추천 결과를 바로 주문하지 않고, 실제 집행 가능 상태인지 다시 검증하는 구조`입니다.

---

## 3. 현재 실매수 진입 장벽은 높은 편인가

결론부터 말하면 `높은 편`입니다.

이유는 단순합니다. 현재 구조는 추천 순위만으로 매수하지 않고, 추천 이후에 여러 단계의 필터를 추가로 통과해야 하기 때문입니다.

현재 실자동매매에서 실제 진입을 줄이는 요소는 대략 아래와 같습니다.

- top20 후보군 안에서 다시 top8, top10 수준의 진입 검토
- gate 상태 확인
- confidence 기준 확인
- liquidity, trading value 기준 확인
- sector/theme cap 확인
- cash minimum 확인
- 재진입 cooldown 확인
- execution, allow-buy, approval, confirm-text 같은 실행 안전장치 확인

따라서 `max_holdings = 8`이라고 해서 항상 8종목을 채우는 구조가 아닙니다.

현재의 `8`은 목표 상한에 가깝고, 실제 진입 종목 수는 그날의 gate 상태와 실행 조건에 따라 훨씬 적어질 수 있습니다.

---

## 4. 현재 구조의 장점과 한계

### 4-1. 장점

- 실거래 리스크를 급격하게 키우지 않는다
- 추천 문제와 실행 문제를 분리해서 볼 수 있다
- 왜 보류되었는지 운영적으로 설명할 수 있다
- 제한적 진입을 통해 실제 체결 로그와 운영 데이터를 쌓을 수 있다

### 4-2. 한계

- 모의투자 top8과 실자동매매 결과 차이가 크게 느껴진다
- 추천은 많이 나오는데 실제 주문은 적어서 체감상 시스템이 멈춘 것처럼 보일 수 있다
- 실거래 데이터가 충분히 쌓이지 않아 실행 로직 검증이 느려진다
- 추천 모델 문제가 아닌데도 추천 모델이 약한 것처럼 오해될 수 있다

즉, 현재 구조는 안전하지만 답답할 수 있습니다.

---

## 5. 선택 가능한 방향 3가지

### A안. 보수 유지형

추천 엔진과 실행 엔진을 지금처럼 강하게 분리해서 운영하는 방향입니다.

- 추천 쪽은 top20, top8, top5 성과 개선에 집중
- 실자동매매는 WATCH/PILOT 제한 진입을 유지

장점:

- 가장 안전합니다
- 추천 문제와 실행 문제를 분리해서 보기 쉽습니다
- 실거래 리스크가 낮습니다

단점:

- 모의투자와 실자동매매 간 괴리가 계속 크게 남습니다
- 실제 매수 건수가 적어 운영 체감이 떨어집니다

### B안. 점진 완화형

현재 추천 엔진은 유지하고, 실자동매매 실행 조건만 단계적으로 완화하는 방향입니다.

- 추천 모델은 당분간 그대로 유지
- 먼저 실행 스위치와 승인 조건을 정리
- 그 다음 pilot 진입 개수와 총 노출 한도를 완화
- 필요할 때만 confidence 기준을 소폭 조정

장점:

- 현재 구조를 유지하면서 실제 진입률을 높일 수 있습니다
- 추천 문제와 실행 보수성을 분리해서 개선할 수 있습니다
- 실거래 데이터 축적 속도가 빨라집니다

단점:

- 완화 기준을 문서화하고 지표로 관리해야 합니다
- 완화 이후 모니터링을 꾸준히 해야 합니다

### C안. 모의투자 정렬형

실자동매매를 모의투자 top8과 최대한 비슷하게 맞추는 방향입니다.

- top8이면 실제로도 8종목에 가깝게 진입
- gate와 제한 조건을 크게 단순화

장점:

- 모의투자와 실자동매매 설명이 쉬워집니다
- 추천 성과와 실거래 결과의 차이가 줄어듭니다

단점:

- 현재 단계에서는 리스크가 큽니다
- 실행 안전장치가 너무 약해질 수 있습니다
- 추천 오차가 실거래 손실로 바로 이어질 가능성이 커집니다

---

## 6. 현재 시점의 추천 방향

현재는 `B안. 점진 완화형`이 가장 적절합니다.

이유는 아래 3가지입니다.

1. 이미 시스템이 추천과 실행을 분리하는 방향으로 설계되어 있습니다.
2. 지금 당장 모의투자 top8을 실매매에 그대로 맞추면 리스크가 너무 크게 증가합니다.
3. 반대로 현재 구조를 그대로 두면 실자동매매가 지나치게 보수적으로 남아 실제 진입과 데이터 축적이 너무 느립니다.

즉, 지금 필요한 것은 `추천 모델 고도화`보다 `실행 장벽 완화`입니다.

---

## 7. 무엇을 먼저 완화해야 하는가

우선순위는 아래 순서가 맞습니다.

### 7-1. 1순위: 실행 스위치와 승인 체계 점검

먼저 확인해야 할 항목은 아래입니다.

- `AUTO_TRADE_EXECUTE`
- `AUTO_TRADE_ALLOW_BUY`
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED`
- `AUTO_TRADE_CONFIRM_TEXT`

이 영역은 추천 품질과 무관하게 실제 제출을 막을 수 있기 때문에 가장 먼저 점검해야 합니다.

### 7-2. 2순위: pilot 진입 수와 총 노출 한도 완화

그 다음은 제한 진입 관련 항목입니다.

- `pilot_limited_max_entries`
- `pilot_limited_total_exposure`
- `pilot_limited_position_cap`

이 구간은 실제 진입 건수를 늘리는 데 가장 직접적인 영향을 줍니다.

### 7-3. 3순위: confidence 기준 조정

추천과 직접 연결되는 영역이므로, 실행 장벽을 먼저 조정한 뒤에 검토하는 것이 맞습니다.

- `standard_entry_confidence`
- `extended_entry_confidence`
- `min_entry_confidence`

### 7-4. 4순위: cap, cash, cooldown

이 항목들은 안전장치 성격이 강하므로 가장 마지막에 봐야 합니다.

- `sector_cap`
- `theme_cap`
- `cash_minimum`
- `reentry_cooldown_days`

## 8. 운영 화면에서 반드시 보여줘야 하는 것

현재처럼 `추천 후보`와 `제출 가능`만 보이면 운영자가 오해하기 쉽습니다.

실자동매매 화면에는 최소한 아래 정보가 함께 보여야 합니다.

- BUY intent 건수
- preview 생성 건수
- execution 생성 건수
- 실제 submitted 건수
- skipped 건수
- 상위 skip reason
- 미제출 예상 사유

그래야 아래 둘을 구분할 수 있습니다.

- 추천은 충분했는데 실행 조건 때문에 보류된 것인지
- 애초에 추천 단계에서 대상이 적었던 것인지

즉, 운영 화면은 `추천 결과 화면`이 아니라 `추천 -> 주문초안 -> 실제제출` 흐름을 보여주는 화면이어야 합니다.

## 9. 최종 정리

현재 실자동매매는 `모의투자 top8을 그대로 따라 매수하는 구조`가 아닙니다.
실제 구조는 `추천 후 여러 실행 안전장치를 통과한 일부만 제한적으로 진입하는 구조`입니다.

따라서 지금 시점의 추천 방향은 아래 한 문장으로 정리할 수 있습니다.

`추천 모델 고도화보다, 실자동매매의 실행 장벽을 먼저 낮춰서 preview -> execution -> 실제 체결 전환율을 올리는 방향이 우선이다.`

즉, 지금은 더 좋은 종목을 찾는 것보다, 이미 찾은 종목이 실제로 얼마나 집행되고 있는지를 개선하는 것이 우선입니다.
