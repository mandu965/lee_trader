# 20260422 실자동매매 진입장벽 완화안 v1

## 0. 문서 목적

이 문서는 현재 실자동매매가 지나치게 보수적으로 동작하여 실제 매수 진입과 실거래 데이터 축적이 충분히 일어나지 않는 문제를 완화하기 위한 `1차 실행안`입니다.

핵심 목표는 아래와 같습니다.

- `preview -> execution -> submitted` 전환율을 높인다
- 실제 신규 진입 종목 수를 늘린다
- 실거래 로그와 운영 데이터를 더 빨리 축적한다
- 추천 모델 자체는 당장 크게 바꾸지 않는다

즉, 이 문서는 `추천모델 고도화안`이 아니라 `실행 장벽 완화안`입니다.

---

## 1. 기본 원칙

이번 v1은 아래 원칙으로 진행합니다.

1. 추천 엔진은 당분간 그대로 둔다
2. 먼저 실행 스위치와 승인 체계를 점검한다
3. 그 다음 pilot 진입 수와 총 노출 한도를 완화한다
4. confidence 기준은 v1에서 즉시 크게 건드리지 않는다
5. cap, cash, cooldown 같은 안전장치는 v1에서는 유지한다

즉, 지금은 `더 좋은 종목을 찾는 단계`보다 `이미 찾은 종목이 실제로 집행되게 만드는 단계`가 우선입니다.

---

## 2. 현재 병목 후보

현재 병목은 크게 4개 영역으로 나눠서 볼 수 있습니다.

### 2-1. 실행 스위치 / 승인 체계

- `AUTO_TRADE_EXECUTE`
- `AUTO_TRADE_ALLOW_BUY`
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED`
- `AUTO_TRADE_CONFIRM_TEXT`

이 영역은 추천 결과와 무관하게 실제 제출 자체를 막을 수 있습니다.

### 2-2. 제한 진입 한도

- `pilot_limited_max_entries`
- `pilot_limited_total_exposure`
- `pilot_limited_position_cap`
- `watch_limited_max_entries`
- `watch_limited_total_exposure`
- `watch_limited_position_cap`

이 영역은 추천이 있어도 실제 진입 숫자를 강하게 제한할 수 있습니다.

### 2-3. confidence 기준

- `standard_entry_confidence`
- `extended_entry_confidence`
- `min_entry_confidence`

이 영역은 추천 후보가 실제 진입 단계로 넘어오기 전에 걸러지는 원인이 될 수 있습니다.

### 2-4. 리스크 안전장치

- `sector_cap`
- `theme_cap`
- `cash_minimum`
- `reentry_cooldown_days`

이 항목들은 실거래 안전장치 성격이 강하므로 v1에서는 마지막 순위로 둡니다.

---

## 3. v1 우선순위

### 3-1. 1순위: execute / allow-buy / approval 점검

가장 먼저 확인할 항목은 아래입니다.

- 실제 서버에서 `AUTO_TRADE_EXECUTE=1` 인가
- 실제 서버에서 `AUTO_TRADE_ALLOW_BUY=1` 인가
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED`가 현재 단계에서 너무 강한가
- `AUTO_TRADE_CONFIRM_TEXT`가 실제 운영값과 맞는가

이 영역은 추천 품질과 관계없이 `preview는 생기는데 execution이 거의 안 나오는 현상`을 만들 수 있기 때문에 최우선 점검 대상입니다.

권고 방향:

- 실행 스위치가 OFF 상태인 경우 먼저 정상화
- approval 체계가 너무 강하면 제한적 완화 검토
- 전면 해제보다 `소수 종목 / 제한 비중 구간`에서 먼저 완화

예상 효과:

- `preview -> execution` 전환율 즉시 개선 가능

---

### 3-2. 2순위: pilot 진입 한도 완화

현재 가정값은 아래와 같습니다.

- `pilot_limited_max_entries: 4`
- `pilot_limited_total_exposure: 0.36`
- `pilot_limited_position_cap: 0.12`

v1 권고안:

- `pilot_limited_max_entries: 4 -> 5`
- `pilot_limited_total_exposure: 0.36 -> 0.45`
- `pilot_limited_position_cap: 0.12` 는 우선 유지

이유:

- 종목당 비중 cap을 먼저 풀기보다
  `몇 종목까지 들어갈 수 있는가`와 `총 얼마까지 들어갈 수 있는가`
  를 먼저 완화하는 것이 해석이 쉽습니다.

예상 효과:

- 실제 신규 진입 종목 수 증가
- 모의투자 top8과 실거래 간 체감 괴리 일부 완화

주의:

- sector/theme cap과 충돌하는지 함께 관찰해야 합니다

---

### 3-3. 3순위: WATCH 구간은 v1에서 유지 또는 최소 변경

현재 WATCH 관련 값은 아래와 같습니다.

- `watch_limited_max_entries: 2`
- `watch_limited_total_exposure: 0.15`
- `watch_limited_position_cap: 0.08`

또한 현재 구조에서는 `watch_limited_entry_override_mode: pilot` 성격이 있어 WATCH가 실제로는 PILOT 기준 쪽으로 해석될 수 있습니다.

v1 권고안:

- WATCH 자체는 이번 1차에서는 크게 바꾸지 않음
- 먼저 PILOT 완화 결과를 본 뒤 다음 단계에서 검토

이유:

- WATCH는 본래 보수적으로 보는 시험 구간 성격이 강합니다
- v1에서 WATCH까지 동시에 크게 풀면 원인 해석이 어려워집니다

---

### 3-4. 4순위: confidence 기준은 관찰 후 소폭 조정

현재 값은 아래와 같습니다.

- `standard_entry_confidence: 76`
- `extended_entry_confidence: 70`
- `min_entry_confidence: 55`

v1 권고안:

- 이번 단계에서는 즉시 변경하지 않음
- 먼저 confidence 때문에 상위 후보가 얼마나 탈락하는지 관찰

조건부 후보안:

- `standard_entry_confidence: 76 -> 74`
- `extended_entry_confidence: 70 -> 68`

이유:

- confidence는 추천 품질과 직접 연결되는 영역입니다
- 실행 스위치와 pilot 한도를 먼저 정리한 뒤 봐야 해석이 가능합니다

---

### 3-5. 5순위: cap / cash / cooldown 은 v1에서 유지

현재 값은 아래와 같습니다.

- `sector_cap: 0.35`
- `theme_cap: 0.35`
- `cash_minimum: 0.05`
- `reentry_cooldown_days: 10`

v1 권고안:

- 이번 단계에서는 유지

이유:

- 이 영역은 안전장치의 핵심입니다
- 여기까지 완화하기 시작하면 `실행 장벽 완화`가 아니라 `리스크 통제 약화` 단계로 넘어갑니다

## 5. 적용 순서

### 단계 1. 운영값 점검

먼저 아래를 확인합니다.

- 실제 서버의 `AUTO_TRADE_EXECUTE`
- 실제 서버의 `AUTO_TRADE_ALLOW_BUY`
- 실제 서버의 `AUTO_TRADE_BUY_APPROVAL_REQUIRED`
- 최근 5영업일 주요 `skip_reason`

완료 기준:

- 왜 제출이 안 되었는지를 실행 로그 기준으로 설명할 수 있어야 함

### 단계 2. approval / execution 병목 완화

운영 스위치와 승인 체계를 먼저 정리합니다.

완료 기준:

- execution 파일 또는 실행 결과가 이전보다 의미 있게 생성됨
- `preview는 있는데 execution 0` 현상이 줄어듦

### 단계 3. pilot 한도 완화

그 다음 아래 값을 조정합니다.

- `pilot_limited_max_entries: 4 -> 5`
- `pilot_limited_total_exposure: 0.36 -> 0.45`

완료 기준:

- 실제 신규 진입 종목 수 증가
- 동시에 과도한 집중이나 운영 오류가 증가하지 않음

### 단계 4. confidence 재검토

pilot 완화 이후에도 top8 대비 실제 진입이 여전히 너무 적으면 그때 confidence를 조정합니다.

완료 기준:

- confidence 완화가 실제 진입 증가에 의미 있게 기여하는지 확인

## 6. 반드시 같이 봐야 할 지표

완화 이후 아래 지표를 일별로 같이 봐야 합니다.

- BUY intent 건수
- preview 건수
- executable preview 건수
- execution 생성 건수
- submitted 건수
- skipped 건수
- 상위 skip reason 5개
- 실제 신규 진입 종목 수
- 실제 신규 진입 총 비중

운영 권고:

- 최소 1주일 단위로 전후 비교
- 하루 결과만 보고 추가 완화하지 않음

---

## 7. v1에서 하지 않을 것

이번 v1의 우선순위는 아래가 아닙니다.

- 추천 모델 구조를 크게 바꾸는 것
- feature를 대폭 추가하는 것
- 모델 점수 체계를 다시 설계하는 것
- 리스크 안전장치를 전반적으로 푸는 것

이유:

- 지금 병목은 추천 부족보다 실행 부족일 가능성이 높습니다
- 추천 모델을 먼저 손보면 실행 병목이 가려져 원인 분리가 더 어려워집니다

---

## 8. 최종 결론

이번 `실자동매매 진입장벽 완화안 v1`의 핵심은 아래 두 줄입니다.

1. 먼저 `execute / allow-buy / approval` 같은 실행 병목을 제거한다
2. 그 다음 `pilot 진입 수 / 총 노출 한도`를 단계적으로 완화한다

즉, 지금은 `추천 모델을 더 복잡하게 만드는 것`보다 `이미 나온 추천이 실제로 집행되게 만드는 것`이 우선입니다.

한 문장 요약:

`v1은 추천모델 고도화보다 실행 병목 해소를 우선하며, approval/execute 점검 후 pilot 진입 한도를 단계적으로 완화하는 방향으로 진행한다.`
