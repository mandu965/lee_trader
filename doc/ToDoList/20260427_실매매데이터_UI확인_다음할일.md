### 1.3 기존 `public.trades` 원장

`public.trades`는 웹에서 직접 입력/수정하는 확정 거래 원장이다.

- 기본 동기화 방향: 웹 DB -> 로컬 DB
- 로컬 -> 웹 업로드는 복구/초기 이관 목적일 때만 명시적으로 수행
- `sync_web_display_data.py`는 기본적으로 `public.trades`를 덮어쓰지 않도록 변경됨

로컬 동기화 명령:

```powershell
$env:LOCAL_DATABASE_URL="postgresql://lee_trader:lee_trader_pw@localhost:5432/lee_trader"
.venv\Scripts\python.exe python\sync_trades_from_web_db.py
```

## 4. 내일 구현 후보

### 4.1 1순위: 실자동매매 화면에 리뷰 입력 UI 추가

현재는 `live_trade_review` API만 있고 화면 입력이 없다.

필요 기능:

- preview/execution/holding 행에서 `리뷰 작성` 버튼 제공
- `pre_tags`, `post_tags`, `outcome_label`, `review_note`, `next_action_note` 입력
- 저장 후 해당 종목/주문에 리뷰 존재 여부 표시
- 리뷰 저장 대상은 `intent_id`, `request_id`, `code`를 함께 넘긴다.

권장 위치:

- `live-auto-trading.html`
- `live-auto-trading.js`

### 4.2 2순위: 실자동매매 화면에 fill 영역 추가

현재 화면은 preview/execution 중심이다. 실제 체결 확정까지 보려면 `live_order_fill` 표시가 필요하다.

필요 기능:

- `research.live_order_fill` 또는 `outputs/live_order_fills.json` 기반 체결 표 추가
- 주문 제출과 체결 확정의 차이 명확히 표시
- 부분 체결, 미체결, 수수료/세금 표시

### 4.3 3순위: decision -> request -> execution -> fill 연결 뷰

운영자가 가장 보고 싶은 흐름은 한 종목/주문 기준 연결이다.

필요 기능:

- `intent_id`, `request_id`, `broker_order_id` 기준 연결
- 한 줄에서 판단, 주문요청, 제출결과, 체결결과, 보유현황, 리뷰를 볼 수 있게 구성
- 오류/차단 사유는 별도 컬럼으로 표시

### 4.4 4순위: UI 용어 정리

혼동을 줄이기 위해 화면 용어를 고정한다.

- `Intent`: 판단
- `Preview`: 주문 초안
- `Execution`: 주문 제출
- `Fill`: 체결 확정
- `Position`: 보유 현황
- `Review`: 운영자 사후 판단
- `Trades`: 웹 수기/확정 거래 원장

## 5. 내일 운영 확인 SQL

최신 자동매매 판단:

```sql
SELECT as_of_date, COUNT(*) AS decision_count, COUNT(*) FILTER (WHERE executable) AS executable_count
FROM research.live_trade_decision
GROUP BY as_of_date
ORDER BY as_of_date DESC
LIMIT 5;
```

최신 주문 요청:

```sql
SELECT as_of_date, side, COUNT(*) AS request_count, COUNT(*) FILTER (WHERE executable_now) AS executable_count
FROM research.live_order_request
GROUP BY as_of_date, side
ORDER BY as_of_date DESC, side;
```

최신 주문 제출:

```sql
SELECT as_of_date, submission_status, COUNT(*) AS execution_count
FROM research.live_order_execution
GROUP BY as_of_date, submission_status
ORDER BY as_of_date DESC, submission_status;
```

최신 체결:

```sql
SELECT as_of_date, side, COUNT(*) AS fill_count, SUM(filled_amount) AS filled_amount
FROM research.live_order_fill
GROUP BY as_of_date, side
ORDER BY as_of_date DESC, side;
```

최신 보유 스냅샷:

```sql
SELECT snapshot_date, COUNT(*) AS holding_count, MAX(snapshot_at) AS latest_snapshot_at
FROM research.live_position_snapshot
GROUP BY snapshot_date
ORDER BY snapshot_date DESC
LIMIT 5;
```
