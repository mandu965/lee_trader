# 20260422 실자동매매 운영점검 명령어

## 0. 목적

이 문서는 `실자동매매 운영 적용 절차`를 실제로 따라갈 때 바로 실행할 수 있는 명령만 따로 모아둔 별도 문서입니다.

아래 순서로 보는 것을 기준으로 합니다.

1. 실행 스위치 병목 확인
2. 운영 화면용 산출물 흐름 확인
3. 로그와 상태 파일 확인
4. 정책값 확인
5. 필요 시 재기동

---

## 1. 기본 컨테이너 상태 확인

```powershell
docker compose ps
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

자동매매 관련 컨테이너만 보고 싶을 때:

```powershell
docker compose ps scheduler-auto-buy scheduler-live-account-sync node-api postgres
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

---

## 2. 실행 스위치 병목 확인

### 2-1. 자동매매 스케줄러 최근 로그

```powershell
docker compose logs --tail=200 scheduler-auto-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

실시간으로 볼 때:

```powershell
docker compose logs -f scheduler-auto-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 2-2. 상태 파일 확인

```powershell
Get-Content outputs\auto_ops_auto_buy_scheduler_status.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

같이 보면 좋은 파일:

```powershell
Get-Content outputs\auto_ops_live_account_sync_scheduler_status.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 2-3. 런타임 상태 확인

브라우저나 API 응답 기준으로 아래 항목이 중요합니다.

- `auto_trade_execute`
- `auto_trade_allow_buy`
- `buy_approval_required`
- `confirm_configured`

로컬 API를 직접 확인할 때 예시:

```powershell
Invoke-WebRequest -Uri "http://localhost:3000/api/auto-trading/runtime-status" | Select-Object -ExpandProperty Content
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

메모:

- 포트가 다르면 실제 운영 포트 기준으로 바꿔서 확인합니다.

---

## 3. 운영 화면 흐름 확인용 산출물

### 3-1. gate / intent / preview 확인

```powershell
Get-Content outputs\operational_buy_gate.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content outputs\trade_intents.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content outputs\order_requests_preview.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 3-2. execution 확인

```powershell
Get-Content outputs\order_requests_execution.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 3-3. BUY 승인 파일 확인

```powershell
Get-Content outputs\order_buy_approvals.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

해석 기준:

- `trade_intents` 는 있는데 `order_requests_preview` 가 적다
  추천 이후 정책 필터가 강한 상태 가능성
- `order_requests_preview` 는 있는데 `order_requests_execution` 이 적다
  execute / allow-buy / approval 병목 가능성 큼

## 4. 로그 파일 빠르게 보기

```powershell
Get-Content .\logs\auto_ops_auto_buy_scheduler.log -Tail 100
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content .\logs\auto_ops_live_account_sync_scheduler.log -Tail 100
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content .\logs\node_api.log -Tail 100
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

메모:

- `node_api.log` 파일이 운영 환경에 없으면 `docker compose logs --tail=100 node-api`로 확인합니다.

```powershell
docker compose logs --tail=100 node-api
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

## 5. 정책값 확인 명령

### 5-1. 설정 파일 열기

```powershell
Get-Content config\production_v1.yaml
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 5-2. 핵심 execution policy만 빠르게 찾기

```powershell
Select-String -Path config\production_v1.yaml -Pattern "standard_entry_confidence|extended_entry_confidence|min_entry_confidence|pilot_limited_max_entries|pilot_limited_total_exposure|pilot_limited_position_cap|watch_limited_max_entries|watch_limited_total_exposure|watch_limited_position_cap|sector_cap|theme_cap|cash_minimum|reentry_cooldown_days"
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 5-3. v1 기준으로 확인할 값

현재 우선 점검 대상:

- `pilot_limited_max_entries`
- `pilot_limited_total_exposure`
- `pilot_limited_position_cap`
- `standard_entry_confidence`
- `extended_entry_confidence`
- `min_entry_confidence`

## 6. 장중 수동 검증 명령

실제 주문 경로가 끝까지 도는지 수동으로 확인할 때:

```powershell
docker compose exec -T scheduler-auto-buy python python/submit_live_orders.py --execute --confirm-text LIVE_ORDER --allow-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

실행 직후 확인:

```powershell
Get-Content outputs\order_requests_execution.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content outputs\auto_ops_auto_buy_scheduler_status.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content .\logs\auto_ops_auto_buy_scheduler.log -Tail 100
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

주의:

- 장운영시간이 아닐 때는 주문 API 경로가 정상 확인되지 않을 수 있습니다.
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED` 가 켜져 있으면 approval 파일도 같이 봐야 합니다.

## 7. 재기동 명령

### 7-1. 자동매매 관련 컨테이너 재기동

```powershell
docker compose up -d --build scheduler-auto-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

docker compose up -d --build scheduler-live-account-sync
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

docker compose up -d --build node-api
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

### 7-2. 순차 점검 포함 기동

```powershell
docker compose up -d postgres
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
Start-Sleep -Seconds 65

docker compose up -d --build node-api
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
Start-Sleep -Seconds 65

docker compose up -d scheduler-auto-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
Start-Sleep -Seconds 65

docker compose up -d scheduler-live-account-sync
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

## 8. v1 완화 적용 전후 비교용 핵심 명령

적용 전후에 아래를 같이 비교합니다.

```powershell
Get-Content outputs\trade_intents.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content outputs\order_requests_preview.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }

Get-Content outputs\order_requests_execution.json
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

같이 보면 좋은 로그:

```powershell
docker compose logs --tail=200 scheduler-auto-buy
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
```

운영 해석 기준:

- execution 건수가 늘었는가
- skipped 비중이 줄었는가
- 상위 skip reason이 바뀌었는가
- 신규 진입 종목 수가 늘었는가

---

## 9. 최종 요약

실자동매매 운영 점검은 아래 순서로 보는 것이 가장 효율적입니다.

1. `docker compose ps` 와 `scheduler-auto-buy` 로그 확인
2. `runtime-status` 와 상태 파일 확인
3. `trade_intents -> preview -> execution` 산출물 확인
4. `config/production_v1.yaml` 정책값 확인
5. 필요 시 재기동 또는 장중 수동 검증

한 문장 요약:

`먼저 실행 가능 상태를 확인하고, 그 다음 산출물 흐름과 정책값을 같이 보면서 진입장벽 완화 전후를 비교하는 방식으로 운영한다.`
