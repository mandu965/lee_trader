# 20260422 실자동매매 운영 적용 절차

## 0. 목적

이 문서는 기존 정리 문서를 바탕으로, 실제 운영에서 무엇을 어떤 순서로 확인하고 적용해야 하는지 한 번에 볼 수 있도록 만든 별도 실행 문서입니다.

이 문서의 목표는 아래 3가지입니다.

- 현재 실자동매매가 왜 실제 진입이 적은지 운영 관점에서 확인한다
- 실행 병목과 정책 병목을 분리해서 본다
- `진입장벽완화안 v1`을 어떤 순서로 적용할지 정한다

## 1. 먼저 기억할 핵심

현재 병목은 추천모델 자체보다 아래 두 영역일 가능성이 더 큽니다.

- 실행 스위치 병목

## 3. 1차 점검 절차

### 3-1. 실행 스위치 점검

먼저 실제 서버에서 아래를 확인합니다.

- `AUTO_TRADE_EXECUTE=1` 인가
- `AUTO_TRADE_ALLOW_BUY=1` 인가
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED` 가 너무 강하지 않은가
- `AUTO_TRADE_CONFIRM_TEXT=LIVE_ORDER` 인가

해석 기준:

- `AUTO_TRADE_EXECUTE=0` 이면 preview 중심 상태입니다
- `AUTO_TRADE_ALLOW_BUY=0` 이면 BUY 제출이 막힙니다
- confirm text가 맞지 않으면 실주문 실행이 불가능합니다
- approval이 과하면 preview는 있어도 execution이 안 나올 수 있습니다

### 3-2. 운영 화면 수치 점검

하루 기준으로 아래 숫자를 확인합니다.

- BUY intent 건수
- preview 건수
- execution 건수
- submitted 건수
- skipped 건수
- 상위 skip reason

해석 기준:

- intent는 많은데 preview가 적다
  추천 이후 조건이 너무 강한 상태 가능성
- preview는 많은데 execution이 적다
  execute / allow-buy / approval 병목 가능성 큼
- execution은 있는데 submitted가 적다
  제출 단계 또는 외부 연계 이슈 가능성

### 3-3. 정책값 점검

현재 기준 정책값을 확인합니다.

기준 파일:

## 4. v1 적용 절차

### 단계 1. 실행 병목 먼저 해소

우선 적용 대상:

- `AUTO_TRADE_EXECUTE`
- `AUTO_TRADE_ALLOW_BUY`
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED`
- `AUTO_TRADE_CONFIRM_TEXT`

목표:

- `preview는 있는데 execution이 거의 없는 상태`를 줄인다

완료 기준:

- execution 건수가 이전보다 의미 있게 증가
- skip reason 상위에 실행 스위치 관련 사유 비중 감소

### 단계 2. pilot 한도 완화

그 다음 아래 값을 조정합니다.

- `pilot_limited_max_entries: 4 -> 5`
- `pilot_limited_total_exposure: 0.36 -> 0.45`

이번 단계에서는 유지:

- `pilot_limited_position_cap: 0.12`

목표:

- 실제 신규 진입 종목 수 증가
- 모의투자 top8과 실거래 간 체감 괴리 일부 완화

완료 기준:

- 신규 진입 종목 수 증가
- 과도한 집중 또는 운영 오류 증가 없음

### 단계 3. WATCH는 우선 유지

이번 단계에서는 아래는 유지합니다.

- `watch_limited_max_entries`
- `watch_limited_total_exposure`
- `watch_limited_position_cap`

이유:

- WATCH까지 동시에 크게 바꾸면 원인 해석이 어려워집니다

### 단계 4. confidence는 조건부 검토

pilot 완화 후에도 실진입이 여전히 너무 적으면 아래를 검토합니다.

- `standard_entry_confidence: 76 -> 74`
- `extended_entry_confidence: 70 -> 68`

이번 단계에서는 바로 적용하지 않습니다.

이유:

- confidence는 추천 품질과 직접 연결되는 값이므로 실행 병목을 먼저 제거한 뒤 보는 것이 맞습니다

### 단계 5. cap / cash / cooldown 은 마지막

이번 단계에서는 아래를 유지합니다.

- `sector_cap`
- `theme_cap`
- `cash_minimum`
- `reentry_cooldown_days`

이유:

- 이 항목들은 실행 장벽보다 안전장치 성격이 더 강합니다

## 5. 적용 후 관찰 항목

적용 후 최소 1주일 동안 아래를 같이 봅니다.

- 일별 BUY intent
- 일별 preview
- 일별 execution
- 일별 submitted
- 일별 skipped
- 상위 skip reason 5개
- 실제 신규 진입 종목 수
- 실제 신규 진입 총 비중

운영 메모:

- `추천 부족`인지 `실행 병목`인지 매일 한 줄로 기록
- 전일 대비 증가/감소 원인을 함께 기록

---

## 6. 이번 단계에서 하지 않을 것

이번 1차 적용에서는 아래를 하지 않습니다.

- 추천모델 구조 개편
- feature 대량 추가
- 점수 체계 재설계
- cap / cash / cooldown 전반 완화

이유:

- 지금은 추천 부족보다 실행 부족을 먼저 분리해서 봐야 합니다

---

## 7. 최종 요약

현재 단계에서 실제 운영 순서는 아래가 맞습니다.

1. 실행 스위치 병목을 먼저 확인한다
2. 운영 화면의 intent / preview / execution / submitted 흐름을 본다
3. `pilot_limited_max_entries`, `pilot_limited_total_exposure` 를 1차 완화한다
4. 최소 1주일 관찰한다
5. 그래도 부족하면 confidence를 소폭 조정한다

한 문장 요약:

`실자동매매 운영 적용의 첫 단계는 추천모델 변경이 아니라, 실행 가능 상태를 먼저 확보하고 pilot 한도를 단계적으로 완화하는 것이다.`
