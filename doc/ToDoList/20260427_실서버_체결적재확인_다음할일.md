# 20260427 실서버 체결적재확인 다음할일

- 작성일: 2026-04-27
- 목적: 실제 서버에서 체결 적재가 정상화되는지 확인하고, DB 구조 변경 없이 추가한 정합성 리포트와 UI 연결을 검증한다.
- 전제: 회사 로컬에서는 KIS 실서버 로그와 실제 계좌 체결 조회를 확인할 수 없으므로, 최종 판단은 실제 서버에서 수행한다.

## 1. 내일 실제 서버에서 먼저 할 일

### 1.1 코드 반영

아래 변경 파일이 실제 서버에 반영되어 있어야 한다.

```text
python/sync_live_order_fills.py
python/build_live_trade_consistency_report.py
node/index.js
node/public/live-auto-trading.html
node/public/live-auto-trading.js
```

핵심 변경:

- 체결 조회 시 `broker_org_order_id`를 `ORD_GNO_BRNO`로 전달
- 주문번호별 체결 조회가 비어 있으면 날짜 범위 전체 조회로 fallback
- `outputs/live_trade_consistency_report.json/md` 생성
- `GET /api/live-trade-consistency` 추가
- `live-auto-trading.html`에 `자동매매 정합성` 영역 추가

## 2. 체결 적재 복구 실행

실제 서버에서 아래 명령을 실행한다.

```powershell
python python/sync_live_order_fills.py --query-all --start-date 20260427 --end-date 20260428
```

실행 후 확인 SQL:

```sql
SELECT COUNT(*) AS fill_count
FROM research.live_order_fill;

SELECT request_id, broker_order_id, code, side, filled_qty, filled_price, filled_at, fill_status
FROM research.live_order_fill
ORDER BY filled_at DESC, fill_id DESC;
```

기대:

```text
fill_count >= 8
```

문제 지속:

```text
fill_count = 0
```

## 3. 정합성 리포트 생성

체결 적재 복구 후 아래 명령을 실행한다.

```powershell
python python/build_live_trade_consistency_report.py --as-of-date 2026-04-24
```

생성 파일:

```text
outputs/live_trade_consistency_report.json
outputs/live_trade_consistency_report.md
```

확인 기준:

```text
submitted_count >= 8
filled_count >= 8
submitted_without_fill 비어 있음
warning_count 0 또는 fill 관련 경고 없음
```

문제 지속 기준:

```text
submitted_count >= 8
filled_count = 0
submitted_without_fill 8건 유지
fill 관련 warning 유지
```

## 4. 웹 UI 확인

확인 영역:

정상 화면 기준:

```text

문제 화면 기준:

```

## 5. 문제가 지속될 때 확인할 것

KIS 체결 조회 응답 원본을 확인해야 한다.

확인 포인트:

```text
api_row_count
fill_row_count
inserted_count
outputs/live_order_fills.json
```

특히 아래 컬럼명이 실제 응답에 있는지 확인한다.

```text
odno
orgn_odno
pdno
sll_buy_dvsn_cd_name
sll_buy_dvsn_cd
tot_ccld_qty
ccld_qty
ord_qty
rmn_qty
avg_prvs
avg_pric
ccld_unpr
ord_unpr
tot_ccld_amt
ord_dt
ord_tmd
ccld_tmd
```

가능한 원인:

- KIS 체결 조회에 `ORD_GNO_BRNO`가 필요했음
- 주문번호별 조회는 빈 결과이고 전체 조회만 결과를 반환함
- KIS 응답의 매수/매도 값 또는 체결 수량/가격 컬럼명이 현재 파서와 다름
- 체결은 계좌에 반영됐지만 조회 가능 시간 또는 조회 기간 조건이 다름
