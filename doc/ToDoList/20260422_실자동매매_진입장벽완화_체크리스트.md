# 20260422 실자동매매 진입장벽 완화 체크리스트

## 0. 목적

이 체크리스트의 목적은 `추천모델 고도화`보다 `실자동매매 실행 병목 해소`를 우선순위로 두고, 실제 진입이 왜 막히는지를 일별로 확인하고 단계적으로 완화하기 위한 운영 기준을 만드는 것입니다.

핵심 목표는 아래 3가지입니다.

- 왜 매수가 안 되었는지 숫자로 설명할 수 있게 만든다
- `preview -> execution -> submitted` 전환율을 높인다
- 실거래 데이터를 더 빠르게 쌓을 수 있게 만든다

---

## 1. 현재 해석

현재 실자동매매는 `추천을 많이 만드는 구조`보다 `추천이 있어도 실제 진입을 엄격하게 제한하는 구조`에 가깝습니다.

즉, 지금 우선 확인해야 할 것은 아래 둘 중 어디가 병목인지입니다.

- 추천 자체가 부족한가
- 추천은 있는데 실행 조건 때문에 막히는가

현재 판단으로는 두 번째 가능성이 더 큽니다.

---

## 2. 오늘 바로 확인할 항목

### 2-1. 실행 스위치

아래 값이 실제 서버에서 어떻게 설정되어 있는지 확인합니다.

- `AUTO_TRADE_EXECUTE`
- `AUTO_TRADE_ALLOW_BUY`
- `AUTO_TRADE_BUY_APPROVAL_REQUIRED`
- `AUTO_TRADE_CONFIRM_TEXT`

판단 기준:

- `AUTO_TRADE_EXECUTE=0` 이면 preview-only 상태입니다
- `AUTO_TRADE_ALLOW_BUY=0` 이면 BUY 제출이 불가능합니다
- approval이 과도하면 preview는 있어도 execution이 막힐 수 있습니다

### 2-2. 실행 흐름 수치

하루 기준으로 아래 숫자를 확인합니다.

- BUY intent 건수
- preview 건수
- executable preview 건수
- execution 생성 건수
- submitted 건수
- skipped 건수

판단 기준:

- intent는 많은데 preview가 적으면 추천 이후 조건이 너무 강한 것입니다
- preview는 많은데 execution이 적으면 실행 스위치나 approval 쪽 병목 가능성이 큽니다
- execution은 있는데 submitted가 적으면 주문 제출 단계나 외부 브로커 연계 문제 가능성이 있습니다

### 2-3. 보류 사유 분포

상위 skip reason을 확인합니다.

중점 확인 예시:

- `AUTO_TRADE_EXECUTE=OFF`
- `AUTO_TRADE_ALLOW_BUY=OFF`
- `buy_approval_required`
- `buy_qty_zero`
- `holding_qty_missing`
- `invalid_final_request_qty`
- `duplicate_request_id`

판단 기준:

- 상위 1~2개 사유가 대부분을 차지하면 그 항목이 1차 완화 대상입니다

---

## 3. 이번 주 우선순위

### 3-1. 1순위: execute / allow-buy / approval 점검

먼저 아래를 확인합니다.

- 실제 운영에서 BUY 제출이 가능한 상태인가
- approval 체계가 현재 단계에서 과도하게 강하지 않은가
- confirm text 조건이 실제 운영 절차와 맞는가

실행 목표:

- `preview는 있는데 execution 0` 상태를 줄인다

### 3-2. 2순위: pilot 진입 한도 완화

그 다음 아래 값을 검토합니다.

- `pilot_limited_max_entries`
- `pilot_limited_total_exposure`
- `pilot_limited_position_cap`

현재 권고 방향:

- `pilot_limited_max_entries: 4 -> 5`
- `pilot_limited_total_exposure: 0.36 -> 0.45`
- `pilot_limited_position_cap` 은 우선 유지

실행 목표:

- 실제 신규 진입 종목 수를 늘린다

### 3-3. 3순위: confidence 기준 검토

pilot 완화 후에도 상위 후보가 지나치게 탈락하면 아래 값을 검토합니다.

- `standard_entry_confidence`
- `extended_entry_confidence`
- `min_entry_confidence`

권고:

- 바로 큰 폭으로 내리지 않음
- 먼저 confidence 때문에 탈락하는 비율을 확인한 뒤 소폭 조정

### 3-4. 4순위: cap / cash / cooldown

아래 항목은 v1 단계에서는 유지가 기본입니다.

- `sector_cap`
- `theme_cap`
- `cash_minimum`
- `reentry_cooldown_days`

이유:

- 이 영역은 실행 장벽이라기보다 안전장치 성격이 강합니다

---

## 4. 일별 운영 체크리스트

매일 아래 항목을 체크합니다.

- 오늘 BUY intent 건수 확인
- 오늘 preview 건수 확인
- 오늘 execution 생성 건수 확인
- 오늘 submitted 건수 확인
- 오늘 skipped 건수 확인
- 오늘 상위 skip reason 확인
- 오늘 실제 신규 진입 종목 수 확인
- 오늘 실제 신규 진입 총 비중 확인
- 오늘 gate 상태 분포 확인

운영 메모 기준:

- `추천 부족`인지 `실행 병목`인지 한 줄로 판단 기록
- 전일 대비 진입 증가/감소 원인 기록

---

## 5. 주간 비교 체크리스트

최소 1주일 단위로 아래를 비교합니다.

- 완화 전후 BUY intent 평균
- 완화 전후 preview 평균
- 완화 전후 execution 평균
- 완화 전후 submitted 평균
- 완화 전후 상위 skip reason 변화
- 완화 전후 신규 진입 종목 수 변화
- 완화 전후 신규 진입 총 비중 변화

판단 기준:

- execution과 submitted가 의미 있게 증가했는가
- 과도한 집중이나 오류 증가 없이 진입만 늘었는가
- confidence 조정 없이도 어느 정도 개선이 되었는가

---

## 6. 이번 단계에서 하지 않을 것

현재 우선순위가 아닌 항목은 아래입니다.

- 추천 모델 구조를 크게 바꾸는 것
- feature를 대폭 추가하는 것
- 점수 체계를 다시 설계하는 것
- sector/theme/cash/cooldown 안전장치를 먼저 푸는 것

이유:

- 지금 병목은 추천모델보다 실행단 병목일 가능성이 높습니다
- 추천모델을 먼저 손보면 원인 분리가 더 어려워집니다

---

## 7. 최종 운영 원칙

현재 단계의 운영 원칙은 아래 한 문장으로 정리할 수 있습니다.

`지금은 더 좋은 종목을 찾는 것보다, 이미 찾은 종목이 왜 실제로 집행되지 않는지를 먼저 줄이는 것이 우선이다.`

실행 순서 요약:

1. 보류 사유를 수치로 확인한다
2. execute / allow-buy / approval 병목을 먼저 점검한다
3. pilot 진입 한도를 단계적으로 완화한다
4. 그래도 부족하면 confidence를 소폭 조정한다
5. cap / cash / cooldown은 마지막에 본다
