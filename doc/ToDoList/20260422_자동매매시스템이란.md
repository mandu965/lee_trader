# 20260422 자동매매 시스템이란

## 0. 이 문서의 목적

이 문서는 일반적인 자동매매 시스템이 무엇인지 설명하고,
현재 우리 프로젝트가 그 구조 안에서 어디쯤 와 있는지를 정리하기 위한 문서입니다.

특히 아래 질문에 답하는 것을 목표로 합니다.

1. 자동매매 시스템은 보통 어떤 단계로 구성되는가
2. 현재 우리 시스템은 그 단계 중 어디까지 구현되어 있는가
3. 모의투자 추천 엔진과 실자동매매 실행 엔진은 왜 다르게 보이는가
4. 앞으로 어떤 방향으로 운영 구조를 고도화하는 것이 맞는가

---

## 1. 자동매매 시스템을 한 문장으로 정의하면

자동매매 시스템은
`시장 데이터를 받아 판단하고, 주문을 만들고, 체결 결과와 계좌 상태를 다시 반영하는 반복 루프`
입니다.

이 정의를 풀면 보통 아래 4단계가 있습니다.

1. 입력
   시장 데이터, 계좌 데이터, 주문 가능 상태를 수집합니다.

2. 판단
   신호를 만들고, 어떤 종목을 사고 팔지 결정합니다.

3. 실행
   주문 초안을 만들고, 실제 주문 제출 여부를 판단하고, 브로커 API로 보냅니다.

4. 반영
   체결 결과, 잔고, 미체결 상태, 로그를 다시 시스템 상태에 반영합니다.

좋은 자동매매 시스템은 이 4단계가 분리되어 있으면서도, 서로 정합적으로 연결되어 있어야 합니다.

---

## 2. 자동매매 시스템의 일반 구조

### 2-1. 데이터 수집 단계

자동매매는 먼저 데이터를 받아야 합니다.

대표적으로 필요한 데이터는 아래와 같습니다.

- 가격 데이터
  시가, 고가, 저가, 종가, 거래량

- 장중 데이터
  실시간 가격, 호가, 체결 정보

- 계좌 데이터
  보유 수량, 평균 단가, 주문 가능 금액, 현금

- 주문 데이터
  기존 주문, 미체결, 부분 체결, 체결 완료 상태

- 보조 데이터
  섹터, 테마, 유동성, 이벤트, 리스크 지표

여기서 중요한 것은 단순히 데이터가 많으냐가 아니라,
`판단에 쓰는 데이터와 실행에 쓰는 데이터가 같은 시점 기준으로 맞아 있느냐`
입니다.

---

### 2-2. 신호 생성 단계

데이터가 준비되면 시스템은 이제 `무엇을 할지` 판단합니다.

이 단계의 구현 방식은 크게 세 가지가 많습니다.

- 규칙 기반
  예: RSI, 이동평균, 돌파, 과열 차단

- 점수 기반
  여러 요소를 종합해 최종 점수를 만든 뒤 상위 종목을 고르는 방식

- 모델 기반
  머신러닝/통계 모델로 수익 가능성이나 상위권 진입 가능성을 추정하는 방식

실제 운영 시스템은 위 세 가지를 섞는 경우가 많습니다.

---

### 2-3. 포트폴리오와 리스크 판단 단계

좋은 자동매매는 `무엇을 살까`만 판단하지 않습니다.
그보다 더 중요한 질문은 아래입니다.

- 지금 사도 되는가
- 얼마를 사야 하는가
- 기존 보유와 충돌하지 않는가
- 현금이 충분한가
- 한 섹터/테마에 너무 몰려 있지 않은가

그래서 이 단계에는 보통 아래와 같은 조건이 들어갑니다.

- 최대 보유 종목 수
- 종목당 최대 비중
- 섹터 / 테마 cap
- 현금 최소 비중
- 재진입 제한
- 과열 구간 진입 차단
- 시장 상태에 따른 gate

실전 시스템에서는 신호 엔진보다 이 리스크 / 실행 정책 엔진이 더 중요해지는 경우가 많습니다.

---

### 2-4. 주문 초안과 실제 실행 단계

판단이 끝났다고 바로 주문하는 것은 아닙니다.

보통 아래처럼 한 단계 더 나눕니다.

1. intent 생성
   어떤 종목을 사고 팔고 줄일지 방향을 정합니다.

2. preview 생성
   실제 주문 가능 수량, 차단 사유, 요청 ID를 계산합니다.

3. execution 생성
   실제 주문 제출 결과와 실패 / 보류 / 스킵 사유를 기록합니다.

이 분리가 중요한 이유는,
`추천`과 `실제 주문 가능 상태`는 항상 같지 않기 때문입니다.

예를 들면 아래처럼 중간에서 멈출 수 있습니다.

- 주문 가능 금액 부족
- 최종 수량 0
- 시장 시간 아님
- 확인 텍스트 미설정
- BUY 스위치 OFF
- approval 파일 누락

즉, 실전 자동매매는
`신호가 나왔다 = 바로 주문`
이 아니라,
`신호 -> 주문 초안 -> 실행 가능 여부 재확인 -> 실제 제출`
구조로 보는 것이 맞습니다.

---

### 2-5. 체결과 계좌 반영 단계

자동매매는 주문을 보내는 것으로 끝나지 않습니다.

그 다음이 더 중요합니다.

- 주문이 실제로 제출되었는가
- 체결되었는가, 미체결인가
- 계좌 잔고가 반영되었는가
- 평균 단가와 현금이 갱신되었는가
- 다음 판단에 들어갈 상태가 최신인가

이 루프가 깨지면,
시스템은 이미 샀다고 생각하지만 실제로는 안 샀다거나,
반대로 이미 팔았다고 생각하지만 잔고에는 남아 있는 문제가 생깁니다.

---

## 3. 현재 우리 시스템은 어디까지 와 있는가

현재 시스템은 완전한 무인 전면 자동매매보다는,
`운영 통제가 강한 자동집행 시스템`
에 가깝습니다.

왜냐하면 지금 구조는 이미 아래와 같이 나뉘어 있기 때문입니다.

- 추천 엔진
  ranking, score, confidence, buy candidate 판단

- 실행 정책 엔진
  gate, cap, cash, cooldown, 제한 진입 판단

- 주문 엔진
  intent, preview, execution 분리

- 운영 안전 장치
  execute 스위치, BUY 허용 스위치, approval, confirm text

즉, 이미 단순 추천 시스템은 아니고,
`추천을 실전 운영 규칙 안에서 제한적으로 집행하는 구조`
까지 와 있습니다.

---

## 4. 모의투자와 실자동매매가 왜 다르게 보이는가

현재 가장 많이 헷갈리는 지점은 여기입니다.

겉으로 보기에는 같은 추천 모델을 쓰는 것처럼 보이지만,
모의투자와 실자동매매는 목적이 다릅니다.

### 4-1. 모의투자

모의투자는 보통 아래 질문에 답합니다.

- 오늘 상위 추천 종목은 무엇인가
- top5 / top8 / top10 포트폴리오 성과는 어떤가
- 어떤 범위가 더 잘 맞는가

즉, 모의투자는
`추천 포트폴리오 성과를 보는 구조`
에 가깝습니다.

### 4-2. 실자동매매

실자동매매는 아래 질문에 답합니다.

- 지금 실제 돈으로 신규 진입을 허용해도 되는가
- 추천 종목 중 어떤 종목이 지금 주문 가능 상태인가
- 운영 정책상 지금 몇 종목까지 진입해도 되는가

즉, 실자동매매는
`추천을 바로 다 사는 구조`가 아니라,
`추천을 실제 집행 가능 상태인지 다시 검증하는 구조`
입니다.

---

## 5. 실매수 조건은 모의투자보다 높은가

결론은 `그렇다`입니다.

현재 실자동매매는 모의투자보다 훨씬 더 많은 조건을 통과해야 합니다.

현재 구조를 실무적으로 해석하면 아래와 같습니다.

- 후보군은 `top20`
- 기본 진입 심사군은 `top8`
- `top9~10`은 조건부 확장 심사군
- confidence 기준이 따로 있음
- liquidity / trading value 기준이 따로 있음
- sector / theme cap이 있음
- cash minimum이 있음
- 재진입 cooldown이 있음
- gate 상태가 `BUY_ALLOWED`가 아니면 신규 진입이 제한됨
- 실제 실행 단계에서는 execute / allow-buy / approval 조건이 또 있음

따라서 `max_holdings = 8`이라는 값은
`항상 8종목을 적극적으로 채운다`는 의미가 아닙니다.

그 값은 `최대 상한`일 뿐이고,
실제로 몇 종목이 진입하느냐는 그날 gate와 실행 조건에 따라 달라집니다.

---

## 6. 현재 구조의 장점과 한계

### 6-1. 장점

- 실거래 리스크를 급격히 키우지 않는다
- 추천 문제와 실행 문제를 분리해서 볼 수 있다
- 왜 안 샀는지, 왜 preview에서 멈췄는지 설명할 수 있다
- 제한 진입을 통해 실제 체결 증거를 쌓을 수 있다

### 6-2. 한계

- 모의투자 top8과 실자동매매가 달라 체감상 혼란이 크다
- 추천 모델이 좋아 보여도 실제 매수가 적으면 신뢰가 낮아 보일 수 있다
- 실매수 건수가 적으면 추천 엔진 검증과 실행 엔진 검증이 함께 느려진다

즉, 현재 구조는 안전하지만 설명 비용이 높습니다.

---

## 7. 추천 방향 3안

### A안. 보수 유지형

추천 엔진과 실행 엔진을 지금처럼 분리해서 운영하는 방식입니다.

- 추천은 `top20/top8/top5` 성과 추적과 고도화에 집중
- 실자동매매는 `WATCH/PILOT 제한 진입` 중심 유지

장점:

- 가장 안전하다
- 해석이 분리된다
- 실거래 리스크가 낮다

단점:

- 모의투자와 실매매 차이가 계속 크게 보인다
- 실매수 건수가 적다

### B안. 점진 완화형

가장 현실적인 방향입니다.

- 추천 엔진은 유지
- 실자동매매 조건만 실거래 증거가 쌓일 때 단계적으로 완화
- 예: `pilot max entries`, `total exposure`, `position cap`, 일부 confidence 컷 조정

장점:

- 현재 안전 구조를 유지하면서 실매매 재현도를 높일 수 있다
- 추천 품질 문제와 실행 보수성 문제를 분리한 채 개선할 수 있다

단점:

- 운영 지표를 꾸준히 봐야 한다
- 완화 기준을 문서화해야 한다

### C안. 모의투자 정렬형

실자동매매를 모의투자 `top8`에 최대한 가깝게 맞추는 방식입니다.

- top8이면 실제로도 8종목에 가깝게 채우는 방향
- gate와 제한 조건을 크게 완화하거나 구조를 단순화

장점:

- 모의투자와 실매매 설명이 쉬워진다
- 추천 엔진 성과와 실매매 결과가 더 가까워진다

단점:

- 현재 단계에서는 가장 위험하다
- 추천 품질, 체결 리스크, 장중 실행 리스크가 한꺼번에 커질 수 있다

---

## 8. 현재 시점의 권고안

현재는 `B안. 점진 완화형`이 가장 적절합니다.

이유는 세 가지입니다.

1. 지금 시스템은 이미 추천과 집행을 분리하는 구조로 설계되어 있다
2. 지금 당장 `top8 실매수 정렬형`으로 가면 리스크가 너무 크게 증가한다
3. 그렇다고 현재 구조를 영구적으로 그대로 두면 실매매가 지나치게 보수적으로 남을 수 있다

즉,
`지금은 바로 top8 복제형으로 갈 시점은 아니지만, 영구적으로 pilot 제한만 유지할 단계도 아니다`
라고 보는 것이 맞습니다.

## 9. 실행 순서 권고

### 9-1. 추천 KPI와 실집행 KPI를 분리

추천 KPI 예시:

- top20 평균 성과
- top8 평균 성과
- top5 평균 성과
- hit rate / drawdown / ordering

실집행 KPI 예시:

- 추천 후보 수
- preview 생성 수
- execution 제출 수
- 보류 사유 분포
- 실제 체결 후 성과

### 9-2. 매일 운영 화면에서 같이 볼 것

아래 네 줄은 매일 같이 봐야 합니다.

- 추천 후보 수
- preview 가능 수
- 실제 제출 수
- 보류 사유 상위 항목

이렇게 해야
`추천이 약한 날`과
`실행 조건이 너무 강한 날`
를 구분할 수 있습니다.

### 9-3. 완화는 단계적으로

실거래가 일정 수준 쌓였을 때만 아래 순서로 완화하는 것이 좋습니다.

1. `pilot max entries`
2. `total exposure`
3. `position cap`
4. 일부 confidence 조건

한 번에 크게 바꾸기보다,
운영 안정성을 유지하면서 천천히 푸는 것이 맞습니다.

---

## 10. 최종 정리

현재 시스템은
`모의투자 top8을 그대로 실자동매매에 복제하는 구조`가 아니라,
`top20 -> top8/top10 추천을 기반으로 gate, confidence, liquidity, cap, execution safety 조건을 통과한 일부만 제한적으로 집행하는 보수형 실자동매매 구조`
입니다.

따라서 현재 추천 방향은
`모의투자 추천 엔진은 유지·고도화하고, 실자동매매는 파일럿 제한 집행으로 운영하면서 실거래 증거가 쌓일 때만 점진적으로 완화하는 방향`
이 가장 적절합니다.
