# 20260427 DB변경없는 자동매매 정합성 리포트

- 작성일: 2026-04-27
- 목적: 실제 서버 DB 구조를 바꾸지 않고, 기존 `research.live_*` 테이블을 읽어서 자동매매 흐름의 정합성을 점검하는 산출물을 추가한다.
- 배경: `research.live_order_execution`에는 submitted 주문 8건이 있으나, 실제 서버의 `research.live_order_fill` 적재는 내일 서버 산출물로 재확인해야 한다.

## 2. 리포트가 확인하는 내용

- 기준일의 판단 건수
- 주문 요청 건수
- 실행 가능 주문 요청 건수
- 주문 제출 결과 건수
- submitted / failed / skipped 건수
- 체결 적재 건수
- submitted 되었지만 fill이 없는 주문 목록
- request는 있지만 execution이 없는 주문 목록
- 최신 보유 스냅샷 기준일
- 운영 경고 메시지

## 3. 로컬 실행 결과

실행 명령:

```powershell
python python/build_live_trade_consistency_report.py --as-of-date 2026-04-24
```

로컬 결과:

```text
intent_count: 10
request_count: 8
executable_request_count: 8
execution_count: 11
submitted_count: 8
failed_count: 3
filled_count: 0
warning_count: 2
```

경고:

```text
Submitted broker orders exist, but no fill rows exist for the basis date.
8 submitted broker orders have no matching fill row.
```

해석:

- 현재 로컬 데이터 기준으로는 `execution`까지는 확인된다.
- `fill`은 아직 로컬에 적재된 데이터가 없으므로, 실제 서버에서 체결 조회 적재가 정상화되는지 내일 확인해야 한다.
- 이 경고는 현재 상황에서 정상적으로 잡힌 것이다.

## 4. 실제 서버에서 이어서 할 일

먼저 보강된 체결 조회 로직을 반영한다.

관련 파일:

```text
python/sync_live_order_fills.py
```

보강 내용:

- 주문번호별 체결 조회 시 `broker_org_order_id`를 `ORD_GNO_BRNO`로 같이 전달
- 주문번호별 조회 결과가 비어 있으면 날짜 범위 전체 체결 조회로 fallback
- KIS 응답의 `매수`, `매도` 값을 명시적으로 인식

서버에서 체결 조회 복구 실행:

```powershell
python python/sync_live_order_fills.py --query-all --start-date 20260427 --end-date 20260428
```

서버에서 정합성 리포트 생성:

```powershell
python python/build_live_trade_consistency_report.py --as-of-date 2026-04-24
```

확인 파일:

```text
outputs/live_trade_consistency_report.md
outputs/live_trade_consistency_report.json
```

## 5. 내일 판단 기준

정상:

```text
submitted_count >= 8
filled_count >= 8
submitted_without_fill 비어 있음
warning_count 0 또는 fill 관련 경고 없음
```

문제 지속:

```text
submitted_count >= 8
filled_count = 0
submitted_without_fill 8건 유지
```

문제가 지속되면 다음을 확인한다.

- KIS `inquire-daily-ccld` 응답 원본 row 수
- `ODNO`, `PDNO`, `SLL_BUY_DVSN_CD`, `TOT_CCLD_QTY`, `AVG_PRVS` 또는 유사 체결가 컬럼명
- `ORD_GNO_BRNO` 없이 조회할 때와 포함할 때의 차이
- `--query-all` 결과와 주문번호별 조회 결과 차이

## 6. 이후 확장 후보

DB 변경 없이 다음 단계로 확장 가능하다.

- `ops-readiness.html` 또는 `live-auto-trading.html`에서 정합성 리포트 표시
- `warning_count > 0`이면 자동매매 화면에 경고 배지 표시
- `submitted_without_fill`이 있으면 신규 BUY를 preview-only로 낮추는 정책 검토
- 정합성 리포트를 `sync_web_display_data.py`의 payload 동기화 대상에 추가

단, 마지막 항목은 웹 DB payload 저장을 사용하므로 실제 서버 적용 시 동기화 대상과 운영 의도를 다시 확인한다.
