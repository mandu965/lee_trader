# 20260421 모의투자 방식

## 1. 목적

이 문서는 현재 프로젝트에 구현된 `모의투자(paper trading)` 방식이 어떻게 동작하는지 정리한 문서입니다.

이 모의투자는 실주문을 보내는 기능이 아니라,

- 일별 추천 결과를 기준으로
- 정해진 규칙으로 가상 포지션을 열고
- 일정 보유 기간 이후 청산하며
- NAV / 수익률 / 드로다운 / 승률을 추적

하는 운영 검증용 시뮬레이션 레이어입니다.

핵심 목적은 다음과 같습니다.

- 추천 로직이 실제 운용 전에 어떤 흐름으로 누적 성과를 만드는지 확인
- `top5 / top8 / top10` 전략별 차이를 같은 규칙으로 비교
- 운영 산출물과 웹 화면에서 참고할 수 있는 실적 트랙 레코드 제공

## 3. 입력 데이터

모의투자는 다음 입력을 사용합니다.

### 3.1 일별 랭킹 스냅샷

- 경로: `data/history/ranking/*_ranking_final.csv`
- 역할: 각 날짜별 후보 종목 집합 생성의 원천

`run_paper_trading_ledger.py`는 과거 랭킹 스냅샷을 순서대로 읽고, 각 날짜에 대해 다시 후보를 뽑습니다.

### 3.2 가격 패널

- 기본 경로: [data/prices_daily_adjusted.csv](/d:/ai/lee_trader/data/prices_daily_adjusted.csv)
- 역할: 진입/청산 가격 및 일별 NAV 계산

조정종가 기준 패널을 사용해 각 종목의 진입일 가격과 이후 평가가격을 계산합니다.

### 3.3 후보 선택 규칙

모의투자용 후보도 별도 수동 정의가 아니라 실제 추천 후보 생성 로직을 재사용합니다.

관련 함수:

- `normalize_input`
- `select_candidates`
- `cap_count`

즉, 모의투자는 “그날 그날의 랭킹 결과를 바탕으로 실제 운영과 유사한 방식으로 종목을 고른 뒤 추적”하는 구조입니다.

## 4. 전략 단위

현재 모의투자는 아래 3개 전략을 동시에 계산합니다.

- `top5`
- `top8`
- `top10`

코드 상 기본값:

즉 각 날짜마다 동일한 입력 스냅샷으로

- top5 포트폴리오
- top8 포트폴리오
- top10 포트폴리오

를 각각 독립적으로 추적합니다.

## 5. 기본 진입 방식

### 5.1 신규 진입

각 날짜의 랭킹 스냅샷에서 전략별 목표 종목 수(`5/8/10`)에 맞는 후보를 선택합니다.

신규 종목은 아래 의미의 액션 코드로 기록됩니다.

- `BUY_NEW_COHORT`
- reason: `selected_from_daily_snapshot`

관련 상수:

- [python/run_paper_trading_ledger.py](/d:/ai/lee_trader/python/run_paper_trading_ledger.py)

### 5.2 교체 진입

옵션으로 `replacement_mode`가 있으면, 기존 포지션이 빠진 자리를 후속 후보가 채울 수 있습니다.

관련 코드:

- `BUY_REPLACEMENT`
- reason: `filled_vacancy_after_exit`

즉 현재 구현은 단순 “한 번 사고 끝”이 아니라,

- 기본 모드: 코호트형 진입 후 보유기간 추적
- 교체 모드: 빠진 자리 재진입 허용

둘 다 지원하도록 설계돼 있습니다.

## 6. 보유 방식

현재 보유 정책 코드는 고정 보유기간 기반입니다.

- `HOLDING_POLICY_CODE = FIXED_HOLD_TRADING_DAYS`

기본 보유일:

- `--hold-days`
- 기본값 `20`

즉 현재 기본 모의투자 방식은 다음과 같습니다.

1. 진입일에 포지션을 엽니다.
2. 이후 거래일 기준으로 보유일을 누적합니다.
3. 기본적으로 `20 거래일` 보유를 목표로 합니다.
4. 중간에 특정 조기 청산 조건이 발생하면 먼저 종료할 수 있습니다.

---

## 7. 보유 중 상태 코드

보유 중인 포지션은 단순 OPEN 외에도 운영 해석을 위한 상태 코드가 붙습니다.

예시:

- `HOLD_ACTIVE`
- `HOLD_NEW_ENTRY`
- `HOLD_REVIEW_SOON`
- `EXIT_REVIEW_SOON`

의미는 대략 다음과 같습니다.

- `HOLD_NEW_ENTRY`: 새로 진입한 포지션
- `HOLD_ACTIVE`: 일반적인 보유 상태
- `HOLD_REVIEW_SOON`: 보유기간 종료가 가까운 상태
- `EXIT_REVIEW_SOON`: 청산 시점에 근접한 상태

이 값들은 포지션 CSV와 DB 테이블에서 함께 관리됩니다.

## 8. 청산 방식

현재 구현은 `20 거래일 보유 후 청산`이 기본이지만, 아래 조기 종료 조건도 있습니다.

### 8.1 기본 청산

- `EXIT_HOLD_D20`
- reason: `planned_holding_period_reached`

### 8.2 손절 기반 청산

- `EXIT_STOP_LOSS`
- reason: `loss_below_minus_8pct`

즉 평가손익이 `-8% 이하`로 내려가면 계획 보유일보다 먼저 청산할 수 있습니다.

### 8.3 confidence 기반 청산

- `EXIT_CONFIDENCE_BLOCK`
- reason: `confidence_below_55`

### 8.4 점수 약화 기반 청산

- `EXIT_SCORE_WEAK`
- reason: `final_score_below_45`

### 8.5 랭크 약화 기반 청산

- `EXIT_RANK_FADE`
- reason: `rank_outside_top10_with_confidence_weak`

즉 현재 모의투자는 “무조건 20일 보유”가 아니라,

- 기본은 20일 보유
- 다만 손실 악화, confidence 붕괴, 점수 약화, 랭크 이탈 등은 조기 종료

로 구현되어 있습니다.

## 9. 가격 및 체결 가정

현재 모의투자는 실제 호가 체결 시뮬레이터가 아니라 단순화된 체결 가정을 사용합니다.

설정 인자:

- `initial_nav`
- `entry_fee_bps`
- `exit_fee_bps`
- `entry_slippage_bps`
- `exit_slippage_bps`

기본값:

- 초기 자산 `1,000,000`
- 수수료 `0`
- 슬리피지 `0`

즉 현재 기본 모드는

- 조정종가 기반 진입/청산
- 비용 0 가정
- 슬리피지 0 가정

에 가깝습니다.

실전과 동일한 체결 모델이라기보다, 전략 비교를 위한 기준선 시뮬레이션입니다.

## 13. 현재 방식의 해석

현재 모의투자는 아래 성격으로 이해하면 됩니다.

- 실시간 체결 기반이 아님
- 장중 주문 시뮬레이터가 아님
- 랭킹 스냅샷 기반의 일별 포트폴리오 추적
- 고정 보유기간 + 조기 종료 규칙을 갖는 운영 검증용 백테스트/레جر 중간 형태

즉 “완전한 체결 엔진”보다는

- 일별 추천이 실제로 누적 성과를 만들 수 있는지
- top5/top8/top10 중 무엇이 더 안정적인지
- 손절/조기종료 규칙이 결과에 어떤 영향을 주는지

를 보기 위한 운영용 모의계좌입니다.

---

## 14. 현재 한계

현재 구현에는 아래 한계가 있습니다.

### 14.1 실제 체결 환경 미반영

- 호가 공백
- 거래량 충격
- 장중 슬리피지
- 부분 체결

을 정교하게 반영하지 않습니다.

### 14.2 장중 intraday 의사결정 미반영

현재 방식은 일별 스냅샷 중심입니다.

즉 실제 장중 조건 변화에 따른 즉시 매수/매도 판단과는 다릅니다.

### 14.3 실계좌 보유/현금과 직접 연결되지 않음

모의투자는 독립 가상 계좌입니다.

- 실계좌 `live_account_holdings.csv`
- 실제 주문 결과

와 직접 합산되지 않습니다.

### 14.4 기본 비용 가정이 0

기본 설정은 수수료와 슬리피지가 0이라, 실전보다 성과가 다소 낙관적으로 나올 수 있습니다.

## 15. 실무 해석 가이드

현재 모의투자 결과는 아래처럼 해석하는 것이 적절합니다.

- `paper_trading_nav` 상승: 추천 규칙이 누적 성과 가능성을 보임
- `drawdown` 과도: 전략이 실전 투입 전 방어 보강 필요
- `closed_win_rate` 낮음: 후보 선택 또는 exit 규칙 재검토 필요
- `top5 / top8 / top10` 차이: 집중도와 분산도 간 운영 trade-off 판단 자료

즉 모의투자는 “실전 매수 허가 버튼”이 아니라, 실전 전 검증 증거를 축적하는 계층입니다.
