# Lee_trader 프로젝트 통합 문서 v1

## 1. 문서 목적

이 문서는 Lee_trader 프로젝트에 흩어져 있는 개념, 실행 흐름, 운영 포인트를 하나로 묶어 이해하기 쉽게 정리한 통합본입니다.

이 문서의 목표는 다음 3가지입니다.

1. 프로젝트 전체 구조를 한 번에 이해한다.
2. 자동매매와 추천 시스템이 어디까지 구현되어 있는지 구분한다.
3. 앞으로 개발/운영/검증 시 어떤 문서를 기준점으로 삼아야 하는지 정한다.

---

## 2. 프로젝트 한 줄 정의

Lee_trader는 **국내 주식 추천 점수 산출 + 포트폴리오 판단 + 자동주문 준비/실행**을 목표로 하는 데이터 기반 투자 시스템입니다.

즉, 단순한 종목 추천 웹이 아니라 아래 3개 층으로 구성됩니다.

* **분석 층**: 가격, 재무, 테마, 팩터, regime, gate 등을 반영해 종목 점수 계산
* **판단 층**: 어떤 종목을 BUY / HOLD / TRIM / EXIT 할지 의사결정 생성
* **집행 층**: 계좌 잔고를 조회하고 실제 주문 요청으로 변환하여 브로커 API에 제출

## 4. 핵심 질문으로 이해하는 시스템

### Q1. 이 프로젝트의 본질은 무엇인가?

**추천 종목 웹서비스**이면서 동시에 **반자동/자동매매 운영 시스템**입니다.

### Q2. 웹 화면에 추천이 잘 나오면 자동매매도 완성된 것인가?

아닙니다.
추천 산출과 실주문은 별도 단계입니다.

* 추천이 잘 나오는 상태 = 분석 엔진이 작동
* BUY/EXIT intent가 나오는 상태 = 판단 엔진이 작동
* preview가 제출 가능 상태 = 주문 직전까지 도달
* execution 결과가 존재 = 실제 제출 시도

### Q3. 자동매매에서 가장 많이 착각하는 지점은?

`Trade Intents`, `Order Requests Preview`가 정상적으로 보이면 자동매매가 완성된 것으로 느끼기 쉽습니다.
하지만 실제로는 마지막 제출 단계가 따로 있습니다.

## 5. 배치와 자동주문의 관계

### 5.1 종가 배치

종가 배치는 다음날 장 시작 전 의사결정의 재료를 준비하는 분석 파이프라인입니다.

주요 역할:

* 시세/재무/테마 데이터 업데이트
* 점수 계산
* 추천 랭킹 생성
* 포트폴리오 판단용 입력 생성

즉, **무엇을 살지/보유할지/줄일지 판단할 재료를 준비**합니다.

### 5.2 auto-buy 스케줄

auto-buy 스케줄은 종가 배치 결과를 읽어 **실제 주문 후보**로 바꾸는 집행 레이어입니다.

주요 역할:

* trade intent 생성/갱신
* 실계좌 holdings 동기화
* 주문 가능 수량 계산
* preview 생성
* 필요 시 실제 주문 제출

즉, **분석 결과를 브로커 주문으로 옮기는 단계**입니다.

## 7. 자동매매 상태를 구분하는 기준

### 상태 A. 추천만 정상

조건:

* 랭킹/추천 화면은 정상
* trade intent 없음 또는 미확인

의미:

* 분석 엔진만 정상

### 상태 B. 판단까지 정상

조건:

* `trade_intents.json` 존재
* BUY/HOLD/TRIM/EXIT 생성

의미:

* 분석 + 판단 엔진 정상

### 상태 C. 주문 직전까지 정상

조건:

* `order_requests_preview.json` 존재
* 제출 가능 상태
* request_qty / allowed_qty 확인 가능

의미:

* 자동주문 직전까지 정상
* 아직 실주문은 아님

### 상태 D. 실제 주문 시도

조건:

* `order_requests_execution.json` 존재
* 제출/스킵/실패 결과가 남음

의미:

* 실주문 단계 진입

### 상태 E. 실전 자동매매 운영 완료

조건:

* auto-buy 스케줄러 안정적 가동
* holdings 동기화 정상
* preview → execution → 브로커 응답 → 후속 검증 루프까지 정착

의미:

* 운영 레벨 자동매매에 근접

## 8. 이 프로젝트에 탑재된 핵심 개념

### 8.1 Score 계열

* **probability score**: 성공 확률/승률 성격의 점수
* **return score**: 기대수익 성격의 점수
* **confidence score**: 예측 신뢰도/사용 적합성 점수
* **quality score**: 재무 품질, 펀더멘털 안정성 성격의 점수
* **final score**: 여러 점수를 결합한 최종 랭킹 점수

### 8.2 Regime

시장 상태를 구분하는 레짐 개념입니다.
예:

* bull
* neutral
* defensive

같은 종목이라도 regime에 따라 가중치, 패널티, gate가 달라질 수 있습니다.

### 8.3 Gate

진입 허용/차단 규칙입니다.
예:

* 신규 진입 차단
* 약한 종목 비중 축소
* defensive 상황에서 더 강한 제한

### 8.4 Overlay

기본 점수 위에 추가로 영향을 주는 보정층입니다.
예:

* theme overlay
* quality downside gate
* shadow 비교 로직

### 8.5 Trade Intent

전략 판단의 최종 액션 분류입니다.
예:

* BUY
* HOLD
* TRIM
* EXIT
* REVIEW

이 단계는 아직 주문이 아니라 **전략 행동 정의**입니다.

### 8.6 Order Preview

실제 주문 직전 초안입니다.
주로 아래를 확인합니다.

* request_qty
* allowed_qty
* final_request_qty
* blocked_reason
* executable_now

### 8.7 Execution

브로커 API 호출 결과입니다.
이 단계에서야 비로소 실제 주문 시도가 이루어집니다.

## 9. 환경변수 개념 정리

자동매매에서 특히 중요한 값은 다음입니다.

* `AUTO_TRADE_EXECUTE`

  * 실제 주문 실행 여부
* `AUTO_TRADE_ALLOW_BUY`

  * BUY 허용 여부
* `AUTO_TRADE_CONFIRM_TEXT`

  * 실주문 안전 확인 문자열
* `AUTO_TRADE_BUY_APPROVAL_REQUIRED`

  * BUY 승인 파일 요구 여부
* `KIS_BASE_URL`

  * 모의투자/실거래 URL 구분
* `KIS_CANO`

  * 계좌번호
* `KIS_ACNT_PRDT_CD`

  * 계좌 상품코드

핵심 해석:

* preview가 있어도 execute가 꺼져 있으면 실제 주문 안 나감
* BUY 허용이 꺼져 있으면 매도만 가능하거나 BUY는 스킵됨
* approval required가 켜져 있으면 승인 파일 없이는 매수 안 나감

## 16. 현재 시점의 한 줄 결론

Lee_trader는 단순 추천 앱이 아니라, **분석 → 판단 → 주문 집행**까지 연결하려는 투자 시스템입니다.

따라서 공부도 반드시 이 3단계로 나눠서 해야 하며,
특히 `preview`와 `execution`을 명확히 구분하는 것이 가장 중요합니다.
