# Lee_trader 점수 체계 통합본 v1

## 1. 문서 목적

이 문서는 Lee_trader 프로젝트의 **점수 체계(score system)**를 한 곳에 모아 이해하기 위한 통합 문서입니다.

이 문서의 목표는 아래와 같습니다.

1. 점수가 왜 필요한지 이해한다.
2. 각 점수의 역할을 구분한다.
3. 최종 랭킹이 어떤 철학으로 만들어지는지 정리한다.
4. 신뢰도와 추천 점수를 문서 수준에서 설명 가능하게 만든다.
5. 앞으로 코드/산출물/운영 결과를 같은 기준으로 해석하게 만든다.

---

## 2. 이 프로젝트에서 점수란 무엇인가

Lee_trader에서 점수는 단순한 숫자가 아니라 **매수 우선순위를 정하기 위한 의사결정 언어**입니다.

즉, 점수는 아래 질문에 답하기 위해 존재합니다.

* 이 종목은 올라갈 가능성이 높은가?
* 기대수익이 큰가?
* 품질이 나쁘지 않은가?
* 지금 시장 상태에서 진입해도 되는가?
* 이 결과를 실제 추천으로 써도 될 만큼 신뢰할 수 있는가?

따라서 점수 체계는 단일 지표가 아니라, 여러 층을 거쳐 최종 점수로 결론이 나는 구조로 이해해야 합니다.

---

## 3. 점수 체계의 큰 구조

이 프로젝트의 점수 체계는 크게 아래 5개 층으로 이해하면 됩니다.

### 3.1 원천 특성층

가격, 수급, 재무, 테마, 변동성, 추세, 상대강도 같은 원천 데이터가 들어오는 층입니다.

예시:

* 가격 모멘텀
* 거래대금
* 변동성
* 재무 안정성
* 섹터/테마 강도
* 시장 상태(regime)

### 3.2 개별 점수층

원천 특성을 사람이 이해 가능한 주요 점수로 묶는 층입니다.

대표 점수:

* probability score
* return score
* confidence score
* quality score

### 3.3 결합 점수층

개별 점수들을 조합해 최종 랭킹에 가까운 점수로 묶는 층입니다.

대표 개념:

* baseline score
* final score
* weighted combination

### 3.4 보정층

시장 상황과 리스크를 반영해 점수를 보수적으로 조정하는 층입니다.

대표 개념:

* regime
* gate
* overlay
* cap
* downside penalty

### 3.5 의사결정층

최종 점수가 단순 숫자로 끝나는 것이 아니라 실제 액션으로 번역되는 층입니다.

대표 결과:

* BUY
* HOLD
* TRIM
* EXIT

## 4. 핵심 점수 4종 정리

## 4.1 Probability Score

### 정의

해당 종목이 향후 기대 방향으로 움직일 **성공 확률** 또는 **승률 성격**을 나타내는 점수입니다.

### 역할

* “맞을 가능성”을 판단하는 축
* 추천 후보의 안정성을 가늠하는 1차 기준
* 단순 고수익 후보보다 **확률적으로 우세한 후보**를 골라내는 데 사용

### 높을수록 의미하는 것

* 모델 또는 규칙 기반 판단상 우호적 신호가 많다
* 단기/중기 방향성이 기대 방향과 일치할 가능성이 높다
* 진입 후보로서의 설득력이 올라간다

### 낮을수록 의미하는 것

* 신호가 약하거나 혼재되어 있다
* 방향 판단이 애매하다
* 추천 우선순위가 밀릴 수 있다

### 해석 주의점

Probability score가 높다고 해서 반드시 기대수익이 큰 것은 아닙니다.
즉,

* **잘 맞을 가능성**과
* **많이 오를 가능성**은
  서로 다른 축입니다.

---

## 4.2 Return Score

### 정의

해당 종목이 기대 기간 동안 만들어낼 수 있는 **기대수익의 크기**를 나타내는 점수입니다.

### 역할

* “얼마나 먹을 수 있는가”를 판단하는 축
* 승률은 다소 낮더라도 수익 기대값이 큰 종목을 발굴하는 데 사용
* 랭킹의 공격성을 결정하는 핵심 축 중 하나

### 높을수록 의미하는 것

* 상승 여력 또는 기대 payoff가 크다
* 추세 확장 가능성이나 레버리지가 크다
* 공격적 포트폴리오에서 우선순위가 높아질 수 있다

### 낮을수록 의미하는 것

* 방향은 좋아도 기대수익이 작다
* 이미 많이 오른 뒤일 수 있다
* 보수적 관점에서는 홀드용일 수 있지만 신규 진입 매력은 낮을 수 있다

### 해석 주의점

Return score가 높아도 probability score가 낮으면
**고위험 고보상** 후보일 수 있습니다.

즉,

* return만 높으면 “매력적이지만 불안한 후보”
* probability만 높으면 “안정적이지만 둔한 후보”
  가 될 수 있습니다.

---

## 4.3 Confidence Score

### 정의

현재 산출된 예측/추천 결과를 **얼마나 신뢰할 수 있는지**를 나타내는 점수입니다.

### 역할

* 사용자에게 보여주는 추천의 품질 안전장치
* 같은 final score라도 신뢰도 낮은 후보를 걸러내는 기준
* 자동매매/추천 시스템에서 매우 중요한 운영 지표

### 왜 중요한가

Lee_trader의 최종 목표는 단순 추천이 아니라 **신뢰 가능한 추천**입니다.
따라서 confidence score는 단순 부가 점수가 아니라, 실제 서비스화에서 핵심 지표가 됩니다.

### 높을수록 의미하는 것

* 신호 간 충돌이 적다
* 데이터 결측/왜곡이 적다
* 예측 근거가 상대적으로 일관적이다
* 추천 결과를 사용자에게 제시하기 좋다

### 낮을수록 의미하는 것

* 결과가 불안정할 수 있다
* 데이터 품질 또는 모델 일관성이 약하다
* 점수는 높아 보여도 실제 사용에 주의가 필요하다

### 실무적 해석

confidence score는 아래 같은 용도로 쓰기 좋습니다.

* UI에서 경고 표시
* 자동매매 진입 제한
* 최종 추천 종목 노출 제한
* 상위 랭킹 중 신뢰도 미달 종목 제외

---

## 4.4 Quality Score

### 정의

재무 품질, 펀더멘털 안정성, 기업 체력 같은 **기초 체력**을 나타내는 점수입니다.

### 역할

* 점수가 좋더라도 재무적으로 너무 약한 종목을 걸러내는 축
* speculative 후보를 적절히 억제하는 역할
* defensive / neutral 상황에서 특히 중요

### 높을수록 의미하는 것

* 재무 구조가 상대적으로 건전하다
* 급격한 훼손 가능성이 낮다
* 중장기적으로 더 안정적인 후보일 수 있다

### 낮을수록 의미하는 것

* 단기 수급으로 올라갈 수는 있어도 기초 체력이 약하다
* 급락 또는 실적 훼손 위험이 더 크다
* quality downside gate의 대상이 되기 쉽다

### 실무적 의미

quality score는 수익을 높이는 점수라기보다,
**망가질 수 있는 종목을 덜 사게 만드는 점수**에 가깝습니다.

---

## 5. 점수들 사이의 관계

이 네 점수는 서로 경쟁하는 것이 아니라, 서로 보완합니다.

### 5.1 probability vs return

핵심 차이:

* probability = 맞을 확률
* return = 맞았을 때 얼마나 크게 갈지

따라서 좋은 종목은 보통 아래 둘 중 하나입니다.

* probability와 return이 둘 다 높은 종목
* 둘 중 하나가 아주 강하고, 다른 하나도 치명적으로 낮지 않은 종목

### 5.2 confidence의 위치

confidence는 방향이나 수익 자체를 뜻하지 않습니다.
대신 **그 판단을 얼마나 믿어도 되는지**를 말합니다.

즉,

* probability/return = 내용
* confidence = 그 내용의 신뢰성

### 5.3 quality의 위치

quality는 현재 수익 기대보다 **하방 위험과 구조적 취약성**에 더 가깝습니다.

즉,

* probability/return = 공격 축
* confidence/quality = 방어 축

이 4개를 같이 봐야 시스템이 균형을 갖습니다.

---

## 6. 최종 점수 철학

Lee_trader의 final score는 단순 평균이 아니라 **공격성과 신뢰성 사이의 균형점**으로 이해해야 합니다.

최종 점수 철학은 아래와 같습니다.

1. 오를 가능성이 있는 종목을 본다.
2. 기대수익이 충분한 종목을 본다.
3. 그런데 결과를 믿을 수 있어야 한다.
4. 그리고 재무적으로 너무 나쁜 종목은 억제한다.
5. 마지막으로 시장 상황에 맞게 보정한다.

즉, final score는 “가장 높이 오를 종목”만 찾는 점수가 아니라,
**실제로 추천/매수 후보로 사용할 만한 종목을 고르는 점수**입니다.

---

## 7. Baseline Score와 Final Score

## 7.1 Baseline Score

보정 전의 기본 점수라고 이해하면 됩니다.

의미:

* 개별 점수들을 1차 결합한 값
* 종목의 본질적 매력도에 가까운 값
* regime, overlay, gate 등 운영 보정 전 기준점

### 왜 필요한가

baseline이 있어야 나중에

* overlay가 얼마나 영향을 줬는지
* penalty가 얼마나 강했는지
* 특정 regime에서 얼마나 눌렸는지
  를 비교할 수 있습니다.

## 7.2 Final Score

최종 추천/랭킹에 반영되는 점수입니다.

의미:

* baseline에 여러 운영 보정이 반영된 결과
* 실제 UI 노출, 포트폴리오 판단, trade intent 생성에 가까운 점수

### 해석 포인트

같은 종목이라도

* baseline은 높은데 final이 낮으면
  → 보정층에서 눌린 것
* baseline과 final이 비슷하면
  → 보정 영향이 크지 않은 것
* final이 상대적으로 올라가면
  → overlay나 regime상 우호적 영향을 받은 것

---

## 8. Regime이 점수에 미치는 영향

Regime은 시장 상태를 구분하는 틀입니다.

대표 예시:

* bull
* neutral
* defensive

### regime이 필요한 이유

같은 종목도 시장 상황에 따라 해석이 달라집니다.
예를 들어:

* bull에서는 공격적 종목이 더 유리할 수 있음
* defensive에서는 품질과 안정성이 더 중요할 수 있음

### regime이 점수에 주는 실제 영향

* 특정 점수의 가중치 변화
* quality penalty 강도 변화
* 신규 진입 gate 강도 변화
* overlay 허용 범위 변화

즉, regime은 단순 라벨이 아니라
**점수 체계의 가중치 환경 설정값**입니다.

---

## 9. Gate가 점수에 미치는 영향

Gate는 “좋아 보여도 지금은 막는다”는 규칙입니다.

### 역할

* 무리한 신규 진입 방지
* 리스크 높은 상태에서 진입 제한
* 포지션 과집중 방지
* 섹터 과집중 방지

### 대표 사례

* 신뢰도 부족으로 신규 진입 금지
* position cap 초과
* sector cap 초과
* defensive 상황에서 gate 강화

### 중요한 해석

Gate는 점수를 다시 계산하는 것이라기보다,
**좋은 점수를 실제 행동으로 연결할지 막을지 결정하는 안전장치**입니다.

즉,

* 점수는 높을 수 있다
* 그런데 gate 때문에 BUY는 막힐 수 있다

이 차이를 반드시 구분해야 합니다.

---

## 10. Overlay가 점수에 미치는 영향

Overlay는 기본 점수 위에 추가로 덧입히는 보정층입니다.

대표 예시:

* theme overlay
* shadow 비교 보정
* asymmetric uplift
* positive only overlay

### 역할

* 원래 점수 체계가 놓치는 컨텍스트를 추가 반영
* 특정 테마 강도나 운영 판단을 후반부에 반영
* baseline과 final 사이에 설명 가능한 차이를 만드는 장치

### 해석 원칙

overlay는 강력하지만 과도하면 안 됩니다.
왜냐하면 overlay가 너무 강하면:

* 기본 점수 체계 철학이 흐려지고
* 설명 가능성이 떨어지고
* acceptance 검증이 어려워집니다.

즉, overlay는 **보조 엔진**이어야지 **본체를 뒤엎는 엔진**이 되면 안 됩니다.

---

## 11. Quality Downside Gate의 의미

이 프로젝트에서 quality downside gate는 매우 중요합니다.

### 본질

quality score가 낮은 종목에 대해 final score를 깎거나 불리하게 만드는 하방 방어 장치입니다.

### 필요한 이유

실전에서는 종종 이런 일이 생깁니다.

* 수급/테마/모멘텀 때문에 점수는 높음
* 하지만 재무 품질이 매우 나쁨
* 결과적으로 고점 추격 후 급락 위험이 큼

quality downside gate는 이런 상황에서
**“점수는 좋아 보여도 위험한 종목”**을 억제합니다.

### 해석 포인트

이 장치는 수익 확대보다 손실 회피에 더 가깝습니다.
즉,

* upside booster가 아니라
* downside suppressor입니다.

---

## 12. Cap 개념과 점수의 관계

점수가 높아도 무한정 매수할 수는 없습니다.
그래서 cap이 필요합니다.

대표 예시:

* position cap
* sector cap
* total remaining cap

### cap의 역할

* 포트폴리오 쏠림 방지
* 같은 테마 과집중 방지
* 자동매매 안정성 확보

### 중요한 점

cap은 점수를 바꾸는 개념이 아니라,
**점수 결과를 실제 주문 수량으로 바꿀 때 제한을 거는 개념**입니다.

따라서 아래를 구분해야 합니다.

* 높은 점수 = 추천 우선순위 높음
* 높은 점수 + cap 제한 = 진입량은 제한될 수 있음

---

## 13. 신뢰도(confidence)를 서비스 관점에서 쓰는 법

Lee_trader의 핵심 차별점 후보는 바로 이 부분입니다.

대부분의 추천 시스템은 “추천”만 합니다.
하지만 Lee_trader는 장기적으로 아래처럼 가야 합니다.

* 추천 점수 제공
* 예측 신뢰도 제공
* 왜 이 점수가 나왔는지 설명 문서 제공

즉, confidence score는 내부용 지표가 아니라
**사용자에게 보여줄 수 있는 서비스 지표**여야 합니다.

### 추천 활용 예시

* confidence 80 이상만 메인 추천 노출
* confidence 낮으면 경고 뱃지 부여
* confidence와 final score를 동시에 표기
* 추천 문서에 “이 추천의 신뢰 수준” 설명 포함

## 14. 점수 해석 예시 프레임

실제 종목을 해석할 때는 아래 프레임이 좋습니다.

### 사례 A

* probability 높음
* return 높음
* confidence 높음
* quality 높음

해석:
가장 이상적인 상위 추천 후보입니다.

### 사례 B

* probability 높음
* return 보통
* confidence 높음
* quality 높음

해석:
공격성은 덜하지만 안정적인 추천 후보입니다.

### 사례 C

* probability 보통
* return 높음
* confidence 낮음
* quality 낮음

해석:
고위험 고보상 후보일 수 있으며, 실전 추천 노출은 제한이 필요합니다.

### 사례 D

* probability 높음
* return 높음
* confidence 낮음
* quality 낮음

해석:
겉으로는 매력적이지만 실전 자동매매에는 위험할 수 있습니다.
confidence gate나 quality downside gate가 개입해야 합니다.

## 15. 코드 기준 공식 정리 v1

아래 내용은 현재 프로젝트 코드 기준으로 정리한 **운영 점수 공식 요약**입니다. 이 섹션은 개념 설명이 아니라, 실제 운영에 사용되는 산식과 구성요소를 문서 수준으로 남기기 위한 목적입니다.

### 15.1 Probability Score 산식 또는 구성요소

현재 운영 probability 축은 `prob_top20_60d` 단일 축을 사용합니다.

핵심 규칙:

* `prob_top20_90d`는 저장/연구용일 수 있으나 운영 `prob_score`에는 직접 반영되지 않음
* 운영에서는 **같은 날짜 단면 내 상대순위 기반 점수**를 사용

구성 순서:

1. `prob_top20_60d`를 숫자로 변환
2. `prob_score_raw = clip(prob_top20_60d * 100, 0, 100)`
3. 같은 날짜(`date`) 내 백분위 순위 계산

   * `prob_rank_pct = percentile01_by_date(prob_top20_60d)`
4. 결측치는 날짜별 중앙값으로 보정
5. 최종 점수:

```text
prob_score = prob_rank_pct * 100
```

해석:

* `prob_score_raw`는 절대 확률 해석용
* `prob_score`는 운영 랭킹용 상대 점수
* 최종 `final_score`에는 `prob_score`가 직접 들어감

즉, 이 시스템의 probability 축은 **절대 확률값을 그대로 쓰지 않고, 당일 후보군 내 상대적 확률 우위**를 점수화한 구조입니다.

---

### 15.2 Return Score 산식 또는 구성요소

현재 운영 return 축은 `pred_return_60d`, `pred_return_90d`를 결합합니다.

구성 순서:

1. `pred_return_60d`의 같은 날짜 내 상대순위 계산

   * `ret_rank_60 = percentile01_by_date(pred_return_60d)`
2. `pred_return_90d`의 같은 날짜 내 상대순위 계산

   * `ret_rank_90 = percentile01_by_date(pred_return_90d)`
3. 최종 점수:

```text
ret_score = 100 * (0.7 * ret_rank_60 + 0.3 * ret_rank_90)
```

보조 컬럼:

* `pred_score_60 = percentile_by_date(pred_return_60d)`
* `pred_score_90 = percentile_by_date(pred_return_90d)`
* `pred_score = 0.6 * pred_score_60 + 0.4 * pred_score_90`
  이 값은 보조적 예측 점수이며 운영 `final_score`의 핵심 축은 `ret_score`

해석:

* 60일 예측수익률에 더 큰 비중을 둠
* 90일 예측수익률은 보조적 중기 축
* 절대 수익률이 아니라 **동일 날짜 내 기대수익 우선순위**를 반영

---

### 15.3 Confidence Score 산식 또는 구성요소

현재 운영 confidence는 4개 하위 축으로 구성됩니다.

하위 축:

1. `data_maturity_score`
2. `model_reliability_score`
3. `signal_agreement_score`
4. `regime_fitness_score`

#### (1) data_maturity_score

구성요소:

* `component_coverage_ratio`
* `quality_score_confidence`
* `fallback_count`

산식:

```text
data_maturity_score = 100 * (0.65 * component_coverage_ratio + 0.35 * (quality_score_confidence / 100)) - 6 * fallback_count
```

범위:

* 0~100 clip

의미:

* 핵심 점수 축이 얼마나 제대로 채워졌는지
* 품질 데이터의 신뢰도가 충분한지
* fallback 사용이 많을수록 불리

#### (2) model_reliability_score

구성요소:

* `ret_score` 존재 여부
* `prob_score` 존재 여부
* `tech_score` 존재 여부
* `tech_liquidity_guard`
* `score_formula_version`

산식 구조:

```text
model_reliability_score = 100 * (0.25 * ret_present + 0.25 * prob_present + 0.20 * tech_present + 0.15 * tech_guard) + 0.15 * version_bonus
```

여기서:

* `ret_present`, `prob_present`, `tech_present`는 존재 시 1, 아니면 0
* `tech_guard`는 0~1
* `version_bonus`는 기본 운영 formula version이면 80, 아니면 65

범위:

* 0~100 clip

#### (3) signal_agreement_score

구성요소:

* `return_score`
* `probability_score`
* `technical_score`
* `qual_score`

중간값:

* `high_share`: 60 이상 점수 비율
* `weak_share`: 35 이하 점수 비율
* `spread`: 최고점 - 최저점
* `spread_score = 100 - spread`

산식:

```text
signal_agreement_score = 100 * (0.45 * high_share + 0.25 * (1 - weak_share) + 0.30 * (spread_score / 100))
```

의미:

* 여러 핵심 신호가 서로 비슷한 방향으로 강한지
* 특정 축만 과도하게 높고 다른 축이 무너져 있지 않은지

#### (4) regime_fitness_score

regime에 따라 다른 가중식을 사용합니다.

입력 축:

* `return_score`
* `probability_score`
* `technical_score`
* `qual_score`
* `valuation_score`
* `risk_score = 100 - (risk_penalty / 18 * 100)`

Bull:

```text
bull_score = 0.35 * ret + 0.30 * prob + 0.25 * tech + 0.10 * risk_score
```

Neutral:

```text
neutral_score = 0.28 * ret + 0.24 * prob + 0.20 * tech + 0.16 * qual + 0.12 * risk_score
```

Defensive:

```text
defensive_score = 0.22 * ret + 0.16 * prob + 0.12 * tech + 0.25 * qual + 0.15 * val + 0.10 * risk_score
```

#### (5) confidence_score 최종 결합

연구용 점수:

```text
confidence_score_research =
  0.30 * data_maturity_score
+ 0.30 * model_reliability_score
+ 0.25 * signal_agreement_score
+ 0.15 * regime_fitness_score
```

운영용 점수:

```text
confidence_score_operational =
  0.40 * data_maturity_score
+ 0.40 * signal_agreement_score
+ 0.20 * regime_fitness_score
```

현재 UI/API 기준 실제 사용 점수:

```text
confidence_score = confidence_score_operational
```

즉, 현재 운영 confidence는 **데이터 성숙도 + 신호 정합성 + 현재 레짐 적합성**을 중심으로 계산됩니다.

---

### 15.4 Quality Score 산식 또는 구성요소

품질 점수는 `quality_builder.py`에서 먼저 만들어지고, 그 후 운영 `qual_score`로 변환됩니다.

#### (1) 원천 factor

현재 factor와 기본 가중치:

* `roe`: 0.25, 높을수록 좋음
* `op_margin`: 0.20, 높을수록 좋음
* `net_margin`: 0.20, 높을수록 좋음
* `debt_ratio`: 0.15, 낮을수록 좋음
* `ocf_to_assets`: 0.20, 높을수록 좋음

#### (2) quality_raw_score 구성

각 factor는 다음 처리 과정을 거칩니다.

* 날짜별 winsorize
* 날짜별 median fill
* 날짜별 robust z-score
* factor direction 반영
* z-score를 -4~4로 clip

그 후 normalized weight로 결합:

```text
quality_raw_score = Σ(normalized_factor_weight * factor_z)
```

#### (3) quality_score 생성

```text
quality_score = percentile_rank_by_date(quality_raw_score) * 100
```

즉 `quality_score`는 같은 날짜 단면 내 상대 품질 점수입니다.

#### (4) quality_score_confidence 생성

품질 데이터 커버리지에 따라 신뢰도를 계산합니다.

기본 개념:

* factor가 많이 채워질수록 신뢰도 상승
* 핵심 조합(op_margin + debt_ratio + 추가 수익성/현금흐름 축)이 있으면 최소 confidence 하한 상향

운영 `qual_score`는 `quality_score`를 그대로 쓰지 않고 아래 multiplier를 반영합니다.

confidence multiplier:

```text
quality_score_confidence_multiplier = 0.35 + 0.65 * (quality_score_confidence / 100)
```

missing multiplier:

```text
quality_score_missing_multiplier = 1.0 - 0.55 * quality_missing_ratio
```

각각 clip 범위:

* confidence multiplier: 0.35 ~ 1.0
* missing multiplier: 0.45 ~ 1.0

최종 운영 품질 점수:

```text
qual_score = quality_score_rank * quality_score_confidence_multiplier * quality_score_missing_multiplier
```

여기서 `quality_score_rank`는 `quality_score`의 날짜별 백분위값입니다.

즉, 운영 `qual_score`는 **품질 자체 + 품질 데이터 신뢰도 + 결측 패널티**가 반영된 값입니다.

---

### 15.5 Baseline Score 결합식

현재 baseline 축은 `apply_baseline_final_score()` 기준입니다.

사용 축:

* `ret_score`
* `prob_score`
* `tech_score`
* `qual_score`
* `risk_penalty`

기본 결합식:

```text
final_score_before_theme =
  w_ret  * ret_score
+ w_prob * prob_score
+ w_tech * tech_score
+ w_qual * qual_score
- w_risk_penalty * risk_penalty
```

현재 문서상 baseline score는 실무적으로 아래와 같이 이해하면 됩니다.

```text
baseline_score ≈ theme overlay 및 후속 보정 전 final_score_before_theme
```

프로젝트 내 shadow/overlay 문맥에서는 `baseline_score`라는 이름을 anchor로 사용하지만, 운영 핵심 계산식 자체는 위 식입니다.

---

### 15.6 Final Score 결합식

현재 운영 기본 `final_score`는 다음 순서로 만들어집니다.

1. baseline 성격 점수 계산
2. quality downside gate 반영 가능
3. theme overlay 반영 가능
4. 최종 rank 계산

기본형:

```text
final_score = clip(final_score_before_theme, 0, 100)
```

quality downside gate 적용 후:

```text
final_score = final_score * quality_penalty_ratio
```

theme overlay 적용 시 mode에 따라 달라집니다.

대표 mode 1: symmetric floor

```text
final_score = base_weight * anchor + theme_weight_effective * theme_score_effective
```

대표 mode 2: asymmetric positive only

```text
overlay_raw = positive(theme_delta) * gain
overlay_capped = min(overlay_raw, cap)
applied_component = overlay_capped * soft_conf_gate
final_score = anchor + applied_component
```

즉 실제 final score는 단일 공식이 아니라:

* baseline
* quality gate
* overlay
* 기타 shadow 실험
  을 거친 최종 결과입니다.

### 15.7 regime별 가중치 차이

현재 production core weight profile은 다음과 같습니다.

#### Bull

* `w_ret = 0.38`
* `w_prob = 0.27`
* `w_tech = 0.27`
* `w_qual = 0.08`
* `w_risk_penalty = 0.40`

해석:

* 성장/추세/기대수익 중심
* 품질 비중은 가장 낮음

#### Neutral

* `w_ret = 0.32`
* `w_prob = 0.26`
* `w_tech = 0.24`
* `w_qual = 0.18`
* `w_risk_penalty = 0.65`

해석:

* 균형형
* 리스크 패널티가 bull보다 강함

#### Defensive

* `w_ret = 0.26`
* `w_prob = 0.22`
* `w_tech = 0.18`
* `w_qual = 0.34`
* `w_risk_penalty = 0.80`

해석:

* 품질과 하방 방어 중심
* risk penalty가 가장 강함

핵심 해석:

* bull일수록 공격 축 우대
* defensive일수록 quality와 risk 관리 우대

---

### 15.8 gate 조건

현재 점수 문맥에서 중요한 gate는 2종입니다.

#### (1) quality downside gate

현재 `apply_quality_downside_gate()`는 defensive regime에만 직접 적용됩니다.

기본 판단 구간:

* `qual_score < 20`
* `20 <= qual_score < 40`

실험 버전(`QUALITY_GATE_EXPERIMENT`)에 따라 다릅니다.

v1 / v2 기준 defensive penalty 예시:

* `qual_score < 20` → `penalty_ratio = 0.94`
* `20 <= qual_score < 40` → `penalty_ratio = 0.97`

v2에서는 아래 alpha 보호 조건이 있으면 gate를 면제합니다.

* `prob_score >= 85`
* 또는 `ret_score >= 75`
* 또는 `confidence_score >= 85`

v3는 warning only 성격으로 기록만 하고 점수는 깎지 않습니다.

#### (2) operational buy gate

자동매매 운영에는 별도 buy gate 상태가 존재합니다.
문서/산출물 기준 주요 상태:

* `BUY_ALLOWED`
* `WATCH`
* `HOLD`
* `BLOCK`

이 gate는 ranking 점수 자체를 바꾸기보다, **실제 BUY intent/실행 허용 여부**를 결정합니다.

즉,

* 점수는 높을 수 있음
* 하지만 gate가 HOLD/BLOCK이면 실제 매수는 막힐 수 있음

---

### 15.9 overlay 반영 방식

현재 대표 overlay는 theme overlay입니다.

핵심 입력:

* `anchor` (`baseline_score` 또는 `final_score`)
* `theme_score_effective`
* `theme_delta_positive`
* `gain`
* `cap`
* `soft_conf_gate`

대표 모드:

#### symmetric_floor

```text
final_score = base_weight * anchor + theme_weight_effective * theme_score_effective
```

특징:

* 음/양 방향 모두 영향 가능
* baseline을 theme 점수와 혼합

#### asymmetric_positive_only

```text
overlay_raw = positive(theme_delta) * gain
final_score = anchor + overlay_raw
```

특징:

* 양의 uplift만 허용
* theme가 baseline보다 좋을 때만 점수 상승

#### asymmetric_positive_only_capped

```text
overlay_raw = positive(theme_delta) * gain
overlay_capped = min(overlay_raw, cap)
final_score = anchor + overlay_capped
```

특징:

* uplift 상한 적용
* 과도한 테마 쏠림 완화

#### soft confidence gate 결합형

```text
applied_component = overlay_capped * soft_conf_gate
final_score = anchor + applied_component
```

특징:

* confidence가 낮으면 overlay 효과를 약하게 적용

핵심 해석:

* overlay는 baseline을 대체하는 것이 아니라 후반 보정층
* positive-only 계열은 설명 가능성과 과도한 churn 억제 측면에서 유리

---

### 15.10 cap 반영 방식

cap은 점수를 계산하는 식이라기보다, **점수 결과를 포트폴리오/주문으로 번역할 때 거는 제한 규칙**입니다.

현재 프로젝트 전반에서 확인되는 대표 cap은 다음입니다.

#### (1) sector cap

예시 코드/운영값:

* sector별 최대 비중 제한
* 예시 문맥: `sector_cap_ratio=0.30` 또는 재구성 스크립트에서 Top20 기준 40%

의미:

* 특정 섹터 쏠림 방지

#### (2) theme cap

예시:

* `theme_cap_ratio=0.30`

의미:

* 특정 테마 과집중 방지

#### (3) no-theme cap

예시:

* `no_theme_cap_ratio=0.50`

의미:

* 테마 미분류 종목 비중 상한

#### (4) position weight cap

예시 문맥:

* 종목당 최대 비중 제한
* 재구성 스크립트에서 5% cap

핵심 적용 방식:

1. 점수 순으로 후보를 선정
2. 목표 비중(`target_weight_pre_cap`) 산출
3. 섹터/테마/포지션 cap을 초과하는 경우 비중 축소
4. 필요하면 남는 비중 재분배

즉,

* 높은 점수 = 진입 우선순위 우위
* cap 적용 후 = 실제 주문 수량/비중은 제한 가능

### 15.11 현재 문서화 원칙

위 10개 항목은 이제 개념 수준이 아니라, **코드 기준 운영 문서의 초안**으로 간주해야 합니다.

다음 버전에서 보강해야 할 것:

* 각 공식이 실제 어느 파일/함수에서 계산되는지 표로 정리
* 입력 컬럼명과 fallback 규칙 추가
* 실험 버전(v1/v2/v3, shadow 모드) 차이 정리
* acceptance 기준과 연결

## 17. 현재 프로젝트에서 가장 중요한 문서 원칙

이 프로젝트는 단순히 “점수가 높다”로 끝나면 안 됩니다.
반드시 아래 3가지가 함께 설명 가능해야 합니다.

1. **왜 높게 나왔는가**
2. **얼마나 믿을 수 있는가**
3. **실제 매수까지 연결해도 되는가**

즉, 점수 문서는 곧 설명 가능성 문서이기도 합니다.

## 19. 현 시점 한 줄 요약

Lee_trader의 점수 체계는 단순 순위표가 아니라,
**확률(probability) + 기대수익(return) + 신뢰도(confidence) + 품질(quality)**를 결합하고,
여기에 **regime / gate / overlay / cap**을 더해 실제 추천과 주문 판단으로 연결하는 다층 구조입니다.
