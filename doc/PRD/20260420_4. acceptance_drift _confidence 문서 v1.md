# Lee Trader acceptance / drift / confidence 문서 v1

## 0. 문서 목적

이 문서는 현재 점수 체계를 운영 가능한 수준으로 관리하기 위해 필요한 3개 축을 정리한다.

1. acceptance report 표준안
2. score drift 감시 기준
3. confidence calibration 설계안

이 문서의 목적은 단순 설명이 아니라,
**점수 산식 변경 후 수용 여부 판단**,
**운영 중 점수 이상징후 감시**,
**예측 신뢰도 점수화**를 가능하게 만드는 것이다.

# 1. acceptance report 표준안

## 1.1 acceptance report의 역할

acceptance report는 점수 산식, 가중치, gate, overlay, cap, 입력 피처, 모델 버전이 바뀌었을 때 아래를 검증하는 리포트다.

* 추천 결과가 얼마나 변했는가
* 변화가 허용 범위인가
* 변화가 성능 개선으로 이어지는가
* 특정 regime에서만 개선된 것은 아닌가
* 점수 체계가 과도하게 흔들리지는 않았는가

즉 acceptance report는
**“코드 변경을 운영에 반영해도 되는지 판단하는 승인 문서”**다.

## 1.5 acceptance 판단 규칙 예시

아래는 운영용 예시 기준이다.
실제 프로젝트 상황에 맞게 숫자는 조정할 수 있다.

### A. 구조 안정성 기준

* `Top20 churn <= 0.30` → 안정적
* `0.30 < Top20 churn <= 0.50` → 주의
* `Top20 churn > 0.50` → 산식 급변 가능성, 원인 분석 필요

### B. 점수 분포 기준

* 전체 평균 `final_score` 급변 없음
* `ret_score`, `prob_score` 평균이 비정상적으로 붕괴하지 않을 것
* `pred_mdd_60d` 평균이 악화되지 않을 것

### C. 성능 기준

* 워크포워드 성과가 baseline 대비 개선 또는 최소 동등
* defensive regime 성과 악화 시 reject 가능
* turnover 급증 시 실전 운용성 저하로 reject 검토

## 1.6 acceptance 상태 분류 예시

### ACCEPT

* churn 허용 범위
* 주요 성과 개선
* 리스크 악화 없음
* regime별로 치명적 손상 없음

### CONDITIONAL ACCEPT

* 특정 regime에서만 개선
* churn은 다소 크지만 성과 개선이 뚜렷
* 추가 shadow 운영 필요

### DEFENSIVE_ONLY

* defensive regime에서는 수용 가능
* neutral/bull 개선 근거 부족
* 해당 regime에서만 제한 적용 가능

### REJECT

* churn 과도
* 성과 악화
* 리스크 악화
* 점수 분포 붕괴
* calibration 악화

# 2. score drift 감시 체크리스트

## 2.1 drift 감시 목적

* 입력 데이터 이상
* 피처 결측 증가
* 모델 출력 분포 붕괴
* rank 체계 급변
* 상위 추천군 품질 저하
* 특정 업종 쏠림 확대
* calibration 붕괴

# 3. confidence calibration 설계서

## 3.1 confidence_score가 필요한 이유

현재 `prob_score`는 모델이 예측한 상위 20% 진입 확률을 단순 점수화한 값이다.

하지만 실전 운영에서는 아래 문제가 있다.

* 높은 확률이 실제로 자주 빗나갈 수 있다
* 시장 regime이 바뀌면 같은 0.7 확률의 의미가 달라질 수 있다
* 확률이 높아도 return 방향 일관성이 약할 수 있다
* 확률이 높아도 risk가 과도할 수 있다

그래서 실전에서는 `prob_score`만으로는 부족하고,
**“이 종목을 지금 얼마나 신뢰할 수 있는가”**를 따로 점수화한 `confidence_score`가 필요하다.

---

## 3.2 confidence_score의 목표

confidence_score는 아래를 함께 반영해야 한다.

1. calibrated probability가 높은가
2. horizon 간 예측이 일관적인가
3. risk가 허용 범위 안인가
4. quality / liquidity 등 기본 체력이 너무 나쁘지 않은가
5. 최근 calibration이 유지되고 있는가

즉 confidence는
**확률 × 일관성 × 안정성**의 개념이다.

---

## 3.3 권장 1단계: probability calibration

원본 확률:

* `prob_top20_60d`
* `prob_top20_90d`

이 raw probability에 대해 calibration 모델을 적합한다.

추천 방법:

* 표본이 충분하면 `Isotonic Regression`
* 단순성과 안정성을 우선하면 `Platt Scaling`

권장 순서:

1. 학습 구간 out-of-fold probability 수집
2. 실제 라벨 `target_60d_top20`, `target_90d_top20` 수집
3. calibration model 적합
4. 추론 시 raw probability 대신 calibrated probability 사용

출력 예:

* `prob_top20_60d_cal`
* `prob_top20_90d_cal`

---

## 3.4 권장 2단계: confidence factor 설계

confidence는 단일 raw probability가 아니라 여러 factor 결합으로 정의한다.

### 기본 factor 후보

* `calibrated_prob_60d`
* `calibrated_prob_90d`
* `return_agreement`
* `risk_stability`
* `quality_support`
* `liquidity_support`

---

## 3.5 factor 정의 예시

### A. calibrated_prob_60d

정의:

* calibration 이후의 60일 상위20% 진입 확률

범위:

* 0 ~ 1

---

### B. calibrated_prob_90d

정의:

* calibration 이후의 90일 상위20% 진입 확률

범위:

* 0 ~ 1

---

### C. return_agreement

정의:

* 60일/90일 수익 예측의 방향성과 강도가 일치하는 정도

예시 규칙:

```text id="6btxea"
둘 다 양수이고 percentile 상위권이면 1.0
둘 다 양수지만 강도 차이가 크면 0.7
한쪽만 양수면 0.4
방향이 반대면 0.2
둘 다 약하면 0.5
```

---

### D. risk_stability

정의:

* 예측 MDD가 과도하지 않고 horizon 간 안정적인 정도

예시 규칙:

```text id="jmb72s"
pred_mdd_60d >= -0.10 and pred_mdd_90d >= -0.12 -> 1.0
pred_mdd_60d >= -0.15 and pred_mdd_90d >= -0.18 -> 0.8
pred_mdd_60d >= -0.20 -> 0.5
그 이하 -> 0.2
```

---

### E. quality_support

정의:

* `qual_score`가 극단적으로 낮지 않은지 반영

예시:

```text id="b0c8lm"
qual_score >= 70 -> 1.0
50 <= qual_score < 70 -> 0.8
30 <= qual_score < 50 -> 0.6
qual_score < 30 -> 0.3
```

---

### F. liquidity_support

정의:

* 거래대금 부족 또는 체결 리스크가 크지 않은지 반영

예시:

```text id="2km9yl"
liquidity_score >= 70 -> 1.0
50 <= liquidity_score < 70 -> 0.8
30 <= liquidity_score < 50 -> 0.6
liquidity_score < 30 -> 0.3
```

---

## 3.6 confidence_score 기본 결합식 예시

가장 단순한 권장식:

```text id="tgrvq9"
confidence_raw =
    0.45 * calibrated_prob_60d
  + 0.15 * calibrated_prob_90d
  + 0.15 * return_agreement
  + 0.15 * risk_stability
  + 0.05 * quality_support
  + 0.05 * liquidity_support
```

최종 점수:

```text id="1jpa3n"
confidence_score = clip(100 * confidence_raw, 0, 100)
```

이 식의 장점:

* 확률 자체를 중심에 둔다
* 60일 horizon을 주축으로 둔다
* 리스크와 일관성으로 허수를 줄인다
* 품질/유동성은 보조적으로만 반영한다

## 3.7 confidence grade 구간 예시

### A 등급

* `confidence_score >= 80`
* 실전 매수 우선 검토

### B 등급

* `65 <= confidence_score < 80`
* 일반 추천 가능

### C 등급

* `50 <= confidence_score < 65`
* 보수적 접근 필요

### D 등급

* `confidence_score < 50`
* 추천 보류 또는 lower priority

## 3.8 confidence calibration 검증 지표

confidence_score는 반드시 검증되어야 한다.

권장 검증:

* confidence decile별 실제 hit rate
* confidence decile별 평균 realized return
* confidence 상위군의 MDD 특성
* confidence 상위군 turnover
* confidence와 실제 성과의 monotonic relationship

좋은 confidence의 조건:

* confidence가 높을수록 실제 hit rate가 높다
* confidence가 높을수록 평균 realized return이 개선된다
* confidence가 높을수록 불필요한 false positive가 줄어든다

## 3.9 confidence calibration 재보정 주기

권장:

* 월 1회 점검
* 분기 1회 재보정 검토
* regime 급변 시 추가 점검

아래 경우 재보정 필요:

* reliability curve 기울기 붕괴
* Brier score 악화
* 고확률 구간 실제 적중률 급락
* 상위 confidence 종목 성과 저하

### 방법 C. final_score 보정용

# 5. 최종 요약

## acceptance report

* `prob_score`와 별개로 신뢰도 점수를 만드는 작업
* calibrated probability + 예측 일관성 + 리스크 안정성을 결합하는 것이 핵심이다
