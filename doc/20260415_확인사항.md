# 2026-04-15 확인사항

## 목적

- 로컬과 Git 종가배치 결과 차이를 최종 축소한다.
- `features`, `labels`, `predictions`, `daily_ranking`이 안정적으로 유지되는지 확인한다.
- `씨젠(096530)` 순위 차이 원인을 추가로 좁힌다.

## 현재까지 정리된 핵심 원인

- 예전 Git 배치는 긴 가격 이력을 유지하지 못한 채 `fact_price_daily -> features -> labels`를 다시 만들고 DB를 `replace`했다.
- 그 결과 웹 DB의 학습셋 row 수가 로컬보다 크게 작아졌고, `model_train`, `model_predict` 결과가 크게 달라졌다.
- 최근 수정으로 아래는 반영됨:
  - `create_adjusted_prices.py`: 기존 DB `fact_price_daily`와 새 가격 이력 병합
  - GitHub Actions cache: `prices_daily_raw.csv`, `prices_daily_clean.csv`, `prices_daily_adjusted.csv` 복원
  - `fetch_top_universe.py`: `MARKET_DATE` 고정, ETF 필터, 비ETF 100개 채우기 보강
  - `sync_csv_db_parity.py`: `fact_price_daily`, `prices_adjusted`, `features`, `labels` 포함 동기화

## 현재 상태 요약

- 웹 DB row 수는 많이 회복됨
  - `prices_adjusted`: 141,628
  - `features`: 141,628
  - `labels`: 135,448
- 다만 `fact_price_daily`는 19,394로 아직 낮아서 추가 확인 필요
- `씨젠(096530)`은 예전 `웹 1위`에서 `웹 12위`로 내려왔지만, 로컬 `63위`와는 여전히 차이가 큼

## 내일 우선 확인 순서

1. 웹 DB row 수 재확인
2. 로컬 DB row 수와 1:1 비교
3. `096530` 로컬/웹 예측값 비교
4. `096530` 로컬/웹 랭킹 구성요소 비교
5. `fact_price_daily` 이력 복구 여부 확인
6. 필요하면 웹 DB 재동기화 후 종가배치 재실행

## 웹 DB 확인 쿼리

```sql
SELECT 'fact_price_daily' AS table_name, COUNT(*) AS total_rows, MAX(date) AS latest_date FROM fact_price_daily
UNION ALL
SELECT 'prices_adjusted', COUNT(*), MAX(date) FROM prices_adjusted
UNION ALL
SELECT 'features', COUNT(*), MAX(date) FROM features
UNION ALL
SELECT 'labels', COUNT(*), MAX(date) FROM labels
UNION ALL
SELECT 'predictions', COUNT(*), MAX(date) FROM predictions
UNION ALL
SELECT 'daily_ranking', COUNT(*), MAX(date) FROM daily_ranking
ORDER BY table_name;
```


## 판정 기준

- `features`, `labels`, `prices_adjusted`가 웹과 로컬에서 비슷한 규모여야 한다.
- `fact_price_daily`가 웹에서도 충분한 이력을 유지해야 한다.
- `096530`의 `pred_return_60d`, `prob_top20_60d`, `rank_final` 차이가 과도하면 추가 원인 분석이 필요하다.
- ETF가 상위 랭킹에 다시 등장하면 유니버스/서빙 데이터 경로를 재점검한다.
