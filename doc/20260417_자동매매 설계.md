## 📌 metrics.py

```python
import numpy as np
import pandas as pd

def calculate_cagr(nav: pd.Series):
    years = len(nav) / 252
    return (nav.iloc[-1] / nav.iloc[0]) ** (1 / years) - 1

def calculate_mdd(nav: pd.Series):
    cum_max = nav.cummax()
    drawdown = (nav - cum_max) / cum_max
    return drawdown.min()

def calculate_sharpe(returns: pd.Series):
    return returns.mean() / returns.std() * np.sqrt(252)
```

```python
import pandas as pd

def run_score_validation(df):
    df['bucket'] = pd.qcut(df['final_score'], 10, labels=False)

    grouped = df.groupby('bucket')['fwd_5d_ret'].mean()

    spread = grouped.iloc[-1] - grouped.iloc[0]

    return {
        "top_bucket": grouped.iloc[-1],
        "bottom_bucket": grouped.iloc[0],
        "spread": spread
    }
```

## 📌 validation_acceptance_gate.py

```python
def run_acceptance(perf, score, exec_result):
    rules = []

    rules.append(("sharpe", perf["sharpe"] >= 1.0))
    rules.append(("mdd", perf["mdd"] >= -0.2))
    rules.append(("spread", score["spread"] > 0))
    rules.append(("execution_drag", exec_result["execution_drag"] < 0.25))

    passed = sum([r[1] for r in rules])

    if passed == len(rules):
        decision = "ACCEPT"
    elif passed >= 2:
        decision = "SHADOW_ONLY"
    else:
        decision = "REJECT"

    return decision, rules
```

# 🧭 5. 실전 전환 관점에서의 최적 시나리오

현재 시스템은 이미 아래 축이 존재합니다.

- 점수 산출 및 추천: `ranking_builder` 계열
- 운영 위험 판단: `build_operational_buy_gate.py`
- 실제 계좌 행동 규칙: `apply_execution_policy.py`
- 실계좌 상태 조회: `sync_live_account_holdings.py`
- 주문 전 미리보기: `build_live_order_preview.py`
- 운영 일일 실행 묶음: `run_operational_refresh.py`

즉, 지금 필요한 것은 완전히 새로운 자동매매 엔진을 처음부터 만드는 것이 아니라,
기존 추천/게이트/정책/계좌 조회 흐름 위에 `주문 승인`, `실주문`, `체결 복구`, `안전장치`를 얹는 것입니다.

가장 현실적인 최적 시나리오는 아래 순서입니다.

1. `자동 신호 생성 + 자동 주문안 생성`
2. `운영자 승인 후 소액 실주문`
3. `신규 진입은 승인형, 축소/청산은 반자동`
4. `안정화 후 일부 신규 진입까지 완전자동`
5. `문제 없을 때만 투자금과 자동화 범위 확대`

핵심은 `신규 매수`와 `위험 축소`를 같은 수준으로 자동화하지 않는 것입니다.

- 신규 매수는 실수 비용이 큽니다.
- 축소/청산은 리스크 방어 성격이 강합니다.
- 따라서 초기 운영에서는 `매수는 보수적`, `축소와 차단은 적극적`이 맞습니다.

# 🏗 6. 권장 아키텍처

## 6-1. 상위 흐름

```text
시장 데이터 수집
  -> 점수/추천 산출
  -> 운영 게이트 산출
  -> execution policy 적용
  -> 주문 의도(trade intent) 생성
  -> 운영자 승인 또는 자동 승인 판정
  -> 브로커 주문 요청(order request) 생성
  -> 체결/미체결 동기화
  -> 포지션/현금/주문 상태 재조정
  -> 로그/리포트/검증 지표 적재
```

## 6-2. 모듈 경계

### A. Signal Engine

역할:
- 일별 점수 산출
- top5 후보 선정
- confidence / liquidity / score gap 계산

현재 기반:
- `ranking_builder`
- `buy_candidate_builder.py`

### B. Risk Gate Engine

역할:
- 시장 위험 구간 판정
- 신규 진입 가능 여부 결정
- `BUY_ALLOWED / WATCH / HOLD / BLOCK` 산출

현재 기반:
- `build_operational_buy_gate.py`

### C. Execution Policy Engine

역할:
- 보유 종목과 신규 후보를 비교
- `유지 / 축소 / 교체 / 신규 진입 보류` 분류
- cap / cooldown / cash minimum 적용

현재 기반:
- `apply_execution_policy.py`
- `docs/execution_policy_v1.md`

### D. Order Planning Engine

역할:
- 실제 주문 전송 전 단계의 `주문 의도` 생성
- 목표 비중, 목표 수량, 주문 사유, 차단 사유 기록
- 실계좌 잔고와 매수가능수량을 반영한 최종 주문안 생성

현재 기반:
- `build_live_order_preview.py`

보강 필요:
- preview를 단순 화면용 JSON이 아니라 `주문 의도 레코드`로 남기기

### E. Broker Gateway

역할:
- KIS 주문 전송
- 주문번호/응답 저장
- 재시도/중복 방지/idempotency 보장

현재 기반:
- `kis_client.py`
- `kis_manual_order.py`

보강 필요:
- 자동 주문 제출기
- 주문 상태 재조회기

### F. Reconciliation Engine

역할:
- 주문 요청과 실제 체결 결과 맞추기
- 보유 수량/평단/현금 차이 복구
- 장중 실패 후 재시작 시 상태 복원

현재 기반:
- `sync_live_account_holdings.py`

보강 필요:
- 주문 단위 reconciliation 로그

### G. Operator Control Layer

역할:
- 승인/거절/긴급중지
- 오늘 자동매매 허용 범위 설정
- 신규 진입 금지, 청산만 허용 같은 운영 스위치 제공

권장:
- 초기는 웹 UI보다도 `JSON 설정 + 운영자 승인 로그`부터 시작해도 충분

# 🛡 8. 운영 규칙 설계

## 8-1. 초기 운영 기본 원칙

- 투자금은 전체 자산이 아니라 `테스트 한도`만 사용
- 1일 주문 횟수 제한
- 1종목 신규 진입 수 제한
- 신규 진입은 장중 1회 또는 장마감 후 1회만 판단
- 청산/축소는 리스크 방어 목적일 때 우선 허용

## 8-2. 승인 체계

초기에는 아래 3단계가 가장 안전합니다.

### 단계 A. Manual Approve

- 시스템이 `trade_intents`만 생성
- 운영자가 검토 후 승인
- 승인 건만 주문 제출

### 단계 B. Guarded Auto

- `SELL_REDUCE`, `SELL_EXIT`는 자동 허용
- `BUY`는 여전히 승인 필요

### 단계 C. Limited Full Auto

- `BUY_ALLOWED`
- confidence 상위 구간
- score gap 충분
- 당일 KIS/동기화 오류 없음
- 포트폴리오 cap 여유 있음

위 조건을 모두 만족할 때만 자동 신규 진입 허용

## 8-3. 킬스위치 조건

아래는 자동 차단이 필요합니다.

- KIS 인증 실패 연속 발생
- 주문 응답과 계좌 상태 불일치
- 당일 가격/랭킹 산출일 불일치
- gate 상태가 `BLOCK`
- 예상 주문 수량과 실제 가능 수량 차이 과다
- 일손실 한도 초과
- 동일 종목 중복 주문 감지

# 🧪 9. 검증 문서와 실거래 문서의 관계

현재 문서 앞부분의 validation 설계는 여전히 필요합니다.
다만 역할을 명확히 나누는 것이 좋습니다.

- validation: 전략이 실전에 올라도 되는지 판단
- execution policy: 오늘 어떤 행동을 해야 하는지 결정
- auto trading: 결정된 행동을 실제 주문으로 안전하게 전송

즉 순서는 아래입니다.

```text
validation 통과
  -> production 정책 반영
  -> trade intent 생성
  -> 승인/자동승인
  -> 브로커 주문
  -> 체결/복구/감사 로그
```

# 📌 11. 결론

당신의 현재 위치는 `전략 검증 완료 후 실전 파일럿 직전`으로 보는 것이 맞습니다.

하지만 여기서 바로 필요한 것은 “더 복잡한 전략”이 아니라,
아래 3가지를 갖춘 운영 계층입니다.

- 주문 전 승인 가능한 `trade intent`
- 실패해도 복구 가능한 `order / fill / reconciliation`
- 즉시 멈출 수 있는 `kill switch`

따라서 최적의 다음 단계는 다음 한 줄로 정리됩니다.

> `추천 시스템`을 `안전한 주문 실행 시스템`으로 바꾸되, 첫 단계는 `승인형 소액 자동매매`로 시작한다.

# 📘 12. 공식 운영 정의

## 12-1. 문서 목적

본 문서는 Lee_trader 자동매매 시스템의 공식 운영 철학과 상위 설계 원칙을 정의한다.

이 문서의 목적은 아래 3가지를 명확히 하는 데 있다.

- 자동매매 시스템의 실행 주체가 어디인지 정의
- 웹 서비스와 실주문 엔진의 역할을 분리
- 향후 매수 종목 수, 포트폴리오 구성, 주문 세부 규칙을 논의할 때 흔들리지 않는 상위 원칙을 고정

본 장에서는 `몇 종목을 살지`, `top20 중 몇 개를 선택할지`, `가중치를 어떻게 둘지`는 확정하지 않는다.
그 항목들은 이후 포트폴리오 설계 장에서 별도로 결정한다.

## 12-2. 공식 시스템 정의

Lee_trader 자동매매 시스템은 다음과 같이 정의한다.

> `집 노트북에서 상시 실행되는 실주문 엔진`과 `Render 웹에서 제공되는 원격 관제 화면`으로 구성된 무인 자동집행 시스템

즉 이 시스템은 다음 구조를 가진다.

- 실주문 판단과 주문 전송은 집 노트북에서 수행한다.
- 웹은 주문 실행 주체가 아니라 상태 조회와 운영 모니터링을 담당한다.
- 자동매매의 핵심은 사람의 수동 승인보다 일관된 규칙, 안전장치, 복구 가능성에 둔다.

## 12-3. 운영 환경 정의

운영 환경은 아래를 기본 전제로 한다.

- 집의 노트북이 장중 및 필요한 야간 시간대에 계속 켜져 있다.
- 데이터 조회와 운영 현황 확인은 Render 웹에서 수행한다.
- 사용자는 외부에서 웹으로 시스템 상태를 확인할 수 있다.
- 실주문 API 호출과 브로커 연동은 로컬 환경에서만 수행한다.

이 전제를 두는 이유는 다음과 같다.

- 무료 또는 저가 호스팅 환경은 sleep, 재기동, 세션 단절 위험이 있다.
- 실주문 엔진은 네트워크 일시 장애가 있더라도 상태 복구가 가능해야 한다.
- 브로커 인증 정보와 주문 권한은 웹 서버보다 로컬 실행 환경에 두는 편이 안전하다.

## 12-4. 운영 철학

본 시스템의 공식 운영 철학은 아래 한 문장으로 정의한다.

> `로컬 자동 실행, 웹 원격 관제, 신규 진입은 보수적 자동화, 위험 축소는 적극적 자동화`

이 철학의 의미는 다음과 같다.

- 추천 산출, 게이트 판단, 주문 생성, 주문 제출, 체결 동기화는 로컬에서 자동 수행한다.
- 웹은 결과를 보여주고 이상 상태를 감시하는 관제 계층으로 사용한다.
- 신규 매수는 강한 조건을 만족할 때만 자동 허용한다.
- 비중 축소, 교체 제한, 신규 진입 차단 같은 리스크 방어는 보다 적극적으로 자동 적용한다.

## 12-4A. 자동매매 기본 실행 시각

현재 운영 기준에서 자동매매 신규 매수 판단 시각은 `09:30` 전후를 기본값으로 둔다.

이유는 아래와 같다.

- 신규 매수 후보는 `전날 종가 기준 top20`에서 출발한다.
- 당일 실집행에서는 장초반 `갭 상승`, `급등 과열`, `추격매수 위험`, `유동성 왜곡`을 다시 걸러야 한다.
- `09:00` 직후는 시가 변동성과 체결 왜곡이 커서 자동 신규 진입 시점으로는 너무 이르다.
- 반대로 `12:10`은 장중 재평가 시점에 가깝고, 전일 종가 기반 신규 진입 판단 시각으로는 다소 늦다.

따라서 현재 설계 철학에서는 아래처럼 역할을 구분한다.

- `09:30 전후`: 신규 매수 자동 판단 및 guarded submit 기준 시각
- `12:00`: 장중 refresh 및 관제/재평가 시각
- `16:00 이후`: 종가 기준 close 배치와 다음 거래일 기준 데이터 확정

즉 본 시스템의 초기 자동매매 기본 시각은 `장초반 보수 집행`이며, 장중 신규 매수형보다 `09:30 전후 1회 판단`이 현재 설계와 더 일관적이다.

## 12-5. 웹의 역할

웹은 기본적으로 `관제 시스템`으로 정의한다.

웹의 주요 역할은 아래와 같다.

- 오늘의 gate 상태 조회
- 오늘 생성된 추천 및 주문 의도 조회
- 현재 보유 종목 및 평가손익 조회
- 주문 결과 및 체결 상태 조회
- 오류, 중지, 경보 상태 조회

초기 운영 단계에서 웹은 `원격 조회 중심`으로 유지한다.

즉 아래 원칙을 따른다.

- 웹에서 직접 매수 버튼을 누르는 운영은 기본 시나리오로 두지 않는다.
- 실주문은 로컬 자동 실행을 기준으로 설계한다.
- 원격 개입이 필요하다면 최초에는 `긴급 중지` 같은 제한적 제어만 허용한다.

## 12-6. 자동매매의 핵심 성공 조건

이 시스템에서 중요한 것은 단순히 추천 성과가 아니다.
실전 자동매매의 성공 조건은 아래 4가지로 정의한다.

### 1. 신호 일관성

- 점수 산출과 후보 선정이 날짜 기준으로 일관되어야 한다.
- stale 데이터나 부분 실패 상태에서 신규 진입이 발생하면 안 된다.

### 2. 주문 정확성

- 동일 종목 중복 주문이 없어야 한다.
- 주문 의도와 실제 제출 주문이 일치해야 한다.
- 가능한 수량과 목표 수량 차이가 큰 경우 자동 차단이 가능해야 한다.

### 3. 장애 복구성

- 노트북 재시작 이후에도 상태를 복원할 수 있어야 한다.
- 주문 실패, 인증 실패, 네트워크 실패가 발생했을 때 안전하게 중단되어야 한다.
- 체결 상태와 보유 상태를 재동기화할 수 있어야 한다.

### 4. 관제 가능성

- 웹에서 현재 상태를 충분히 이해할 수 있어야 한다.
- 사용자는 외부에서 매매 진행 여부와 이상 상황을 확인할 수 있어야 한다.

## 12-7. 승인형 구조를 기본값으로 두지 않는 이유

본 시스템은 매 거래일마다 웹에서 승인 버튼을 눌러 매수하는 구조를 기본 모델로 채택하지 않는다.

그 이유는 다음과 같다.

- 사용자는 집이 아닌 외부에서도 시스템 상태만 확인하고 싶어 한다.
- 승인형 구조는 상시 개입을 요구하므로 자동매매 본래 목적과 맞지 않는다.
- Render 웹은 관제에는 적합하지만 실시간 주문 승인 UI 중심 구조에는 불편함이 크다.

따라서 본 시스템은 `사람 승인 기반 자동매매`보다 `무인 자동집행 + 웹 관제`를 기본 모델로 둔다.

단, 사람 승인이 완전히 사라지는 것은 아니다.
사람의 역할은 `매일 주문 승인`이 아니라 아래에 가깝다.

- 전략/정책 조정
- 시스템 이상 여부 점검
- 긴급 중지
- 운영 결과 리뷰

## 12-8. 자동 차단 원칙

승인 버튼을 없애는 대신, 자동 차단 규칙을 강하게 둔다.

아래 조건에서는 신규 매수 또는 전체 자동매매를 중지할 수 있어야 한다.

- 당일 산출물 날짜와 장 날짜가 맞지 않음
- `buy gate` 상태가 `BUY_ALLOWED`가 아님
- KIS 인증 실패 또는 주문 실패가 연속 발생
- 주문 응답과 실제 보유 상태가 맞지 않음
- 동일 종목 중복 주문이 감지됨
- 일손실 또는 당일 리스크 한도를 초과함
- 필수 데이터 파일이 누락되었거나 부분 생성 상태임

즉 본 시스템은 `사람 승인` 대신 `자동 차단과 자동 보수화`를 핵심 안전장치로 채택한다.

## 12-9. 포트폴리오 구성은 별도 의사결정 항목

매수 대상 수와 종목 선택 방식은 매우 중요한 항목이지만, 본 장에서 확정하지 않는다.

현재 논의 대상은 아래와 같다.

- top20 중 몇 종목을 실제 매수 대상으로 사용할지
- 동일 비중인지 차등 비중인지
- 신규 진입 최대 종목 수를 몇 개로 둘지
- 기존 top5 체계를 유지할지, top10 또는 top20 기반 선택 체계로 확장할지

이 항목들은 다음 단계의 별도 설계 주제로 분리한다.

그 이유는 명확하다.

- 상위 운영 철학은 포트폴리오 크기와 무관하게 먼저 고정되어야 한다.
- 매수 종목 수는 백테스트, 모의투자, 실제 체결 비용, 운영 복잡도를 함께 보고 결정해야 한다.
- 시스템 이론과 운영 구조를 먼저 정의해야 포트폴리오 논의도 흔들리지 않는다.

## 12-10. 현재 시점의 공식 결론

현재 시점에서 Lee_trader 자동매매 시스템의 공식 정의는 아래와 같다.

그리고 현재 단계의 공식 원칙은 아래와 같다.

- 웹은 조회와 경보 확인 중심으로 사용한다.
- 실주문은 로컬 자동 실행을 기준으로 설계한다.

# 📗 13. 포트폴리오 구성 이론

## 13-1. 문서 목적

본 장은 Lee_trader 자동매매 시스템의 포트폴리오 구성 이론을 정의한다.

본 장의 목적은 아래 항목에 대한 상위 원칙을 고정하는 것이다.

- top20 추천군을 어떻게 해석할 것인가
- 실제 보유 종목 수를 어떤 논리로 결정할 것인가
- 동일비중과 차등비중 중 어떤 철학을 채택할 것인가
- 기존 top5 체계를 유지할 것인가, 확장할 것인가

이 장은 `최종 숫자 확정 문서`가 아니다.
즉 실제 종목 수와 세부 비중 파라미터는 이후 백테스트, 모의투자, 실거래 관찰 결과를 보고 조정할 수 있다.

다만 그 이전에 흔들리지 않아야 할 포트폴리오 이론의 방향을 먼저 정의한다.

## 13-2. 포트폴리오 설계의 핵심 문제

Lee_trader의 포트폴리오 설계는 단순히 기대수익률 최대화만을 목표로 하지 않는다.

이 시스템이 동시에 만족해야 할 목표는 아래와 같다.

- 점수 체계의 예측력을 실제 포트폴리오에 반영할 것
- 개별 종목 실패와 변동성을 완화할 것
- turnover를 지나치게 높이지 않을 것
- 집 노트북 기반 무인 자동집행 환경에서 운영 가능할 것
- 장애 발생 시 복구와 상태 해석이 쉬울 것

즉 포트폴리오 설계는 `알파 집중`과 `운영 안정성` 사이의 균형 문제로 본다.

## 13-3. top20의 의미

본 시스템에서 `top20`은 곧바로 `전부 매수 대상`을 의미하지 않는다.

top20은 다음과 같이 정의한다.

> `모델이 현재 시점에서 상대적으로 우수하다고 판단한 상위 후보군`

즉 top20은 `추천 후보 우주`이지, 자동으로 전량 보유해야 하는 완성 포트폴리오가 아니다.

이 원칙을 두는 이유는 명확하다.

- 상위권 종목 간 점수 차이는 실제 운용상 충분히 작을 수 있다.
- top20 전체를 모두 보유하면 예측력 우위가 희석될 수 있다.
- 종목 수가 늘어날수록 주문 관리와 교체 로직이 복잡해진다.
- 자동매매에서는 종목 수 증가가 단순 분산 이상의 운영 비용을 만든다.

따라서 `추천 후보군`과 `실제 보유 포트폴리오`는 분리해서 해석해야 한다.

## 13-4. 3단계 구조: 후보군, 진입군, 보유군

Lee_trader 포트폴리오 이론은 아래 3단계 구조를 기본으로 한다.

### 1. 후보군

후보군은 기본적으로 `top20`이다.

역할:
- 감시 대상 유지
- 신규 진입 후보 확보
- 보유 종목 교체 후보 비교 기준 제공

후보군은 넓게 유지하되, 그 자체로 즉시 매수 대상으로 해석하지 않는다.

### 2. 진입 심사군

진입 심사군은 후보군 중 실제 신규 진입을 검토할 소수 상위 집합이다.

역할:
- 신규 매수 판단의 실질 대상
- 보유 종목 대비 우월성 판단 기준
- 점수, 신뢰도, 유동성, 게이트 상태를 함께 반영하는 구간

이 구간은 top20 전체보다 좁아야 한다.
즉 모든 후보가 아니라 `충분히 강한 후보만` 실제 진입 심사 대상으로 본다.

### 3. 실제 보유군

실제 보유군은 자동매매 계좌에 실제로 들고 가는 포트폴리오다.

역할:
- 실전 성과의 직접 대상
- 변동성, 집중도, 회전율 관리의 핵심 단위
- 주문 실행과 복구 로직의 기준 상태

결론적으로 Lee_trader는 `top20 전체 매수형`이 아니라 `top20 기반 선별 보유형`을 기본 모델로 채택한다.

## 13-5. 종목 수에 대한 이론적 판단

현재 시점에서 종목 수는 아래 세 구간으로 해석할 수 있다.

### 1. 5종목 이하

특징:
- 상위 점수 집중 효과가 강함
- 알파가 살아 있으면 성과가 크게 나타날 수 있음

한계:
- 개별 종목 실패 영향이 큼
- 갭 하락, 체결 오차, 뉴스 충격에 취약
- 초기 무인 자동매매에는 다소 공격적

### 2. 6~8종목

특징:
- 예측력 우위를 크게 희석하지 않으면서 분산 효과 확보 가능
- 한 종목 실패가 전체 계좌에 미치는 충격을 완화
- 자동매매 운영 복잡도도 아직 관리 가능

평가:
- 현재 단계에서 가장 균형적인 중심 구간으로 본다

### 3. 10종목 이상

특징:
- 분산 효과는 더 커질 수 있음
- 개별 충격 완화에는 유리

한계:
- 상위 점수 우위가 희석될 가능성이 큼
- 주문 수, 교체 수, 체결 관리가 복잡해짐
- 초기 자동매매 시스템에는 다소 이른 확장일 수 있음

따라서 현재 이론적 중심값은 `top20 후보군에서 실제 보유는 6~8종목 수준`으로 둔다.

이 문장은 확정 수치 선언이 아니라, 현 시점의 기본 가설이다.

## 13-6. top5 체계의 해석

기존 top5 체계는 폐기 대상이 아니다.

오히려 Lee_trader의 기존 구조를 고려하면 top5는 다음과 같이 재정의하는 것이 적절하다.

> `top5는 최우선 판단 버킷이며, top20은 확장 후보 우주다`

이 정의의 의미는 다음과 같다.

- top5는 가장 강한 신호군으로 유지한다.
- top20은 교체 후보와 대기 후보를 포함하는 넓은 우주로 사용한다.
- 실제 포트폴리오는 top5만으로 고정하지 않고, 필요 시 top20 안에서 확장한다.

즉 방향은 `top5 폐기`가 아니라 `top5 유지 + top20 확장 해석`이다.

이 구조는 기존 시스템 자산을 버리지 않으면서도 확장성을 확보한다.

## 13-7. 동일비중과 차등비중에 대한 원칙

비중 체계는 아래 두 극단 중 하나로 가지 않는 것이 중요하다.

### 극단 1. 완전 동일비중

장점:
- 단순하다
- 운영과 검증이 쉽다
- 복구 로직이 간단하다

한계:
- 상위 점수 종목과 하위 진입 종목의 차이를 충분히 반영하지 못한다

### 극단 2. 강한 점수 연동 차등비중

장점:
- 신호 강도를 비중에 직접 반영할 수 있다

한계:
- 상위 1~2개 종목 쏠림이 쉽게 커진다
- 점수의 미세한 차이를 과대 해석할 위험이 있다
- 실거래 변동성이 커진다

따라서 Lee_trader의 기본 원칙은 아래와 같이 둔다.

> `랭킹은 정교하게 사용하되, 비중은 보수적으로 사용한다`

즉 점수 차이는 포트폴리오에 반영하되, 비중은 완만한 구간형 차등비중으로 설계한다.

## 13-8. 권장 비중 철학: 완만한 차등비중

현재 단계의 기본 비중 철학은 `완전 동일비중`도 아니고 `강한 집중형 차등비중`도 아니다.

Lee_trader는 아래 구조를 기본 철학으로 둔다.

- 최상위군은 기준비중보다 소폭 높은 비중
- 중간 보유군은 기준비중 부근 유지
- 하위 진입군은 기준비중보다 소폭 낮은 비중
- 종목당 상한은 강하게 유지

즉 구조적으로는 `가벼운 overweight / neutral / underweight` 구간을 둔다.

이 방식이 적절한 이유는 아래와 같다.

- 순위의 우열은 반영할 수 있다
- 점수 미세차를 과대 해석하지 않는다
- 상위 종목 편중을 억제할 수 있다
- 자동매매의 주문 수량 계산과 복구가 지나치게 복잡해지지 않는다

## 13-9. 교체 철학

포트폴리오 구성에서 중요한 것은 `무엇을 살까`만이 아니라 `언제 교체할까`다.

Lee_trader는 교체를 아래 원칙으로 해석한다.

- 후보군에 새 종목이 들어왔다고 바로 교체하지 않는다
- 현재 보유 종목보다 `충분히 우월한 후보`만 교체 대상으로 본다
- 점수 차이가 작으면 유지가 기본이다
- turnover 억제는 성과만큼 중요한 운영 목표다

즉 `후보군 확대`가 곧 `교체 빈도 증가`로 이어지면 안 된다.

top20을 쓰더라도 자동매매의 핵심은 `후보를 넓히되, 교체는 보수적으로`다.

## 13-10. 현재 시점의 공식 가설

현재 시점에서 포트폴리오 구성에 대한 공식 가설은 아래와 같이 둔다.

- 후보군은 `top20`으로 유지한다
- 실제 진입 심사군은 후보군보다 좁게 둔다
- 실제 보유 종목 수는 `6~8종목` 구간을 기본 가설로 본다
- 기존 `top5`는 최우선 버킷으로 유지한다
- 비중은 완전 동일비중보다 `완만한 차등비중`을 선호한다
- 교체는 상위 후보가 현재 보유 대비 충분히 우월할 때만 허용한다

이 가설은 이후 검증을 통해 조정될 수 있지만, 현재 자동매매 시스템 설계의 가장 일관된 출발점으로 본다.

## 13-11. 다음 단계

본 장 다음에 다뤄야 할 항목은 아래와 같다.

1. `진입 심사군`을 몇 종목으로 둘지 구체화
2. `6~8종목` 가설을 실제 백테스트와 모의투자로 검증
3. 완만한 차등비중을 실제 수식 또는 band 규칙으로 정의
4. 교체 기준의 최소 점수 차이와 최소 보유 기간을 정식화

즉 현재 장의 목적은 숫자를 끝내는 것이 아니라, 숫자를 어떤 논리 위에서 결정할지를 먼저 고정하는 데 있다.

# 📙 14. 진입 심사군 이론

## 14-1. 문서 목적

본 장은 `top20 후보군` 중 어떤 종목을 실제 신규 진입 검토 대상으로 올릴 것인지에 대한 원칙을 정의한다.

즉 이 장의 관심사는 아래와 같다.

- top20 전체를 어떻게 실제 진입 검토 집합으로 축소할 것인가
- 신규 진입 심사군의 적정 크기를 어떻게 볼 것인가
- 급등주는 어디까지 허용하고, 급등과열 종목은 어떻게 다룰 것인가

본 장은 아직 최종 수치 확정 문서가 아니다.
다만 자동매매 시스템에서 신규 진입이 가장 민감한 의사결정이므로, 상위 심사 철학을 먼저 고정한다.

## 14-2. 진입 심사군의 필요성

후보군이 `top20`이라 하더라도, 실제 자동매매는 top20 전체를 동시에 진입 대상으로 보면 안 된다.

그 이유는 아래와 같다.

- 상위 후보군에는 신호 강도가 서로 다른 종목이 함께 섞여 있다.
- 일부 종목은 점수는 높아도 유동성, 과열, 변동성 측면에서 즉시 진입에 부적합할 수 있다.
- 자동매매는 사람이 마지막에 눈으로 걸러주지 않기 때문에, 진입 직전 심사층이 반드시 필요하다.

즉 `후보군`과 `진입 가능군`은 같은 집합이 아니다.

Lee_trader는 아래 구조를 기본으로 한다.

```text
top20 후보군
  -> 진입 심사군
  -> 실제 신규 진입군
```

## 14-3. 현재 시스템에 이미 존재하는 과열 신호

현재 Lee_trader 코드에는 이미 과열 관련 단서가 존재한다.

- `recent_surge_soft_flag`
- `overheat_soft_flag`
- `overheat_hard_flag`
- confidence score 산식 내 `overheat_penalty`

즉 과열 판단은 새로운 요구사항이 아니라, 이미 시스템 내부에 존재하는 리스크 개념이다.
이번 설계에서는 이 개념을 단순 부가 지표가 아니라 `진입 심사 핵심 축`으로 격상한다.

## 14-4. 급등주와 급등과열 종목은 구분해야 한다

자동매매 이론에서 중요한 것은 `급등` 자체를 무조건 금지하지 않는 것이다.

강한 추세를 타는 종목은 실제로 상위 점수군에 진입할 수 있고,
그 자체가 나쁜 신호는 아니다.

하지만 아래는 분리해서 봐야 한다.

### 1. 허용 가능한 급등주

특징:
- 추세 강화나 모멘텀 반영 결과로 상위권에 진입
- 유동성과 거래대금이 충분
- 점수, 신뢰도, 시장 게이트와 함께 볼 때 과도한 일회성 왜곡으로 보이지 않음

해석:
- `추세 강화형 강세 종목`
- 자동매매에서 제한적 허용 가능

### 2. 경계해야 할 급등과열 종목

특징:
- 단기간 수익률이 과도하게 높음
- RSI, 단기 이격, 단기 거래 과열이 동반됨
- 체결가 괴리와 익일 변동성 위험이 큼
- 진입 직후 평균회귀 손실 가능성이 높음

해석:
- `즉시 추격 매수 위험이 큰 종목`
- 자동매매에서는 별도 제한이 필요

즉 원칙은 아래와 같다.

> `강한 종목은 살 수 있지만, 과열된 종목은 같은 방식으로 사면 안 된다`

## 14-5. 진입 심사군의 기본 크기

현재 포트폴리오 이론상 실제 보유 종목 수의 기본 가설은 `6~8종목`이다.

이 구조에서 진입 심사군은 실제 보유군보다 약간 넓되, 후보군보다는 충분히 좁아야 한다.

현재 시점의 공식 가설은 아래와 같다.

- 후보군: `top20`
- 진입 심사군: `상위 8~10종목 수준`
- 실제 신규 진입군: 그중 조건을 통과한 더 적은 수

이렇게 두는 이유는 아래와 같다.

- top20 전체를 매번 신규 진입 대상으로 보면 turnover가 과도해진다.
- 진입 심사군은 실제 보유군보다 약간 넓어야 비교와 교체가 가능하다.
- 하지만 너무 넓으면 약한 후보까지 진입 논리에 섞여 자동매매 안정성이 떨어진다.

따라서 현재 단계에서는 `top20 -> top8~10 진입 심사군 -> 최종 진입` 구조가 가장 일관적이다.

## 14-6. 진입 심사 기준의 4축

진입 심사군은 단순 순위만으로 결정하지 않는다.

Lee_trader는 아래 4축 심사를 기본으로 한다.

### 1. 순위/점수 축

- top20 안에 있어야 한다
- 상위권일수록 진입 심사 우선순위를 높인다
- 기존 보유 종목 대비 점수 우위가 있어야 한다

### 2. 신뢰도/유동성 축

- confidence가 최소 기준 이상이어야 한다
- liquidity score와 거래대금이 최소 기준 이상이어야 한다
- 신뢰도는 충분하더라도 유동성이 낮으면 자동진입을 보수화한다

### 3. 시장 게이트 축

- `BUY_ALLOWED`일 때만 신규 진입을 기본 허용한다
- `WATCH`, `HOLD`, `BLOCK` 상태에서는 신규 진입 심사를 원칙적으로 중단하거나 강하게 축소한다

### 4. 과열/추격위험 축

- 최근 급등 여부를 별도 판단한다
- soft 과열과 hard 과열을 구분한다
- hard 과열은 신규 진입 차단 또는 대기 처리의 대상이 된다

즉 진입 심사군은 `점수 상위군`이 아니라 `점수 + 신뢰도 + 게이트 + 과열 위험`을 통과한 집합으로 본다.

## 14-7. 과열 리스크에 대한 공식 해석

Lee_trader는 과열 리스크를 아래 3단계로 해석한다.

### A. 정상 구간

특징:
- 단기 상승은 있으나 과열 신호가 강하지 않음
- 일반 진입 심사 절차 적용 가능

행동:
- 표준 진입 심사 허용

### B. soft 과열 구간

특징:
- 최근 상승 속도가 빠름
- 추세 지속 가능성과 단기 되돌림 위험이 공존

행동:
- 완전 차단 대신 `진입 보수화`
- 비중 축소
- 상위 우선순위여도 즉시 full-size 진입 금지
- 필요하면 1일 이상 관찰 후 진입

### C. hard 과열 구간

특징:
- 급등률, RSI, 단기 과열 신호가 과도
- 추격 매수 리스크가 명확

행동:
- 신규 진입 차단 또는 강한 대기 처리
- 후보군에는 남길 수 있으나, 자동매매 신규 매수군에서는 제외

즉 과열 종목은 `관찰가치`와 `즉시매수가치`를 분리해서 해석한다.

## 14-8. 급등과열 종목을 완전히 버리지 않는 이유

급등과열 종목을 무조건 후보군에서 제외하는 것도 바람직하지 않다.

그 이유는 다음과 같다.

- 일부 강한 리더주는 단기 과열처럼 보여도 중기 추세가 이어질 수 있다
- 너무 이른 배제는 시스템이 강세장 리더를 놓치게 만들 수 있다
- 모델이 계속 상위로 평가하는 종목은 관찰가치가 여전히 존재한다

따라서 급등과열 종목의 원칙은 아래와 같이 둔다.

- 후보군에서는 유지 가능
- 진입 심사군에서는 제한적 포함
- 실제 신규 진입군에서는 매우 보수적으로 처리

즉 `완전 배제`가 아니라 `후보 유지 + 자동진입 제한`이 기본 철학이다.

## 14-9. 보유 종목과 신규 진입 종목은 다른 규칙을 적용한다

과열 리스크는 보유 중인 종목과 신규 진입 종목에 동일하게 적용하지 않는다.

### 신규 진입

- 추격 매수 리스크가 크므로 가장 엄격하게 본다
- hard 과열은 진입 금지에 가깝게 해석한다

### 기존 보유

- 이미 유리한 가격대에서 보유 중일 수 있다
- 단순 과열만으로 즉시 청산하는 것은 오히려 수익 추세를 끊을 수 있다
- 따라서 보유 종목은 `축소 검토` 대상이지 자동 청산 대상으로 보지 않는다

즉 과열은 `신규 진입 제한`에 더 강하게 작동하고,
`기존 보유 관리`에는 완화된 방식으로 작동해야 한다.

## 14-10. 현재 시점의 공식 가설

현재 시점에서 진입 심사군에 대한 공식 가설은 아래와 같다.

- top20 전체를 직접 진입 대상으로 보지 않는다
- 진입 심사군은 우선 `top8~10` 수준을 기본 가설로 둔다
- 신규 진입은 순위, 신뢰도, 유동성, 게이트, 과열 위험을 함께 본다
- `급등주`와 `급등과열 종목`은 구분한다
- soft 과열은 감액 또는 대기 대상으로 본다
- hard 과열은 후보 유지 가능하더라도 자동 신규 진입은 차단하는 쪽이 기본이다

이 가설은 실제 백테스트, 모의투자, 실거래 관찰로 검증해야 하지만,
현재 자동매매 구조에서 가장 방어적이고 일관된 출발점이다.

## 14-11. 다음 단계

본 장 다음에 정리할 항목은 아래와 같다.

1. `top8~10 진입 심사군`을 실제 규칙으로 어떻게 자를지
2. soft 과열 시 비중 축소 규칙을 어떻게 둘지
3. hard 과열 시 재심사 대기 기간을 둘지
4. 기존 보유 종목의 과열 대응을 축소형으로 설계할지

즉 다음 단계는 이론을 실제 규칙으로 내리는 작업이다.

# 📕 15. 진입 심사군 정량 규칙 초안

## 15-1. 문서 목적

본 장은 앞선 `포트폴리오 구성 이론`과 `진입 심사군 이론`을 실제 운용 규칙 초안으로 변환한다.

즉 이번 장의 목적은 아래와 같다.

- top20 후보군 중 진입 심사군을 어떻게 정량적으로 자를지 정의
- 과열 상태를 soft / hard로 나누어 실제 행동 규칙에 연결
- 신규 진입, 보유 유지, 대기 처리의 기준을 수치형 초안으로 정리

본 장은 `첫 운영 버전`을 위한 초안이다.
즉 향후 백테스트, paper trading, 소액 실거래 관찰에 따라 조정될 수 있다.

## 15-2. 상위 구조

진입 대상 판정은 아래 순서로 해석한다.

```text
top20 후보군
  -> 기본 적격성 필터
  -> 과열/추격 위험 필터
  -> 진입 심사군(top8~10 가설)
  -> 실제 신규 진입 우선순위 결정
```

즉 순위가 높다는 이유만으로 바로 매수하지 않고,
`기본 적격성`과 `과열 리스크`를 통과한 뒤 진입 심사군에 포함시킨다.

## 15-3. 1차 필터: 후보군 적격성

top20 후보군 중 아래 조건을 만족하는 종목만 진입 심사 대상이 될 수 있다.

### 필수 조건

- top20 안에 포함될 것
- `buy gate` 상태가 기본적으로 `BUY_ALLOWED`일 것
- `confidence_score`가 최소 진입 기준 이상일 것
- `liquidity_score`가 최소 기준 이상일 것
- `trading_value`가 최소 기준 이상일 것
- re-entry cooldown 위반이 아닐 것

현재 초안 기준 수치:

- 후보군: `rank <= 20`
- 진입 심사 최소 신뢰도: `confidence_score >= 70`
- 표준 진입 최소 신뢰도: `confidence_score >= 76`
- 적극 진입 최소 신뢰도: `confidence_score >= 80`
- 최소 유동성 점수: `liquidity_score >= 15`
- 최소 거래대금: `trading_value >= 5,000,000,000`

해석은 아래와 같다.

- `70~75.99`: 심사 가능은 하지만 자동 진입은 보수적으로
- `76~79.99`: 표준 진입 심사 가능
- `80+`: 강한 진입 심사 후보

즉 진입 심사군은 `무조건 상위순위`가 아니라 `순위 + 적격성 필터 통과` 집합이다.

## 15-4. 2차 필터: 진입 심사군 크기

1차 필터를 통과한 종목 중 실제 진입 심사군은 아래 규칙으로 자른다.

### 기본 원칙

- 최대 `10종목`
- 기본 목표는 `8종목`
- 단, 적격 종목이 부족하면 그보다 적을 수 있음

현재 초안:

- `rank <= 8` 이면서 1차 필터 통과: 자동 진입 심사군 우선 편입
- `rank 9~10` 구간은 보조 심사군으로 편입
- `rank 11~20` 구간은 대기 후보군으로 유지

이 구조의 의미는 다음과 같다.

- top8은 가장 적극적으로 검토하는 핵심 진입 심사군
- top9~10은 보유 종목 교체나 후보 부족 시 활용하는 확장 심사군
- top11~20은 관찰 가치가 있으나 즉시 진입 논리는 약한 구간

즉 현재 정량 초안은 아래와 같다.

> `진입 심사군 = top8 기본 + top9~10 조건부 확장`

## 15-5. 3차 필터: 과열 리스크 규칙

진입 심사군 후보에 대해 아래 과열 규칙을 적용한다.

현재 시스템에 있는 신호를 기준으로 soft / hard를 아래처럼 해석한다.

### soft 과열

예시 기준:

- `recent_surge_soft_flag = true`
- 또는 `overheat_soft_flag = true`
- 또는 단기 수익률 / RSI가 soft 경계선에 걸림

기본 행동:

- 후보군 유지
- 진입 심사군 포함 가능
- 다만 비중 감액 또는 1일 대기 적용

### hard 과열

예시 기준:

- `overheat_hard_flag = true`
- 또는 confidence 산식 내 과열 패널티가 강하게 반영되는 구간
- 또는 단기 급등률과 RSI가 동시에 높은 구간

기본 행동:

- 후보군 유지 가능
- 진입 심사군에서는 `제한적 포함`
- 실제 자동 신규 진입군에서는 기본적으로 제외

즉 정량 초안은 아래와 같다.

- `정상`: 표준 심사
- `soft 과열`: 감액 심사 또는 대기
- `hard 과열`: 자동 신규 진입 차단

## 15-6. 신규 진입 행동 규칙

신규 진입은 아래 3개 상태로 나눈다.

### 1. BUY_READY

조건 예시:

- `rank <= 8`
- `confidence_score >= 76`
- `liquidity_score >= 15`
- `trading_value >= 5,000,000,000`
- `buy gate = BUY_ALLOWED`
- hard 과열 아님

해석:

- 자동 신규 진입 검토 가능
- 비중은 confidence band와 포트폴리오 cap에 따라 산정

### 2. BUY_REDUCED

조건 예시:

- `rank <= 10`
- `confidence_score >= 70`
- 유동성 기준 충족
- `buy gate = BUY_ALLOWED`
- soft 과열이 있거나 confidence가 중간 구간

해석:

- 진입은 가능하나 감액
- 또는 당일 즉시 진입 대신 관찰 후 진입 가능

### 3. BUY_BLOCKED

조건 예시:

- `buy gate != BUY_ALLOWED`
- `confidence_score < 70`
- `liquidity_score < 15`
- `trading_value < 5,000,000,000`
- cooldown active
- hard 과열

해석:

- 후보군에 있어도 자동 신규 진입은 생성하지 않음

즉 진입 심사군의 최종 상태는 아래 세 가지로 단순화한다.

- `BUY_READY`
- `BUY_REDUCED`
- `BUY_BLOCKED`

## 15-7. soft 과열 대응 초안

soft 과열 종목은 무조건 배제하지 않는다.
다만 일반 종목과 같은 방식으로 진입시키지 않는다.

현재 초안은 아래와 같다.

- 신규 진입 허용은 가능
- 기본 목표 비중의 `50%~70%` 수준으로 감액
- 상위 rank라도 full-size 진입 금지
- 가능하면 익일 또는 다음 재계산일까지 한 번 더 확인

운용 해석:

- strong momentum은 인정
- 추격 매수 위험은 비중과 타이밍으로 제어

즉 soft 과열은 `허용하되, 가볍게 진입`이 기본 철학이다.

## 15-8. hard 과열 대응 초안

hard 과열 종목은 신규 진입 관점에서 사실상 차단에 가깝게 본다.

현재 초안은 아래와 같다.

- 자동 신규 진입 생성 금지
- 후보군과 대기군에는 유지 가능
- 다음 재계산 시 hard 과열이 해소되면 재심사 가능
- 기존 보유 종목이면 즉시 청산이 아니라 축소 검토 우선

운용 해석:

- 하드 과열은 `나쁜 종목`이라는 뜻이 아니라 `지금 추격 매수하기 나쁜 종목`이라는 뜻이다

이 해석은 자동매매에서 매우 중요하다.

## 15-9. 보유 종목에 대한 예외 규칙

신규 진입 규칙과 보유 유지 규칙은 다르게 적용한다.

보유 종목에 대한 초안은 아래와 같다.

- 기존 보유 종목이 soft 과열이면 유지 가능
- 기존 보유 종목이 hard 과열이어도 즉시 청산하지 않음
- 다만 비중이 과도하면 축소 검토
- hard 과열 + 순위 이탈 + confidence 약화가 동시에 오면 축소 또는 교체 우선

즉 과열은 `신규 진입 차단`에는 강하게 작동하지만,
`기존 보유 관리`에는 복합 조건으로 작동한다.

## 15-10. 진입 심사군 선정 초안

현재 시점의 실무형 초안은 아래처럼 요약할 수 있다.

### A. 핵심 진입 심사군

- `rank 1~8`
- `confidence_score >= 76`
- `liquidity_score >= 15`
- `trading_value >= 5,000,000,000`
- `buy gate = BUY_ALLOWED`
- hard 과열 아님

### B. 확장 진입 심사군

- `rank 9~10`
- `confidence_score >= 70`
- `liquidity_score >= 15`
- `trading_value >= 5,000,000,000`
- `buy gate = BUY_ALLOWED`
- hard 과열 아님

추가 조건:

- soft 과열이면 감액 또는 대기
- 기존 보유 종목 교체가 필요한 경우에 우선 활용

### C. 대기 후보군

- `rank 11~20`
- 상위 조건 일부 충족
- 관찰 대상이지만 기본 자동 신규 진입군은 아님

## 15-11. 현재 시점의 공식 초안

현재 시점에서 Lee_trader 자동매매의 진입 심사군 정량 초안은 아래와 같다.

- 후보군은 `top20`
- 핵심 진입 심사군은 `top8`
- 필요 시 `top9~10`까지 조건부 확장
- `confidence_score >= 76`은 표준 진입 기준
- `confidence_score >= 80`은 적극 진입 기준
- `liquidity_score >= 15`, `trading_value >= 5,000,000,000`은 유지
- soft 과열은 감액 또는 대기
- hard 과열은 자동 신규 진입 차단

이 초안은 현재 시스템의 existing rule과도 크게 충돌하지 않는다.
즉 기존 `execution_policy`, `buyability`, `overheat` 계열 지표를 확장 해석해 실전 규칙으로 연결한 형태다.

## 15-12. 다음 단계

본 장 다음에 다뤄야 할 항목은 아래와 같다.

1. `완만한 차등비중`을 실제 band 규칙으로 정리
2. soft 과열 감액 비중을 몇 단계로 나눌지 정리
3. hard 과열 해제 후 재진입 대기일을 둘지 결정
4. 교체 시 최소 점수 차이와 최소 보유기간을 함께 묶어 정식화

즉 이제 다음 주제는 `무엇을 살지`에서 `얼마나 살지`로 넘어간다.

# 📒 16. 완만한 차등비중 규칙

## 16-1. 문서 목적

본 장은 Lee_trader 자동매매 시스템의 실제 포트폴리오 비중 철학을 정량 규칙 초안으로 정의한다.

이번 장의 목적은 아래와 같다.

- 동일비중과 강한 집중형 차등비중 사이의 중간 해법 정의
- 신규 진입군의 상대적 우선순위를 비중에 어떻게 반영할지 정리
- 과열, 신뢰도, 유동성을 비중 감액 규칙에 연결

즉 이 장은 `무엇을 살지` 다음 단계인 `얼마나 살지`를 다룬다.

## 16-2. 기본 철학

Lee_trader의 기본 비중 철학은 아래 한 문장으로 정리한다.

> `랭킹은 정교하게 사용하되, 비중은 보수적으로 조정한다`

이 말의 의미는 다음과 같다.

- 상위 종목에 더 높은 우선순위를 부여한다
- 그러나 상위 1~2종목에 과도하게 쏠리지 않는다
- 점수의 미세 차이를 비중 차이로 과장하지 않는다
- 자동매매 복구와 운용 단순성을 유지한다

즉 Lee_trader는 `강한 집중형 가중치`보다 `완만한 band형 차등비중`을 채택한다.

## 16-3. 비중 규칙의 설계 목표

비중 규칙은 단순히 기대수익률만이 아니라 아래 목표를 동시에 만족해야 한다.

- 상위 점수 종목 우선 반영
- 종목당 과도한 집중 방지
- 과열/유동성 리스크의 자동 감액
- 실주문 수량 계산의 단순성
- 재시작 및 reconciliation 시 해석 용이성

따라서 비중 규칙은 복잡한 연속 함수보다 `band 기반 규칙`이 더 적합하다.

## 16-4. 기준 구조

현재 포트폴리오 기본 가설은 실제 보유 종목 수 `6~8종목`이다.

이 구조에서 기준 비중은 아래처럼 해석한다.

- 6종목 보유 시 기준비중: 약 `15.8%`
- 7종목 보유 시 기준비중: 약 `13.6%`
- 8종목 보유 시 기준비중: 약 `11.9%`

전제:

- 현금 buffer `5%` 유지
- 투자 가능 자산 `95%`를 종목에 배분

즉 실전 비중은 `기준비중`을 중심으로 상하 조절하는 방식으로 본다.

## 16-5. 3단계 비중 band

Lee_trader는 우선 아래 3단계 band를 기본 초안으로 둔다.

### 1. Overweight band

대상:
- 핵심 진입 심사군 상위 종목
- 신뢰도 상위 구간
- 과열 hard 없음
- 유동성 문제 없음

역할:
- 기준비중보다 소폭 높게 배정

### 2. Neutral band

대상:
- 일반적인 표준 진입 종목
- 신뢰도와 유동성이 기준 충족
- 과열 문제가 크지 않음

역할:
- 기준비중 중심으로 배정

### 3. Reduced band

대상:
- soft 과열
- confidence 중간 구간
- 유동성은 기준 충족하지만 다소 약함
- 확장 심사군(top9~10) 후보

역할:
- 기준비중보다 낮게 배정

즉 구조는 `강약약`이 아니라 `조금 강함 / 보통 / 조금 약함`으로 설계한다.

## 16-6. 권장 배수 초안

현재 시점의 비중 배수 초안은 아래와 같다.

- `Overweight`: 기준비중 x `1.15`
- `Neutral`: 기준비중 x `1.00`
- `Reduced`: 기준비중 x `0.60 ~ 0.75`

운용 해석:

- 상위 종목이라도 2배, 3배처럼 과격하게 싣지 않는다
- soft 과열이나 borderline 후보는 완전 배제가 아니라 소액 진입으로 다룬다
- rank가 높아도 risk filter가 걸리면 Reduced로 내린다

이 초안은 기존 코드의 `weight_scale`, `position_cap_scale` 철학과도 일관된다.

## 16-7. band 결정 기준

band는 단일 변수로 결정하지 않는다.

아래 4개 축을 함께 본다.

### A. rank 축

- `rank 1~3`: overweight 후보 우선
- `rank 4~8`: neutral 기본
- `rank 9~10`: reduced 또는 neutral 예외

### B. confidence 축

- `80+`: overweight 또는 neutral 가능
- `76~79.99`: neutral 기본
- `70~75.99`: reduced 기본

### C. 과열 축

- 정상: 기존 band 유지
- soft 과열: 한 단계 감액
- hard 과열: 신규 진입 band 배정하지 않음

### D. 유동성 축

- 기준 충족: 기존 band 유지
- 기준 근접/약함: 한 단계 감액
- 기준 미달: 신규 진입 차단

즉 실제 band는 `순위 우대`보다 `리스크 감액`이 더 우선한다.

## 16-8. band 결정 예시

아래는 실무 해석 예시다.

### 예시 1

- rank 2
- confidence 84
- 유동성 양호
- 과열 없음

판정:
- `Overweight`

### 예시 2

- rank 5
- confidence 78
- 유동성 양호
- 과열 없음

판정:
- `Neutral`

### 예시 3

- rank 3
- confidence 82
- soft 과열

판정:
- 원래는 overweight 후보지만 soft 과열로 한 단계 감액
- `Neutral` 또는 `Reduced`

### 예시 4

- rank 9
- confidence 72
- 유동성 양호
- soft 과열

판정:
- `Reduced`

### 예시 5

- rank 1
- confidence 88
- hard 과열

판정:
- 순위와 점수가 높아도 자동 신규 진입은 차단
- `BUY_BLOCKED`

## 16-9. 종목당 상한

완만한 차등비중은 종목당 상한과 함께 해석해야 한다.

현재 기본 원칙은 아래와 같다.

- 종목당 최대 비중 상한은 `24%`
- overweight band라도 상한을 넘지 않는다
- soft 과열 또는 유동성 약화 종목은 별도 감액 상한을 둘 수 있다

즉 band는 가산 규칙이고, 상한은 절대 제한 규칙이다.

## 16-10. soft 과열 감액 규칙

soft 과열은 비중 규칙에서 가장 실무적으로 중요한 구간이다.

현재 초안은 아래와 같다.

- overweight 후보라도 soft 과열이면 neutral 이하로 내린다
- neutral 후보라도 soft 과열이면 reduced로 내린다
- reduced 후보가 soft 과열이면 최소 탐색 비중 또는 대기 처리

운용 해석:

- soft 과열은 `진입 금지`가 아니라 `비중 하향`의 신호다
- 즉 과열은 진입 여부보다 진입 강도를 조정하는 변수다

## 16-11. hard 과열 차단 규칙

hard 과열은 비중 조정 대상이 아니라 기본적으로 진입 차단 대상이다.

현재 초안은 아래와 같다.

- hard 과열 신규 후보는 band를 배정하지 않는다
- 후보군에는 유지할 수 있다
- 다음 재심사 시 과열 해소 여부를 확인한다

즉 hard 과열은 `감액`이 아니라 `보류`에 가깝다.

## 16-12. 기존 보유 종목의 비중 규칙

기존 보유 종목은 신규 진입 종목과 같은 기준으로 재단하지 않는다.

현재 초안은 아래와 같다.

- 기존 보유의 overweight는 유지 가능
- soft 과열이면 신규 진입처럼 막지 않고 비중만 점검
- hard 과열이어도 즉시 전량 청산이 아니라 일부 축소 검토
- 순위 이탈, confidence 하락, 과열이 동시에 발생하면 축소 우선

즉 비중 규칙은 `신규 진입`에는 엄격하고, `기존 보유`에는 완화적으로 적용한다.

## 16-13. 현재 시점의 공식 초안

현재 시점에서 Lee_trader 자동매매의 완만한 차등비중 초안은 아래와 같다.

- 기준비중은 `투자가능자산 / 보유종목수`로 계산
- 기본 현금 buffer는 `5%`
- 비중 band는 `Overweight / Neutral / Reduced` 3단계
- 권장 배수는 `1.15 / 1.00 / 0.60~0.75`
- `rank`, `confidence`, `과열`, `유동성` 4축으로 band 결정
- soft 과열은 한 단계 감액
- hard 과열은 신규 진입 band 미배정
- 종목당 절대 상한은 `24%`

이 구조는 점수 체계의 우열을 반영하면서도,
실전 자동매매에 필요한 보수성과 단순성을 유지하는 것을 목표로 한다.

# 📓 17. 교체 규칙 정량화

## 17-1. 문서 목적

본 장은 Lee_trader 자동매매 시스템에서 포트폴리오 교체를 언제, 어떤 조건으로 수행할지 정량 규칙으로 정의한다.

이번 장의 목적은 아래와 같다.

- `20일` 같은 표현을 달력일이 아니라 명확한 운영 단위로 재정의
- 최소 보유 기간, 재평가 주기, 즉시 교체 예외 조건을 분리
- turnover를 억제하면서도 약한 종목을 적절히 교체하는 기준을 만든다

## 17-2. 시간 단위 원칙

포트폴리오 운영에서 `20일`은 달력일이 아니라 `거래일`로 해석한다.

즉 Lee_trader 자동매매 문서에서 기간 관련 기준은 아래 원칙을 따른다.

- `일수`라고 표기하더라도 기본은 `거래일` 기준
- 달력일이 필요한 경우에만 별도로 `달력일`이라고 명시
- 최소 보유기간, cooldown, 재심사 대기기간은 모두 거래일 기준으로 계산

이 원칙을 두는 이유는 아래와 같다.

- 주말과 휴장이 끼면 달력일은 실제 시장 노출 일수와 어긋난다
- 자동매매 판단은 시장이 열린 횟수 기준이 더 일관적이다
- backtest, paper trading, live trading을 같은 언어로 맞출 수 있다

따라서 기존의 `20일 기준`은 공식적으로 `20거래일 기준`으로 재정의한다.

## 17-3. 교체 규칙의 3축

교체 판단은 아래 3축으로 나눈다.

### 1. 최소 보유 거래일

의미:
- 신규 진입 직후 너무 빠른 교체를 막기 위한 장치

역할:
- 미세한 점수 변동에 의한 과잉 교체 방지
- 체결 오차와 단기 잡음 흡수

### 2. 정기 재평가 주기

의미:
- 현재 보유 종목을 주기적으로 재심사하는 기준

역할:
- 포트폴리오를 완전히 고정시키지 않되, 매일 불필요하게 흔들리지 않게 함

### 3. 즉시 교체 예외 조건

의미:
- 최소 보유 거래일을 채우지 않았더라도 교체할 수 있는 예외 상황

역할:
- 급격한 약화, 신뢰도 붕괴, hard risk 발생 시 빠른 대응

즉 교체는 단순히 `20거래일마다 바꾼다`가 아니라,
`최소 보유`, `정기 재평가`, `예외 교체`를 동시에 가지는 구조여야 한다.

## 17-4. 최소 보유 거래일 초안

현재 시점의 기본 초안은 아래와 같다.

- 표준 최소 보유기간: `20거래일`
- 단, 이는 `강제 보유`가 아니라 `일반 교체 억제 기준`이다

해석:

- 진입 후 20거래일 이내에는 단순 순위 변동만으로 쉽게 교체하지 않는다
- 20거래일 이내라도 강한 위험 신호가 있으면 예외 교체 가능

즉 `20거래일`은 교체 금지 절대 규칙이 아니라,
`일반적인 score-based 교체를 억제하는 기준선`이다.

## 17-5. 정기 재평가 주기 초안

최소 보유기간과 별개로, 보유 종목은 매일 데이터 업데이트와 함께 상태를 재평가한다.

다만 행동 규칙은 아래처럼 구분한다.

- `매일`: 위험 상태 점검
- `5거래일 단위`: 교체 가능성 정기 검토
- `20거래일 도달 시`: 일반 교체 해제 구간 진입

즉 구조는 아래와 같다.

### 매일 점검

- gate 상태
- confidence 변화
- hard 과열 여부
- 유동성 악화 여부
- rank 급락 여부

### 5거래일 단위 정기 검토

- 대기 후보 대비 우월성 비교
- 점수 차이 누적 여부 확인
- sector/theme concentration 점검

### 20거래일 이후

- 일반 교체 제약 완화
- 상위 후보가 충분히 우월하면 교체 허용

즉 매일 교체하지는 않지만, 매일 아무것도 안 보는 것도 아니다.

## 17-6. 교체 허용의 기본 조건

보유 종목이 일반 교체 대상이 되려면 아래 중 하나 이상을 만족해야 한다.

- 최신 snapshot 기준 `top8` 밖으로 이탈
- `confidence_score < 72`
- current holding band가 `Reduced` 이하로 약화
- sector/theme cap 해소가 필요
- 상위 후보와의 점수 차이가 충분히 큼

이 조건을 만족하지 않으면, 단순 rank 1~2단계 흔들림만으로 교체하지 않는다.

## 17-7. 최소 점수 차이 초안

교체는 신규 후보가 단순히 더 높다는 이유만으로 허용하지 않는다.

현재 기본 초안은 아래와 같다.

- 교체 최소 점수 차이: `final_score +3.0` 이상 우위

즉 신규 후보의 `final_score`가 현재 보유 종목보다 최소 `3.0점` 이상 높아야 한다.

이 기준을 두는 이유는 아래와 같다.

- 상위권 미세한 점수 차이는 실전에서 의미가 약할 수 있다
- 점수 차이보다 체결 오차와 수수료 영향이 더 클 수 있다
- 자동매매는 작은 우위보다 turnover 억제가 중요하다

## 17-8. 최소 보유기간 내 교체 예외

진입 후 `20거래일`이 지나지 않았더라도 아래 조건에서는 예외 교체 또는 축소가 가능하다.

### 즉시 예외 조건

- `buy gate`가 `BLOCK`으로 악화
- `confidence_score < 70`
- hard 과열 + 순위 이탈 + 신뢰도 약화 동시 발생
- liquidity 기준 이탈
- cap 위반 해소 필요
- 브로커/체결 관점에서 비정상 리스크 발생

해석:

- 최소 보유기간은 위험 대응보다 우선하지 않는다
- 즉 `20거래일`은 안전한 환경에서만 작동하는 억제 규칙이다

## 17-9. 교체 우선순위 규칙

여러 종목이 교체 대상일 때는 아래 우선순위를 따른다.

### 교체 대상 우선순위

1. `confidence_score`가 가장 약한 종목
2. `top8` 밖 이탈이 가장 큰 종목
3. cap 위반 해소가 필요한 종목
4. soft/hard risk가 겹친 종목

### 신규 편입 우선순위

1. `top8` 내 상위 rank
2. `confidence_score` 상위
3. hard 과열 아님
4. 유동성 양호
5. 기존 보유 대비 `final_score` 우위 충분

즉 교체는 `가장 약한 보유`를 줄이고 `충분히 강한 후보`를 넣는 방식으로 해석한다.

## 17-10. 교체 수 제한

한 번의 재평가 사이클에서 교체 수가 너무 많아지면 자동매매 안정성이 크게 떨어진다.

현재 초안은 아래와 같다.

- 기본 교체 최대 수: `1회 재평가당 2종목`
- 대규모 리스크 이벤트가 아닌 한 한 번에 3종목 이상 교체하지 않음

해석:

- 포트폴리오 구조 변화는 점진적으로 일어나야 한다
- 자동매매는 최적화보다 안정적 이행이 우선이다

## 17-11. 보유기간과 교체의 관계

보유기간 규칙은 아래처럼 해석한다.

- `0~5거래일`: 사실상 신규 진입 적응 구간, 예외 상황 외 교체 금지에 가깝게 운용
- `6~19거래일`: 일반 교체는 최대한 억제, 단 강한 열화가 있으면 예외 대응
- `20거래일 이상`: 표준 교체 규칙 적용

즉 `20거래일`은 하나의 숫자이지만, 실제 운용상으로는 3단계 보호 구조로 보는 것이 맞다.

## 17-12. 기존 보유와 신규 후보 비교 규칙

교체 판단은 아래 비교로 요약할 수 있다.

```text
현재 보유 종목이
  top8 유지 + confidence 유지 + risk 양호
이면 유지 우선

현재 보유 종목이
  top8 이탈 또는 confidence 약화
이고
  신규 후보가 final_score 3.0 이상 우위
이며
  신규 후보가 hard 과열이 아니고 유동성 기준 충족
이면 교체 가능
```

즉 교체는 `현재 보유 약화`와 `신규 후보 우위`가 동시에 있어야 한다.

## 17-13. 현재 시점의 공식 초안

현재 시점에서 Lee_trader 자동매매의 교체 규칙 정량 초안은 아래와 같다.

- 기간 기준은 달력일이 아니라 `거래일`
- 표준 최소 보유기간은 `20거래일`
- 상태 점검은 매일, 정기 교체 검토는 `5거래일` 단위
- `20거래일` 전에는 일반 교체 억제
- 다만 `BLOCK`, confidence 급락, 유동성 악화, hard risk는 예외
- 교체 최소 점수 차이는 `final_score +3.0`
- 한 번의 재평가에서 최대 `2종목` 교체

이 초안은 turnover 억제, 실거래 마찰비용 통제, 자동집행 안정성을 동시에 만족시키기 위한 보수적 기준이다.
