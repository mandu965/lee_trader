# Lee Trader KR 모델 후보 비교

작성일: 2026-05-26  
범위: 한국 주식(KR) 랭킹 산정 모델

---

## 1. 목적

이 문서는 현재 KR 랭킹 산정에 사용 중인 LightGBM 기반 모델을 기준선으로 두고, 대안 모델군이 실제로 필요한지와 어떤 순서로 비교해야 하는지를 정리한다.

이 문서의 초점은 "이론적으로 더 좋은 모델"이 아니라 "현재 Lee Trader KR 운영 구조에서 가장 현실적으로 검증 가능한 모델"이다.

---

## 2. 현재 운영 모델 구조

현재 KR 모델은 `python/model_train.py` 기준으로 LightGBM 회귀와 분류를 함께 사용한다.

- 회귀: `LGBMRegressor`
- 분류: `LGBMClassifier`
- 회귀 타깃: `target_log_30d`, `target_mdd_30d`, `target_log_60d`, `target_mdd_60d`, `target_log_90d`, `target_mdd_90d`
- 분류 타깃: `target_60d_top20`
- 검증 방식: `TimeSeriesSplit(n_splits=3)`
- 확률 보정: `CalibratedClassifierCV(method="isotonic")`
- 표본 가중치: 최근 데이터에 더 높은 가중치를 두는 exponential decay

추가로 회귀 파라미터 일부는 `models/lgbm_reg_params.json`에서 로드되며, 해당 파일은 `python/model_train_optuna.py`를 통해 Optuna 탐색 결과를 저장한다.

즉 현재 구조는 "하나의 모델이 모든 것을 예측"하는 방식이 아니라, 수익률과 MDD와 Top20 진입 확률을 나눠 학습한 뒤 `ranking_builder.py`에서 운영 점수로 합성하는 구조다.

---

## 3. LightGBM을 쓰는 판단은 맞는가

현재 단계에서는 맞다. 이유는 아래와 같다.

- KR 데이터는 이미지나 텍스트가 아니라 `종목 x 날짜` 형태의 tabular 데이터다.
- 가격, 수급, 재무, 품질, 유동성, 시장 상태처럼 성격이 다른 수치형 피처가 많다.
- 결측치가 일부 존재해도 학습을 진행하기 쉽다.
- 학습과 추론 속도가 빨라 일일 배치 운영에 적합하다.
- feature importance, split 구조, calibration 보조 자료 등 운영 해석이 가능하다.

즉 지금 단계에서 LightGBM은 "보수적이지만 적절한 기본 선택"이다.  
문제가 있다면 대체로 모델 이름보다 타깃 설계, 피처 설계, 점수 합성, 승격 기준 쪽에서 발생할 가능성이 더 높다.

---

## 4. 현재 모델의 강점

- 회귀와 분류를 분리해 운영 목적에 맞는 신호를 나눠 학습한다.
- `TimeSeriesSplit`을 사용해 미래 데이터 누출 위험을 줄인다.
- 최근 데이터에 가중치를 더 줘서 최신 장세를 더 반영하려고 한다.
- 분류 확률에 isotonic calibration을 적용해 `confidence_score` 해석력을 보강하려고 한다.
- 수익뿐 아니라 `MDD`도 별도 예측해 리스크 정보를 점수 체계에 넣을 수 있다.

이 구조는 단순한 "60일 뒤 수익률 하나 예측"보다 운영용 모델에 더 가깝다.

---

## 5. 현재 모델의 한계

### 5-1. 모델 종류보다 랭킹 품질 문제가 더 크다

`outputs/walkforward_acceptance.json`의 2026-05-25 23:09:05 결과는 `REJECTED`다.

핵심 이유:

- `top20_excess_return_positive`: 초과수익은 플러스
- `ordering_not_stable`: `top20`이 `top50`보다 우월하지 않음
- `drawdown_too_deep`: 상위 선택군 MDD가 충분히 얕지 않음
- `confidence_monotonicity_missing`: confidence 구간별 일관성이 약함

즉 현재 한계는 "LightGBM이라서 안 된다"보다 "상위 랭킹이 정말 더 좋은 순서로 정렬되고 있는가"가 아직 약하다는 점이다.

### 5-2. 운영 점수는 모델 출력만으로 결정되지 않는다

최종 순위는 모델 예측값 그대로가 아니라 `ranking_builder.py`의 합성 점수 로직을 거친다.  
따라서 모델 교체 실험은 아래를 분리해서 봐야 한다.

- 모델 자체 예측력
- 예측값을 운영 점수로 바꾸는 조합식
- 게이트와 체결 제약을 통과한 뒤 실제 실행 성과

### 5-3. 분류 신호의 표본이 아직 깊지 않다

`confidence_summary.stable_bucket_count_5d = 3`, `monotonic_hit_rate_5d = false` 상태다.  
즉 확률값을 바로 강한 운영 의사결정에 연결하기에는 보정 신뢰도가 아직 충분히 쌓이지 않았다.

## 6. 대안 모델군 비교

### 6-1. 선형 회귀 / 로지스틱 회귀

장점:

- 가장 단순하고 해석이 쉽다.
- 기준선 모델로는 유용하다.

단점:

- 가격, 수급, 재무 간 비선형 상호작용을 충분히 반영하기 어렵다.
- 현 구조 대비 성능 상향 가능성이 크지 않다.

판단:

- 연구용 baseline으로는 가능
- 운영 대체 후보로는 우선순위 낮음

### 6-2. RandomForest

장점:

- 트리 기반이라 비선형 관계를 처리할 수 있다.
- 튜닝 부담이 상대적으로 낮다.

단점:

- 부스팅 계열보다 랭킹 정밀도가 떨어질 가능성이 높다.
- 추론/메모리 측면에서도 이점이 크지 않다.

판단:

- 굳이 현재 시점에 비교 우선순위가 높지 않다.

### 6-3. XGBoost

장점:

- LightGBM과 유사한 강한 tabular baseline이다.
- 하이퍼파라미터 민감도가 다소 달라 동일 데이터에서 더 안정적인 정렬이 나올 수 있다.
- 산업 현장에서 비교 기준으로 자주 사용된다.

단점:

- 현재 파이프라인에 별도 구현이 필요하다.
- 성능 차이가 크지 않을 수 있다.

판단:

- 첫 번째 비교 후보로 적절하다.

### 6-4. CatBoost

장점:

- 결측과 범주형 처리에 강점이 있다.
- 튜닝이 상대적으로 덜 까다로운 편이다.
- 데이터 품질이 들쭉날쭉할 때 안정적일 수 있다.

단점:

- 현재 피처 대부분이 수치형이라 CatBoost의 고유 장점이 크게 드러나지 않을 수 있다.
- 운영 환경에 라이브러리와 학습 스크립트 추가 정리가 필요하다.

판단:

- XGBoost와 함께 1차 비교군으로 검토할 수 있다.

### 6-5. Ranking 전용 모델 (`LambdaMART`, LightGBM rank objective 등)

장점:

- 현재 문제의 본질인 "상위 순위 정렬"에 직접 맞는 목적함수를 사용할 수 있다.
- `top20 > top50 > universe` 구조 개선에 더 직접적일 수 있다.

단점:

- 현재 파이프라인은 회귀/분류/합성 점수 구조로 되어 있어 바로 치환하기 어렵다.
- 학습 데이터 구성과 평가 지표를 랭킹 중심으로 다시 설계해야 한다.
- 실험 난이도가 LightGBM/XGBoost 비교보다 높다.

판단:

- 중기 연구 과제로는 유망
- 지금 바로 1순위 교체 후보로 보기엔 이르다

### 6-6. 신경망 계열 (`MLP`, `LSTM`, `Transformer`, `TFT`)

장점:

- 충분한 데이터와 정교한 설계가 있으면 복잡한 패턴 학습 가능

단점:

- 현재 데이터 규모와 운영 검증 깊이에 비해 과한 선택일 가능성이 높다.
- 재현성, 튜닝 비용, 운영 복잡도가 크게 증가한다.
- tabular alpha 문제에서 트리 부스팅을 명확히 이긴다는 보장이 없다.

판단:

- 현 단계에서는 시기상조다.

## 7. 현재 프로젝트 기준 추천 우선순위

### 7-1. 유지할 것

- LightGBM baseline 유지
- 현재 타깃 체계 유지
- 현재 walkforward acceptance 체계 유지

이 셋은 비교 실험의 기준선으로 반드시 고정해야 한다.

### 7-2. 먼저 비교할 것

1. `LightGBM`
2. `XGBoost`
3. `CatBoost`

비교 조건은 반드시 동일해야 한다.

- 동일 피처셋
- 동일 학습 기간
- 동일 타깃 정의
- 동일 walkforward split
- 동일 ranking score 조합
- 동일 acceptance 기준

이렇게 해야 모델 이름만 바꿨을 때 순수한 차이를 볼 수 있다.

### 7-3. 나중에 검토할 것

- ranking objective 기반 모델
- 앙상블
- 딥러닝 계열

이들은 현재 baseline 3종 비교 후에도 정렬력 한계가 명확할 때 들어가는 게 맞다.

## 8. 모델 교체보다 먼저 확인할 항목

모델 종류를 바꾸기 전에 아래를 점검하는 편이 더 중요할 수 있다.

- `target_log_60d`, `target_mdd_60d`, `target_60d_top20`이 실제 운영 목적과 맞는지
- `final_score` 합성식이 예측값을 과하게 왜곡하지 않는지
- 상위 랭킹에서 유동성, 수급, 품질 필터가 과소 또는 과대 반영되는지
- confidence calibration이 아직 얕은 표본에서 과하게 해석되고 있지 않은지
- walkforward 표본 수가 너무 적어서 순위 비교가 우연에 흔들리고 있지 않은지

현재 저장소 상태를 보면 이 영역이 모델 교체 자체보다 더 큰 설명력을 가질 가능성이 있다.

## 9. 실험 설계 권고

모델 비교는 아래 형태가 적절하다.

1. 같은 학습 데이터와 피처를 사용한다.
2. `LightGBM`, `XGBoost`, `CatBoost`로 동일 타깃을 각각 학습한다.
3. 각 모델 출력으로 같은 방식의 `predictions.csv`를 만든다.
4. 기존 `ranking_builder.py` 로직으로 `ranking_final.csv`를 만든다.
5. 같은 walkforward acceptance 기준으로 평가한다.
6. `top20`, `top50`, `universe`의 수익률, 초과수익, MDD, hit rate, confidence monotonicity를 비교한다.

여기서 가장 중요한 1차 판정 기준은 평균 수익률 자체보다 아래 두 가지다.

- `top20`이 `top50`보다 일관되게 좋아지는가
- `top20`의 MDD가 운영 가능한 수준으로 통제되는가

## 10. 결론

현재 KR 모델에서 LightGBM 선택 자체는 타당하다.  
지금 당장 문제는 "모델 브랜드"보다 "정렬력과 운영 검증 증거"다.

따라서 권고는 아래와 같다.

- LightGBM은 유지한다.
- 대안 비교는 `XGBoost`, `CatBoost`까지만 1차로 좁힌다.
- ranking 전용 모델과 딥러닝은 아직 보류한다.
- 모델 교체보다 먼저 타깃, 합성 점수, walkforward 증거 부족 문제를 함께 본다.

한 줄로 정리하면, 현재 KR 모델은 "LightGBM이라서 틀린 것"이 아니라 "LightGBM baseline은 괜찮지만 아직 상위 정렬 품질이 충분히 입증되지 않은 상태"다.
